# v2 口述收敛记录

> 真源 = 主权者口述。本文件只记**已确认**的条目；待裁决项列在末尾。
> 每条 = 结论 + 主权者原意要点 + 与 v1.5/现状的差异。
> v2.0-草案（docs/归档/设计史/组织设计-v2.0-草案-作废.md）不作数，留作「此路不通」标本。

## 已确认

### 1. 复核者 = 一张普通岗位卡（2026-10-18）
- 复核者不是独立主体类别，就是 `集体L3-成员角色卡/` 下的一张卡，与「插件工程」「文档整理」「记忆整理」同地位。
- **砍掉的机制**：第五类主体、主权者逐案任命（registry_assign 复核员必填授权引用）、review_nominate 提名、池、轮换。
- **保留的疑问**：独立性靠什么扛 → 初步方向「冲突排除规则」，主权者标注**不确定**，待继续摸。

### 2. 复核实例生命周期：随任务起、用完即散（2026-10-18）
- 卡恒久、实例临时，与普通成员同一套实例模型。
- 没有常驻复核实例、没有排队等它。

### 3. 复核触发 = Lead 手动派（2026-10-18）
- 与派任何成员同一条路：任务到待复核后，Lead 用 member_spawn 起复核实例，不引入「系统自动起」的新机制。
- 已知缺口（主权者认可）：Lead 可以拖着不复核 → 任务停在待复核，只是停滞，不产生错误采纳。
- 连带推论：复核员岗不再要求 registry_assign 授权引用——它就是普通岗，随派随起。

### 4. 复核结论 = 硬闸（2026-10-18）
- 没有「过」不得采纳；「未验」也不得采纳。
- Lead 可记录不同意，但不得修改复核结论；采纳必须引用复核结论。
- 判据本体不在 Lead 手里：派发时冻结 + member_spawn 由机制自动附上，Lead 的任务书只是补充说明。

### 复核独立性最终扛法（由 1~4 合成）
- 冲突排除（执行者/交卷人/负责人/同会话者不得复核本任务）——机制判。
- 冻结判据机制附上——Lead 改不了复核看什么。
- 实例独立上下文——天然成立，立项理由③的着陆点。
- 采纳权在 Lead 是设计本意；Lead 越过硬闸强采纳，靠审计留痕 + 主权者三权兜底，不靠复核者。

### 5. 免审保留，开关放设置（2026-10-18）
- 主权者原话：「留，设置里给选项」。
- 免审开关/粒度由主权者在设置中配置，变更入审计；细节（全局开关 vs 按风险档）待细化。

### 6. 复核实例读范围 = 按任务授权宽读（2026-10-18）
- 复核实例可读本任务的交付物、判据、相关账本与审计。
- 比普通成员「只读自己那片」宽，但限定在任务作用域内；不是全局随便看。

### 7. 复核约束由机制扛，按岗位名判（2026-10-18）
- 「只读数、不改、不提案」是策略引擎对复核岗位卡的硬规则：写操作一律拒。
- 与冲突排除同款做法；不靠卡文本自觉。

### 8. 主体名单 = 五类（2026-10-18）
- 主权者 / 出厂作者 / Lead / 成员 / **系统**。
- 复核者退出主体名单（见条目 1）；「系统」单列一类：审计、探针、失联冻结等机制动作的记账主体，与人/组织的动作在账本上一眼可分清。

### 9. Lead = 岗位唯一，多会话实例（2026-10-18）
- Lead 是一张岗位卡；每个主会话窗口是一个 Lead 实例。
- 所有实例共享岗位卡、能力库、记忆、任务图与审计；会话上下文互不互通。
- 并发冲突靠任务认领 + 审计归属协调；同一任务不得重复派发或重复采纳。

### 10. 实例模型全岗位统一，Lead 也钉卡版本（2026-10-18）
- 卡恒久、实例临时、启动钉 `cardVersion`、绑定任务、用完封存——Lead / 成员 / 复核同一套。
- Lead 实例随主会话出生，出生时钉当时的卡版本。
- 钉版本的理由（主权者确认）：审计能答「凭什么」、规则不半途变脸、复核有基准。
- 策略引擎只认「实例 + 卡版本 + 任务作用域」。

### 11. 负责人寻址 = 写岗位名，实例随派产生（2026-10-18）
- 任务节点「负责人」填岗位名；member_spawn 起实例时把实例绑到节点。
- 「全员已交」等判定按**已绑实例**算。
- 明确否决 v2.0 草案的「派发时展开为在岗实例集合」——与「实例随任务起、无常驻」（条目 2）矛盾。

### 12. 孤儿实例：系统回收，未完成不自动成功（2026-10-18）
- 崩溃/重启后孤儿实例由系统标封存；未完成的交卷绝不自动算成。
- 与约束清单④「重启后所有判定必须能重建」一致。

### 13. 失联冻结 = 维持宪章：冻结所有自治变更（2026-10-18）
- 否决 v2.0 草案的「只冻结治理变更」松绑。
- 维持：失联 ⇒ 所有自治变更冻结；服务与记忆照常；安全类强更照常；恢复 = 主权者任一交互，恢复 ≠ 批准待决项。

### 14. 介入度 = 主权者本人的介入程度（2026-10-18）
- 主权者原话：「介入应该是指要落盘的东西要经过主权者审核同意才能落盘」。
- **纠偏**：后两档的执行者是主权者本人，不是复核实例。复核实例从介入度机制中撤出——它是主干环路的验收闸，不是主权者替身。
- 四档语义：零参与 = 直接落盘事后可查；事后抽检 = 落盘后主权者抽查；变更预审 = 高风险自治写停在「待你决定」等主权者放行；逐条审批 = 每条自治写都等放行。
- 与失联一致：预审/逐条档下主权者不在线，自治写自然排队；失联冻结再罩一层。
- 待细化：预审档「高风险」的界定清单。

### 15. 知识写入 = 晋升动作；任务内只写经历/作答（2026-10-18）
- 成员实例任务内可写「经历」「作答」，交卷可附知识候选；**不得直接写「知识」类、不得改能力库、不得改角色卡引用**。
- 采纳后由 Lead 或记忆整理岗把候选蒸馏为知识条目（岗位+项目双标签）。
- 依据：复核硬闸（条目 4）的推论——未验收的产出不进组织知识；经历账本保底不丢信息。
- 晋升权责分层：项目内知识/岗位经验 = Lead 批；跨项目 = Lead 批 + 披露检查（契约C保留）；发能力/改卡引用 = Lead + 按介入度走。
- 晋升不是新机制，就是普通自治写，被介入度四档与失联冻结罩住，无特例。

### 16. 晋升的三个入口（2026-10-18）
- **主**：结账强制——task_settle 拒收无「记忆处置」声明的结账；机制在结账时把本任务经历/交卷候选列给 Lead 逐条判（晋升/留账本/丢弃）。
- **兜底**：工作台把「已采纳但记忆处置为空」投到「待你决定」。
- **补充**：Lead 随时手动晋升。
- 原则：主动发起不靠 Lead 记得，靠环路不结案。

### 17. 介入度砍成三档并改名：放权 / 预审 / 审批（2026-10-18）
- 砍掉「事后抽检」档（主权者裁决：要么拦要么不拦，中间态退化成零参与）。
- 三档：**放权** = 自治写直接落盘、留痕、事后可查可否决；**预审** = 高风险自治写停在「待你决定」，主权者批准后落盘，低风险直落；**审批** = 每条自治写逐条等主权者放行。
- 仍只影响自治档；立宪、立法、否决、撤回不受影响（宪章不动）。
- 设置项仅主权者可改、变更入审计、非法值 fail-closed（维持）。

### 18. 会审 = 与会话绑定的独立功能，退出任务图（2026-10-18）
- 主权者原话：「按理说这应该是一个独立的功能」「会审按理说应该是和一个会话绑定的」「存到会审页里」。
- 会审不再进工作台账（不占任务节点、不走派发/复核/结账）；它是会话里的咨询工具：抛问题 → N 个独立实例作答 → 交齐解锁 → 收敛结论；想干活再往台账正常登活。
- 每次会审存档：问题、各份答案、分歧、结论、来源会话、时间；会审页（看板既有 tab）列全部历史。
- 连带：任务图「一岗多人模式」字段取消——独立会审删除后多人只剩并行分担一种。

### 19. 会审配件裁决（主权者授权 Lead 定，可否决）（2026-10-18）
- 提交后解锁：**留**（含盲评：未交齐只见盲标、交齐揭名，不单列）。
- 强制反对者：**砍**（轻量咨询不值一次实例调用；分歧不足由零分歧报警补位）。
- 零分歧报警：**留**（纯信号，存档记「零分歧异常」）。
- 讨论段：**留但默认不开**；Lead 显式开启，预算上限照旧（轮2/人8/每轮24条/每人4000字）。

### 20. 不立统一授权模型；天然载体 + 两条不变式（2026-10-18）
- 主权者确认 Lead 推荐：不立四类授权对象。
- 各层权力用天然凭证：主权者 = 身份本身（设置项/authority 标签/决议）；Lead = 任务节点（冻结判据 + 绑定）；成员 = 实例绑定。
- 草案里保留两条红线进策略引擎不变式：**不越授**（Lead 派活的写域/工具不得超出自身范围）、**不自授**（主体不得给自己扩权，宪章⑤的推广）。
- 审计照旧记「凭什么」（依据字段）；将来出现跨边界授权需求再立对象（先例：领域协调者、会审）。
- 全组织仅剩的授权引用：更正审计须引主权者决议（audit_correct）。

### 21. 项目隔离：维持 v1.5（2026-10-18）
- 项目 = 隔离单元（台账/看板/记忆按项目分）；身份、岗位、履历全组织一份；项目键 = 工作区目录名；上下文按需拉取。

### 22. 通用空间 + 跨项目规则（2026-10-18）
- 主权者原意：「合适的话记到通用里是可以的，不用非得晋升；记到其他项目也可以，但要合理」。
- **新增「通用」记忆命名空间**：项目无关知识的合法住所。写入闸与知识同款（条目 15）：成员只提候选，Lead/记忆整理落笔，披露检查照跑、入审计。省掉晋升仪式，不省检查。
- **跨项目写**：Lead 可显式传 project 参数写别的项目——依据必填 + 审计（「合理」落在依据上，事后可判）；成员实例禁止跨项目，无例外。
- **读面**：Lead 与主权者可跨项目读；成员只读本任务项目。
- `project` 参数保留，策略引擎按「谁 + 写/读 + 有无依据」判。

### 23. B 摞五块：设计维持 v1.5（2026-10-18）
- 载体与升级（双区 + 条款级合并）、安全类（封闭清单 + 探针 + 回滚定位）、审计（只增 + 链式哈希 + T1/T2 承诺分档）、消息总线（线程隔离 + 发件人真实主体）、检索与接口（零命中报口径 + 三面同源）——设计层全部维持，不做改动。
- 实现层核查未做：主权者另有审查轮，本记录不背书实现。

### 24. 两个小口子裁决（2026-10-18，主权者采纳 Lead 推荐）
- **免审 = 全局开关**：设置里一个开关，不设任务风险分级；真有感觉再加档。
- **预审档「高风险」= 按动作类型的写死清单**：改岗位卡、发布能力、物理删除记忆、改设置。清单写死，好判好审；要扩清单 = 改设置，主权者动作。
