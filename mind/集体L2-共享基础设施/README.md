# 共享基础设施（出厂侧）

> 这一页只说三件事：每个子目录装什么、哪一份是**程序**、哪一份是**数据**。
> 纪律：**目录负责「找得到」，标签负责「谁能改」**——判定授权只读标签，不读路径。

## 私有侧装【数据】

任务图/<项目>/ · 消息总线/<项目>/*.jsonl · 记忆服务/（跨项目 ＋ 各项目）· 审计日志/audit-YYYY-MM.jsonl ·

**判据**：**随产品更新的是程序；跑出来的、可回滚的是数据。**
拿不准时问一句：**重装产品之后，这条内容还在吗？** 在 ⇒ 数据，落私有区。

## defaults/

**每个键只有一个出厂源**，别处不再重复一份（重复 = 改了不生效）：

| 文件 | 它**唯一**承载的键 | 谁能定 |
|---|---|---|
| 介入度.json | `介入度`（四档之一，默认 `零参与`）。**不再承载响应期限** | 主权者 |
| 响应期限.json | `失联限制`（默认 `true`）＋ `响应期限小时`（默认 `72`）——**这两个键的唯一出厂源** | 主权者 |
| 工具总范围.json | 空数组 ＝ 不额外收窄 | **主权者** |
| 安全类探针.json | 封闭清单的探针声明 | **主权者声明，出厂作者实现** |

- `失联限制` ＝ 失联保险：`true` 时，自最后一次交互起超过 `响应期限小时` 未响应 ⇒ 自动标记失联 ⇒ **所有自治变更冻结**；主权者任一次交互即解除。
- 设成 `false` ＝ **关掉这个保险**。读数里会如实出现 `已关闭: true`——机制被停掉这件事不会被伪装成「主权者一直在」。
  （工作台与状态条投影里这表现为 `状态条.失联 = '已关闭'`，四态之一：`在位` / `已失联` / `已关闭` / `未知`。）

### 改这两个键：两条路，先看第一条

**路一（更省事，推荐）：命令行入口 `/mind presence` —— 人要改这两个键，不用碰文件。**

```
/mind presence                      # 读：只回报当前生效读数，不改盘、不入账
/mind presence 开关=否 小时=168      # 写：失联限制=否（关掉），响应期限小时=168
/mind presence 开关=是               # 只改一个键也行（另一个键保持不动）
```

- `开关` 只收 `是 / 否`；`小时` 只收 **1 ~ 876000 之间的整数**（上限 ≈ 100 年）。含糊写法（`也许` / `0` / `abc`）
  **当场拒**，并说清合法取值。
  **为什么必须有上限**：期限要拿去算「起算时刻 ＋ 小时 × 3600 秒」，而 `Date` 能表示的最大时刻是有限的 ——
  再大的"合法大整数"会让那个时刻算不出来，于是**失联判定连着整条读数链一起废掉**
  （`/mind status` 与工作台都拿不到状态条，引擎却还报健康）。所以上限是**判据的一部分**，不是输入体检；
  取 100 年是因为它已经等于「永不判失联」，再大没有含义。
- 它写的就是下面那一份**私有 `部署.json`**：**merge 写**（只覆盖这两个键，文件里别的键一个不丢）
  ＋ **原子写** ＋ **无条件入账**（审计里记一条「设置变更」，主体是敲命令的那个人）。
- **这个动作是命令面专属**：`mind` 工具的 `enum` 里没有它 —— 模型没有这只手，只有人能敲。
- 拒绝路径（非法值 / 坏文件 / 写不进去）**一个字节都不改盘**，但照旧留一条账。
- ⚠️ **写完要回读**：命令的返回体是"它说它做了什么"，**回读才是"盘上现在是什么"**。
  `/mind presence`（不带参数）就是那次回读。（设置页那一格也是这么做的。）

**路二：自己写私有文件**（路一不可用时 —— 比如没有命令面 —— 照这条路走。）

- 改哪一份：出厂区那份随产品更新，**不要就地改**；主权者要改，改私有区 `mind-data/mind-private/集体L2-共享基础设施/defaults/部署.json`，里面写同名键即可，它**最后覆盖**出厂那几份。
- **私有区那份 `部署.json` 不存在就自己新建**：安装时**不会**建这个目录与文件（它是「你确实想覆盖出厂默认值」时才需要的东西，空着不影响任何功能）。
  最小操作：建出目录 `mind-data/mind-private/集体L2-共享基础设施/defaults/`，在里面放一个 `部署.json`，只写你要改的键，例如 `{ "响应期限小时": 168 }`（改完不必重启：重载时生效）。
- 写了非法值（`0` / `-5` / `"abc"` / `null`）**不会让保护失效，也不静默**：仍按内置兜底 `72` 判（失联保险照常工作），
  同时读数里带 `值不合法: true` ＋ `原值` ＋ `原值来源` ＋ `响应期限小时来源`（`出厂` / `私有` / `内置兜底`）——
  「生效值来自哪一层」是这两个键最该有的透明度；一条 `说明` 之类**纯给人看的键不会进运行态**（不会跟着读数流出去）。
- 坏 JSON 会**响亮报错**（引擎转 fail-closed，写动作全部被拒），不会静默退回默认值——否则你的设置被无视了你却看不出来。

### 私有层与探针声明：私有 `安全类` **本来就压得过**出厂

上表说的「私有最后覆盖」是**全键统一**的，`安全类` 也不例外。别被旧注释误导：

- **事实**：旧代码里探针的赋值在 `if (zone === '出厂')` 分支里（**第一次**迭代），而私有 `部署.json` 的
  `Object.assign` 是**第二次**迭代 ⇒ **旧代码里私有 `安全类` 本来就压得过**出厂声明。
  （曾经有过"私有 `安全类` 压不过出厂声明"的说法，那**是错的**，已按 HEAD 旧代码逐行核过。）
- **但这条调整在行为面是 no-op**：`state.defaults.安全类` 这一格**当前在 `src/`、`lib/` 里没有消费者** ——
  探针引擎（`src/probes.js`）是**照路径直读**声明文件（`layout.probeDeclaration()`，
  见其 `声明（…）` 与 `机制版本`），**不读这一格**；内核闸也只读章程 / 法律 / 编制。
  所以"私有覆盖"这件事在探针上既不靠它生效、也不会因为它不生效而出问题。
- 写在这里的用处只有一条：**别照着"私有压不过出厂"这个错觉再去"修"一遍**。
  真要改探针声明，改的是**它自己的声明文件**（`安全类探针.json` 的私有覆盖），不是这一格。


## 能力库：双区各一份

出厂侧这份是**出厂能力库**（随产品更新，不就地改）；组织自己长出来的技能落私有区的**自治能力库**。
**同名不合并**：两条都返回并标注来源，默认用自治版，冲突时并列给 Lead 判。
岗位卡只在 `个体L2` 里**引用 id**，不内嵌正文——一项能力被多岗位共用时只改一处（**单源**）。
