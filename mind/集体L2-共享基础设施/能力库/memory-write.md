# 记忆写入

**一句话**：记忆**只追加**；写入必须带「谁记的 ＋ 怎么知道的」。

<!-- authority: 自治 -->
## 适用岗位

- 文档整理
- 记忆整理

## 怎么做

写入与维护都照这份走：文档整理负责条目，记忆整理负责条目状态。

1. **先分四类，再落笔**：知识 / 经历 / 偏好 / 作答。**能力不在这里**——技能与规程进能力库，不进记忆服务。
2. **写入必带来源**：**谁记的 ＋ 怎么知道的**。来源缺失即拒写；"我记得"不是来源。
3. **按归属选命名空间**：

   | 类 | 归属 | 命名空间 |
   |---|---|---|
   | **知识** | 岗位 ＋ 项目**双标签** | 跨项目（岗位）/ 本项目 |
   | **经历** | 组织账本 | 只增 |
   | **偏好** | 部署 | **永不外流** |
   | **作答** | 实例 | 私有区内部，任务结束归档 |

4. **知识标签规则**：项目内知识带项目与适用岗位标签；岗位标签本身不开放其他项目。由 Lead 明确执行跨项目晋升且通过披露检查后，才进入跨项目召回面。
5. **知识 = 晋升动作**：成员实例任务内只写「经历」「作答」，交卷可附**知识候选**；**不得直写「知识」**（会被拒），知识由 Lead / 记忆整理岗在采纳后落笔（项目无关知识走 `项目=通用`）。
6. **写入时校验必要字段**：正文非空，来源和对应类所需的项目、岗位、任务及引用完整；服务会核验相应资格。字段合格不证明结论正确，知识是否适用仍需证据与内容判断。不要虚构服务尚未提供的正文分段检查。
7. **不许改写，只能追加**：

   | 情形 | 处置 |
   |---|---|
   | 经历 | 只增，不改 |
   | 错误 / 过期 | **追加 `invalid` 状态** |
   | 冷 | **追加降权状态**，不删 |
   | 被推翻 | **追加一条双份留痕**（原条 ＋ 新条都指得清） |
   | **物理删除** | 仅限：敏感数据、主权者明确要求 |

8. **归档作答，并守读权限**：主权者 / Lead / 复核实例可读；**成员不可读**；自动检索**不进默认检索面**，可显式检索。
9. **检索按需拉**：`memory_query` 默认摘要；有文本时只返回实际命中，零命中不夹带无关账本。按 `id` 与 `返回模式=全文` 取详情，仍受原读域和内容预算限制；长正文使用 `下一正文偏移`，列表使用 `下一偏移`，续页均带原 `数据版本`，数据变化时从 0 重读。失效与归档材料须显式请求且具备读权，不能作为当前有效建议。上下文不全量推送历史、其他线程或其他项目。

## 判据

- **单源**：一条事实只有一处出处；发现两处，判断哪一处是源，另一处改成引用。
- **可追溯**：任何条目都能回答"谁在什么时候、凭什么知道的"。
- **报「0 命中」必须连口径一起报**：搜索面 / 查询词 / 范围。

## 不做什么

- 不装能力（那是能力库）。
- 不决定注入什么（注入面是调用方按需拉）。
- 不上数据库：账本式 `.jsonl` ＋ 可重算的索引足够。
