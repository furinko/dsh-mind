# 编制

> 出厂默认编制，组织可自决调整（自治档，Lead 确定并留痕）。这里的「L2」是分类标记，不是授权档。
> 本文的 ```policy 块供策略引擎加载岗位清单与默认会审模式。

<!-- authority: 自治 -->
## 岗位总则

- **Lead 常驻、唯一、跨项目**：换项目 ＝ 换上下文，不是换 Lead。
- **成员岗位持久、实例临时**：一次派活 ＝ 该身份的一个实例，干完就散；**知识挂岗位，不挂实例**。
- **领域协调者暂不设。** 出现「Lead 成瓶颈」的实测再议——先有实测，再有岗位。
- **复核员是常驻岗**，不随任务起落；任命由**主权者确认**，Lead 可提名。
- 每张岗位卡 = **个体 L0 身份（锁定）· L1 规则 · L2 能力引用 · L3 经验引用**。
  **L2 只写能力 id，不内嵌正文**（单源）；L3 只写引用，经验本体住记忆服务。
- **一岗多人必须显式声明模式**，声明记在任务节点上；未声明即不许开工。

## 在岗清单

| 岗位 | 性质 | 一句话职责 | 卡 |
|---|---|---|---|
| **Lead** | 常驻，唯一，跨项目 | 受理与定判据、判权限、派活、汇总验收、建改删卡；**不首发意见** | 见权限矩阵「岗位与卡」 |
| **复核员** | 常驻岗 | **只读数**：独立验证交卷，出三态 ＋ 分歧清单 ＋ 反例面，不写不派活不提案 | `复核员` |
| **插件工程** | 成员岗 | 写与改插件程序件：按判据实现、留证据、落产物引用 | `插件工程` |
| **文档整理** | 成员岗 | 把结论整理成可检索的知识与文档条目，写记忆时带来源 | `文档整理` |
| **记忆整理** | 成员岗 | 维护记忆四类账目：去重、降权、失效、推翻，全部只追加 | `记忆整理` |

**岗位是持久的，实例是临时的**：上表的岗位不会因为一次任务结束而消失；实例权限随任务结束失效。

## 一岗多人的两种模式

| | 并行分担 | 独立会审 |
|---|---|---|
| 互相可见 | 能 | **交卷前不能** |
| 共享 | 中间结果 | **只共享岗位知识与能力** |
| 产出 | 合起来的成果 | N 份独立答案 ＋ **分歧清单** |
| 解锁时机 | 不适用 | **任务图报「全员已交」** → 消息总线解锁并广播 |
| 适用 | 工作量可切分、判据无歧义 | 判据有歧义、结论可能趋同、需要制衡 |

**独立会审的配套**：强制反对者（系统随机指定一名未参与成员，且不重复）· Lead 不首发 · 盲评（第一轮只显示成员代号）· 零分歧报警（结论层一致且无人给出反例面 ⇒ 记一笔 ＋ 人工抽检）。

## 编制变更

- **增岗 / 撤岗 / 改职责** ＝ 自治档：Lead 确定，留痕五件齐（谁提的 / 凭什么 / 谁复核 / 结果 / 可回滚点）。
- **复核者卡例外**：它的身份 ＋ 权限 ＋ 判据三段是**法律**档，改它要**主权者**；只有能力与经验段归组织。
- **封存 ≠ 删除**：岗位空置写封存，卡与历史都留着。
- **撤岗不撤记忆**：岗位的相关知识条目保留并标注归属，检索时能答「这个岗位曾经管什么」。
