# 协作协议

> 出厂默认文本，主权者可覆盖。本文规定**怎么一起干活**：环路、留痕、标签、隔离、分工。
> 本文的规范段（主干环路 / 留痕 / 标签 / 隔离）为**法律**档，改它要主权者；作业细则段为**自治**档，组织自决。

<!-- authority: 法律 -->
## 主干环路

```
受理 → 定判据 → 判权限 → 派发 → 执行 → 交卷 → 复核 → 采纳/打回 → 落记忆 → 结账 → 刷新视图
```

| 步 | 谁做 | 落什么 |
|---|---|---|
| 受理 | Lead | 消息总线收到需求，开线程 |
| 定判据 | Lead | 任务节点 **判据必填**：写不出判据就不许开节点 |
| 判权限 | 策略引擎 | `{主体, 对象 id, 动作}` → 允许 / 拒绝 / 需确认 ＋ **理由** |
| 派发 | Lead | 派发后**判据冻结**；一岗多人必标模式 |
| 执行 | 成员实例 | 任务内全权，任务外无 |
| 交卷 | 成员实例 | 产出物落对象存储，节点只存引用 |
| 复核 | 复核者 | 三态 过 / 不过 / 未验 ＋ 分歧清单 ＋ 反例面 |
| 采纳/打回 | Lead 采纳；打回计数记在节点上 | 同一节点打回 ≥2 次 ⇒ **升级主权者** |
| 落记忆 | 提出方 ＋ 记忆服务 | 写入必带「谁记的 ＋ 怎么知道的」 |
| 结账 | 审计日志 | 状态变更与敏感操作无条件落账 |
| 刷新视图 | 工作台 | **只读投影**，可从任务图 ＋ 日志重算 |

**四个唯一**：唯一入口（消息总线）· 唯一判定点（策略引擎）· 唯一出口（审计日志）· 唯一投影（工作台）。
**两个自治源**：**任务图 ＝ 状态权威**；**角色注册表 ＝ 权限事实源**（注册表本身只是索引）。

### 三条接口硬规则

1. **写操作先过策略引擎，无旁路**——对象存储、记忆服务、任务图、消息总线都在闸后。
2. **状态变更与敏感操作无条件落账**。
3. **工作台只读**——它是投影，不是第二事实源。

**唯一豁免**：策略引擎为判定而读标签，是**特权读**，不经判定——它是判定点自己的输入，不是旁路；**只有策略引擎拥有特权读**。
**对象传的是 `id`，不是内容**；引用一律用 id，不用路径。

## 留痕门槛

**留痕是自治的门槛。** 一次自治变更必须留齐五件：

1. **谁提的**；
2. **凭什么**（依据条款 / 判据）；
3. **谁复核**；
4. **结果**；
5. **可回滚点**（回滚到哪一版、回滚什么）。

**无留痕的自治变更 ＝ 无效。** 无效不是「下次注意」——它不产生效力，视图不刷新，账不认。

**留痕与版本**：宪章与法律每次改动生成版本；**只有主权者能回滚文本版本**。
**回滚的是文本，不是世界**；安全类的自动回滚是**机制回滚**，触发者是策略引擎，无条件执行且无条件入账。

## 授权标签纪律

**授权是标签，不是路径**；粒度 ＝ **段**。

**怎么打**：段首单独一行写 `<!-- authority: 法律 -->`，紧跟该段的 `##` 标题；下一段再写 `<!-- authority: 自治 -->` 并接它自己的标题。
标记是**段**级的——同一份文档里，规范段可以是法律档，作业细则段可以是自治档。

- **谁打**：出厂件由出厂作者打 · 法律件由主权者打 · 自治件由 Lead 打。
- **标签是对象的元数据**，写入时一并写入；**变更标签本身要走策略引擎**。
- **冲突**：同一对象标签冲突时，**以更高 authority 为准**（宪章 ＞ 法律 ＞ 自治 ＞ 只增）。
- **纪律**：**目录负责「找得到」，标签负责「谁能改」**。策略引擎判定只读标签，不读路径。

## 项目隔离

**项目是隔离单元。**

| 对象 | 是否按项目隔离 |
|---|---|
| 任务图 · 工作台 · 记忆命名空间 | 按项目 |
| **知识** | **双标签**：岗位（跨项目）＋ 项目（本项目） |
| 身份 / 岗位 / 履历 | 不按项目——跨项目统一 |
| Lead | **唯一且跨项目** |

**三条硬规则**：

1. **身份跨项目统一，记忆命名空间按项目隔离。**
2. **「跨项目拉取」专指「项目专属知识」**；**岗位知识与岗位能力随身份带，不算跨项目拉取**。
3. **Lead 切换项目 ＝ 换上下文，不是换 Lead。**

> 项目隔离是「避免上下文污染」的物理实现——**靠目录边界挡，不靠纪律**。

## 能力库与记忆服务的分工

| | 装什么 | 答什么问题 | 谁持有 |
|---|---|---|---|
| **能力库** | 技能 / 规程（**怎么做**） | 「这件事怎么做」 | 岗位（可多岗位共用，**单源**） |
| **记忆服务** | 知识 / 经历 / 偏好 / 作答（**知道什么**） | 「我们知道什么」 | 见记忆服务归属 |

- **能力不在记忆服务里**；能力库与记忆服务**并列**，各占一件。
- **角色卡的个体 L2 段 ＝ 引用能力库里的哪几项**，不内嵌全文。
- **两个能力库**：出厂能力库随产品更新；自治能力库组织自治、永不外流。**同名不合并**，两条都返回并标注来源，默认用自治版，冲突时并列给 Lead 判。

### 上下文来源（按需拉，不许全量推）

岗位知识（随身份带）· 岗位能力（随身份带）· 任务节点 · 工作台（自己那一片）· 记忆检索（按需）· 本轮线程消息 · 当前项目记忆。
**不含**：其他线程、全量历史、群聊归档、其他项目。

## 作业细则

- **派活前先判权限**：拿不到「允许」就别开工，把拒绝理由（哪条规则 ＋ 改它要什么授权）原样带回线程。
- **交卷即交证据**：产出物给引用，不贴正文；结论与反例面分开写。
- **视图不手改**：工作台对不上以任务图与账本为准，改的是上游，不是投影。
- **改变更性质就重新走门槛**：作业细则里长出来的新规范，若约束到别人，按它的性质补打法律或宪章标签，再走对应门槛。
