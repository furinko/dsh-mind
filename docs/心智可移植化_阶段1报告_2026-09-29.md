## 二、阶段 1 交付物

### 2.1 `packages/dshome/lib/host/mind-paths.js`（**新增 · 路径唯一真源**）

**病灶**：同一段 `repoRoot()` 逻辑被复制 **11 遍**（8 个 host 插件 + `cron.cjs` +
`dshome-mind/index.cjs` + `quick-phrases/index.cjs`），且各自硬编码 `profiles/dshome`
（DSHOME 专属 profile 名）——**装进别的 profile 即错**。

**三层根**：`mindRoot()` / `profileRoot()` / `marketDir()`，全部可被环境变量显式钉住（测试隔离）。

**解析顺序**（每一步都经实测校正）：

```
mindRoot():   MIND_HOME > DSH_HOME(含 mind/) > DSH_HOME/mind-data/mind/ > dev 上溯 > 兜底
profileRoot(): DSH_HOME 在场 ⇒ 一律随它（不读 DSH_PROFILE/DSH_PROFILE_DIR）
               否则 ⇒ DSH_PROFILE_DIR > <mind-data>/profile > <root>/profiles/<名>
marketDir():   MIND_MARKET_DIR > profileRoot()/.dsh-market（loose 时走 homeRootLoose()）
homeRootLoose(): DSH_HOME（**不要求含 mind/**）—— 给"锚点是 home 而非固件"的用法
```

### 2.2 `packages/dshome/lib/host/mind-bootstrap.js`（**新增 · 首启自举**）

**为什么必须有**：现有心智的隐含前提是"`mind/` 已经躺在 DSH_HOME 里"——它靠**仓库布局**而非
**插件能力**。装成插件后用户机器上没有那份固件 ⇒ 注入器读不到 SOUL/AGENTS、面板扫不出树，
**装上也是空壳**。

**五条纪律**：
- **幂等**：必备件齐全就一个字节都不动
- **只增不改**：已存在的文件一律跳过（**绝不覆盖用户养出来的心智**）
- **不写示例记忆**：只建私有区空壳 + 首启说明（写了＝预设生长方向，违背"全放开生长"）
- **缺失必＝未就位**：必备件**清单**判据（非单点，见下 §四 缺陷 ③）
- **fail-open**：自举异常只 warn，绝不断插件加载（护栏模式纪律）

## 四、本轮抓出的三个真缺陷（都是门禁抓的，不是我自查）

### ① `mind-guard` 的宽口径不能换成窄口径（**最重**）

窄口径要求 `DSH_HOME` 含 `mind/`，而 `verify-guard-decisions` 的 marker 夹具**故意只设
`DSH_HOME` 不建 `mind/`**（它测接线、不测根解析）⇒ 夹具被判"不是心智根"、**响亮回落到真仓库**
⇒ **9 项断言整片变红**。

**定位方式**：`git checkout HEAD` 出权威版重跑 → 全绿 → 确认是我的改动；`git diff` 只有 8 行。
**结论**：护栏管的是"往心智区写"的拦截，**锚点是 home，不该与"固件是否已就位"耦合**。
→ 新增 `homeRootLoose()` 与 `marketDir({loose})`。

### ② `profileRoot()` 跟着 GUI 会话跑偏

首版把 `DSH_PROFILE_DIR` 当最高优先。但该变量在**当前 GUI 会话里恒存在**
（本机实测 `= C:\Users\kuro\.dsh\profiles\desktop`），与"心智基座所在的那个 profile"（`dshome`）
是两回事 ⇒ marker 写到**仓库外**，`verify-host-plugins` 场景 8/9 整片变红。
**判据修正**：marker/台账属于**心智基座**，不属于"当前 GUI 会话的 profile"。

### ③ 删 import 后漏改使用点（**同型 3 处**）

删除 `dirname` / `existsSync` 的 import 后，仍被使用 → **ReferenceError 被 fail-open 静默 catch**
⇒ 台账永远不落地。`node --check` 查不出（语法全过、真跑才炸）。

- 抓到方式：`mind-write-log-itest` 报 `ENOENT`
- 同型另外两处（`mind-compaction-log` / `session-budget`）由**我补的导入完整性静态扫描**抓到
- 这正是 `verify-integrity` 配方 19③「改动面自证」的实例
