## ① `readonlyCommand` 生产零调用点（未接线）

**债**：复核者的「只读命令白名单」（`ReviewProtocol.readonlyCommand`，`src/review.js:290`）**没有任何运行时调用点**——
白名单本身已经修实（`node --test` 已移除，跑测试＝写副作用），但没有门禁在跑它。

**证据（两处 grep，各自的分母）**：

```
# 面 1：本仓生产面（src/ + lib/ + components/*/lib/）
$ git grep -n "readonlyCommand" -- src lib components
src/review.js:290:  static readonlyCommand(command) {      ← 唯一命中＝定义本身 ⇒ 生产调用 0 处
# （另有 5 处测试引用在 test/entry-bounds-w3c.test.js、3 处文档引用在 DESIGN-MAP/INTERFACES/docs，不计入生产面）

# 面 2：宿主安装目录（复核补搜）
$ 在 C:\Users\kuro\.dsh\profiles\desktop\node_modules\dsh-mind 下只搜 src/ 与 lib/（排除 test）
C:\Users\kuro\.dsh\profiles\desktop\node_modules\dsh-mind\src\review.js:290   ← 同样只有定义
```

**动作面也没有承载它**：`lib/actions.js` 的 `ACTIONS`（第 17–54 行）里没有对应动作名。

**为什么现在不修**：接线属**设计决策**——复核者的命令面在哪（模型侧还是人侧）、谁执行、闸挂哪一层，都没有裁决。
先接线＝替组织定流程；而且没有执行器时，白名单再严也只是一件纪律文书。
**什么时候必须回头修**：出现「复核者要跑命令」的真实需求，或复核者命令面进入设计/裁决时。

## ③ `bus.summary` 接投影前必须做「免审计 / 聚合档」（未接）

**债**：`bus.summary`（`src/bus.js:236-244`）对**每个线程**调一次 `read()`；而契约 B（`13a3421`）之后，
`read()` 每次调用落**一条**「只读服务调用」审计（`src/bus.js:107-121`）。若直接把它接进看板轮询，审计面会被投影读数淹没。

**证据**：
- 当前**零调用点**：`git grep -n "summary("` 全仓只命中 `src/bus.js:236` 定义本身；
- 轮询间隔：`components/board/lib/client.js:1380` → `var POLL_MS = 3000;`；
- **定量（推算，不是压测）**：86 400 s ÷ 3 s = **28 800 次/天**；再乘「每次投影要读的线程数」——
  复核给的 ≈**14 万条/天**对应「按 5 条线程算」：28 800 × 5 = 144 000。**分母＝线程数，随项目变化**；
  这个系数（5）我没能在源码里钉死，属推算，写在这里是为了可复算，不是当实测读数用。

**为什么现在不修**：summary 还没接投影（不接就没有噪音）；真要修的是「投影类批量读」的**免审计或聚合档**，
这属于策略面设计（哪些读算投影、免审计的边界在哪、谁批准），不该顺手改。
**什么时候必须回头修**：任何把 `summary`（或 per-thread `read` 循环）接进轮询/看板**之前**。

## ④ `#lineageIndex` / `bus.readRaw` 每次全量读账（成本面）

**债**：血缘索引与线程读取都是**每次调用全量读账**，账本大了是线性成本。

**证据**：
- `src/memory.js:786-793`：`#lineageIndex()` 扫 `MEMORY_KINDS × (跨项目 + 全部项目账本)` 的**全部行**再建索引（纯投影、不落盘——不变式 #4「可重建、不另立真源」）；
- `src/bus.js:135-148`：`readRaw()` 读整条线程账本再按 id 折叠；
- 调用面：讨论预算闸**每次发言**都 `readRaw`（`src/debate.js:117`）；`purge` 对每个下游项调一次闭包（`src/memory.js:801-803`，每次重建索引）。

**为什么现在不修**：当前数据量（记忆个位数、线程几十条）线性成本可忽略；**先测瓶颈再动**——
与《现状核对》§四 第 4 条同款纪律（「现在记忆条数是个位数，任何性能论证都还没有数据」）。
**什么时候必须回头修**：单账本行数上万，或血缘查询/线程读进入热路径（例如看板每轮 poll）时——
届时考虑索引缓存 + mtime 失效，或把血缘索引落成「可重建的派生件」（不能变成第二真源）。

## ⑤ `withLock` 残余 TOCTOU（已知边界）

**债**：`finally` 里「读回锁文件确认令牌 → `rm`」之间有一个极窄窗口——确认之后、删除之前，
锁文件若被强夺者重建，删掉的仍可能是新持有者的锁。

**证据**：已登记 `INTERFACES.md` §2.19 第 1 条（647–653 行）：**实测分母 = 复核 150 轮 + 40 轮实机压测，未命中**；
读码确认窗口存在（两次独立系统调用之间没有原子性可借）。现有三道防线：①「验后删」（`e37f9df` 批1）；
②进程内 `serializeByKey`；③stale 强夺 + `onSteal` 留痕。

**为什么现在不修**：要真原子化得换 `flock` / `O_EXCL` 目录锁这类**跨平台语义不同**的机制，
收益（窗口从"极窄"降到"零"）与代价（Windows 语义差异 + 已实测的锁易主留痕路径要重写）不成比例。
**什么时候必须回头修**：命中一次（留痕可查）／临界区变长／跨进程写者变多时。

## ⑥ 跨账本同毫秒撞 id（待裁决）

**债**：记忆 id 的种子是「类 + 主体 + 时刻」，**不含 scope**；同一毫秒、同一主体、同一类在**两个不同项目账本**里会算出同一个 id，
而跨账合并的读面（`query` 的跨项目+项目扫描、`stats()` 跨账 fold）按 id 归并 ⇒ **两条记忆静默合一**。

**证据**：
- id 形状：`src/kernel/ids.js:44-61`（`<kind 前缀>-<slug(seed)>-<短哈希>`，`at` 参与哈希）；
- 查重只在**单本账本**内：`src/memory.js:856-866` —— `const rows = await readJsonl(file); const 已用 = new Set(rows.map(...))`（`file` 是一本账）；
- 实例内递增只管本实例：`src/memory.js:805-820`（`#lastStamp` 是实例字段）；
- 合并 fold 确实存在：`src/memory.js:339` 起的召回面与 `stats()` 跨账合并（`93109b1` 批2 ⑪）。

⇒ 触发条件是「两项目 × 同毫秒 × 同主体 × 同类」同时成立——窄，但不是不可能。
（批1 已在**同账本**内堵过：锁内查重 + bump 时刻重算，`test/concurrency-w3.test.js` 有断言。）

**为什么现在不修**：修法（id 种子加 scope）会改既有 id 形状与既有引用面，属**数据模型变更**；
单项目部署下根本触发不到。
**什么时候必须回头修**：出现第二个项目、且同类记忆在同一毫秒写入的现场；或做 id 方案整体变更时一并带上。

## ⑦ `archiveAnswers` 锁外读（待裁决）

**债**：归档时先**锁外**读整本作答账，再**锁内**逐条追加归档状态行——两次之间新写入的作答不会被本次归档覆盖。

**证据**：`src/memory.js:615-626`：

```
const rows = await readJsonl(file);                       // ← 锁外读
const open = rows.filter((row) => !isStateRow(row));
...
await this.#appendLedger(file, open.map(...追加 '归档' 状态行...));   // ← 锁内写
```

**后果**：**不丢数据，只漏一次归档**——那条作答仍留在召回面，直到下一次结账/归档调用（`tasks.settle` → `MemoryService.archiveAnswers`，`b30c704` ③）。

**为什么现在不修**：把读也搬进同一把锁（read-modify-write 合一）会扩大 `#appendLedger` 的职责（读+写一体），
需要一条新的门禁测试；而归档是结账路径（低频、Lead 触发），当前没有并发现场。
**什么时候必须回头修**：结账与成员交卷并发出现，或把「一次结账把当时全部作答归零」写成硬承诺时。

## ⑧ 服务面 `发件` 未收紧（动作面已封）

**债**：`bus_send` **动作面**已封（`args.发件` 一律忽略，handler 恒以主体链真实 id 为发件人），
但**服务层** `bus.send` 仍接受调用方给的 `发件`——因为内部编排需要它（unlock 广播、讨论轮边界、converge 末位表态）。

**证据**：`INTERFACES.md` §2.15（545–550 行，「系统类型消息仅系统主体可发」+「动作面发件不自报」）；
`src/debate.js:171-179`（轮边界用 `subject: { id: 'system', kind: '系统' }`）、`src/debate.js:210-218`（converge 发件 `lead`）。
攻击面已被 W2 安全修复堵掉（`bbec0d1`：任何人自报三件套 → `Denied`；动作面自报发件 → 落线发件＝真实主体）。

**为什么现在不修**：服务面收紧会让上述内部编排**没有表达方式**——要么改签名让编排传主体、要么给「系统主体」一个内部构造器；
这是接口设计（谁可以扮演系统），不该在安全修复批次里顺手改。
**什么时候必须回头修**：新增任何「模型参数直通 `bus.send`」的路径之前（那时服务面就是新的伪造入口）。

## ⑩ `useStore` 的宿主假设未验证（待裁决）

**债**：看板客户端有一个**假设**——「宿主给插件的 React 里 `useEffect` 很可能是空实现」；
它不是机制性验证，而是对真机现象的推断。`hook()` 兜底只覆盖「hook 缺失」，覆盖不到「是函数但不跑回调」。

**证据**：
- `components/board/lib/client.js:1360-1376`：注释自述观察（真机上面板/设置页停在初始态，而点「保存」能动 ⇒ `useState` 好、`useEffect` 坏）；
- `components/board/lib/client.js:64-85`：`hook()` 检测 `typeof fn === 'function'`，是函数就用 ⇒ 「是函数但不跑回调」这条路径的兜底**不生效**；
- 缓解已在：取数移出 `useEffect`（裸 `setInterval` 轮询，`client.js:1359-1382`）⇒ 即使假设成立，也只少一层增强。

**为什么现在不修**：要验证得能拿到宿主 React 实例（跑一次真实挂载探针），本仓测试环境给不出；
改法只剩「关键路径不用 `useEffect`」——**已经做到**了。
**什么时候必须回头修**：宿主升级 React／出现第二家宿主时，或要把关键路径重新挂回 `useEffect` 时。

## ⑫ `needsQuote` 触发集与读侧规则互为配对（已知边界·不变式）

**债（配对不变式，不是待修缺陷）**：`formatFrontMatter` 写侧的「需要时才引号化」触发集
（含 ` # ` / 行首 `#` / 换行 / 引号 / 反斜杠 / 首尾空白 / 空串 / 整值形如 `[...]`）与读侧规则
（剥引号、切行内注释、切数组）**互为配对**：改一侧必须同步改另一侧。

**证据**：`INTERFACES.md` §2.19 第 2/3 条（654–658 行）；实现 `src/tags.js` 的 `needsQuote/quoteValue` + `unquote`/`splitArrayItems`；

已有断言钉住 `26162cb`）；触发集是「不引号化就会读坏」的集合，不能扩大成"全引号"。
**什么时候必须回头补**：读侧新增任何注释/分隔语法时，**同一提交里**把触发集补上——否则又会出现「往返不闭合且静默」。

## ⑮ `强制反对者` 不进投影、不上板（未接线·反趋同同族）

**债**：`强制反对者`（§10：系统随机指定一名**未参与**成员，且**不重复**）机制**已经实现并且真的在跑**，
但它只落在**审计详情**里——工作台会审行投影**没有这个字段**，看板也**不渲染它**。
属「反趋同机制在、接线不在」同族（与该批 API `openBlind` / `declareMode` / `pickDissenter` 同源）。

**证据（各自的搜索面与分母）**：

```
# ① 机制存在且在跑：src/review.js 有定义，且把结果写进审计详情
$ git grep -n "pickDissenter" -- src
src/review.js:157:  async pickDissenter(spec) {            ← 定义
src/review.js:172:      详情: { 强制反对者: 反对者, 节点: …, 不用过: 已用过 },
#   它还自读审计详情来保证「不重复」（review.js:327-329）⇒ 事实源是审计，不是投影

# ② 工作台投影没有该字段：面＝src/workbench.js 的会审行（325-367），分母 0
$ git grep -n "强制\|反对者" -- src/workbench.js
（零命中；同文件 14 行的会审块说明也只列「交卷进度 · 独立答案 · 分歧清单 · 反例面 · 零分歧」）

# ③ 看板不渲染：面＝看板 client 及其测试，分母 0
$ git grep -n "反对者" -- components/board/lib/client.js components/board/test/
（零命中；会审行的归一化字段表在 client.js:456-492，也没有这一项）
```

**现在从哪能看见它**：只有审计线（`audit_tail` 或账本）里那条 `状态变更 · 详情.强制反对者`，
以及 `review.js:327-329` 自读审计的「已用过名单」。

**为什么现在不修**：接线要先定「**谁看、在哪看**」——工作台的设计已经定了两条：
①它是纯投影、**不显示讨论内容**（`src/workbench.js:21`，§7「不做讨论、不做权威记录」）；
②面板关于讨论只给**一行状态读数**（`components/board/lib/client.js:1809-1821`）。
「这次会审有没有强制反对者」属于**新增的可见面**，是设计决策，不该在文档收口批次里顺手加一个投影字段。
（同类留白同源：`openBlind` / `declareMode` / `pickDissenter` 在 `ACTIONS`（`lib/actions.js:17-54`）里都没有动作入口，
`review_zero` 是唯一进了 `ACTIONS` 的复核/反趋同相关动作；`reveal` 由 `debate_open` 内部调用，不经模型可达动作。）

**什么时候必须回头修**：如果要让人在**面板上**看见「这次会审有没有强制反对者 / 是谁」，先定投影字段
（工作台会审行加一位，或单独一格），再改看板渲染——**两处一起改**，只加投影不渲染等于没接。
