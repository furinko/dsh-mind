## 验证命令

项目无运行时 npm 依赖。使用 `package.json` 支持的 Node 版本，在仓库根目录执行：

```powershell
node test/preflight.mjs
node --test "test/*.test.js" "components/board/test/*.test.js"
node components/board/test/client-harness.mjs
node scripts/verify-profile-install.mjs --selftest
git diff --check
```

`npm test` 包含前三项。没有 npm 命令时可直接使用 Node，不能因此省略看板或安装检查。

先跑改动相关的正反例，涉及执行、权限或跨模块行为时再按影响范围运行完整池。纯文档与历史材料归档核对链接、文件清单、发布边界和preflight，不重复业务测试。测试应验证用户可见行为和实际边界；文案与可逆低影响编辑不另建照抄实现的测试。

preflight 检查出厂文档、岗位能力引用、包导出、三组件装配、浏览器经典脚本限制与模块可加载。安装 selftest 证明包形状检查器能发现反例，不证明真实 profile 已安装或当前运行代码已生效。

## 部署

开发、提交、推送、包发布与本机源码同步是分开的操作。用户已授权后续完成并验证的Mind更新持续同步到本机DSH，当前状态见[状态页](STATUS.md)。运行部署前需核对成员文件范围、历史项目绑定、原有私有叠加与岗位钉版，以及实际宿主接口；新出厂卡不会自动重写已有实例的权限。

部署后的真实工具、审批界面、项目归属、guard 回执和采集健康需要在目标环境验证。无法确认的运行状态保持未知；不要把 Git HEAD、安装退出码或文件时间当作 HMR 已成功的证据。

真实宿主验收先使用独立profile和数据根，隔离DSH_HOME、DSH_AGENTS_HOME、USERPROFILE、AppData与Temp；不复制真实凭证。核对实际桌面安装的CLI及ASAR包版本，不把旧profile的SDK版本当当前宿主。Windows解档后逐文件SHA核对中文路径，失败不继续启动。恢复前确认本轮持有的子进程已退出及对应端口关闭，恢复字节和目录/链接拓扑，再冷启动检查未安装Mind；冷启动会自然写状态，停机后需再次恢复并比较。实例启动日志中的测试认证令牌不能公开。实际结果见[隔离宿主验收](归档/验收记录/隔离宿主验收-2026-10-21.md)。
