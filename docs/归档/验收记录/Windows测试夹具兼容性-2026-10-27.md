# Windows 测试夹具兼容性（2026-10-27）

本批仅修改测试和记录。Mind 运行代码、权限规则及桌面配置不变，不需要重新装载；现有 runtime 继续使用 `e2bed7b`。

## 文件符号链接

原 `memory-reuse-2026-10-24.test.js` 将损坏日志与文件符号链接场景放在同一项中。Windows 在创建临时测试链接时返回 `EPERM`，后续防护断言未执行，造成整项失败。旧标题还写了“过时身份”，却没有实际执行封存检查。

现在将三种情况各自验证：

- 损坏日志须返回明确错误，并保持原坏文件内容。
- 文件符号链接须被读写入口拒绝，链接目标内容须不变。仅当 **Windows 创建测试文件链接** 报 `EPERM` 时，明确跳过并标注“该防护场景未验证”。链接创建成功后的防护断言、其他错误及非 Windows 错误全部继续报失败。
- 用真实 Registry 封存合成 Lead，确认旧身份无法读写，原观察账本内容不变。

沙箱外隔离执行原用例仍出现 `EPERM`，没有为此修改 Windows 全局权限或安装额外系统环境。当前机器的真实文件符号链接场景仍未验证，不能计为通过。仓库既有 Ubuntu/Windows × Node22/24 CI 矩阵保留；非 Windows 不适用本跳过条件，本批未推送或运行远端 CI。

通过预加载脚本将 `symlink` 的错误替换为 `EIO`，目标测试保持失败、零跳过，确认不会将其他 I/O 故障吞成“无权限”。这是错误处理校准，不是真实符号链接验收。

## 同批发现的虚拟时钟问题

首次完整回归在自由空间审批重放测试中出现“失联”拒绝。夹具固定为 2026-10-24 02:00 UTC，却只重写 `clock.ms()` 和 `clock.iso()`，策略检查的 `clock.now()` 仍读实际时间。2026-10-27 02:00 UTC 后，审批操作写入的夹具交互时间超过真实时钟的 72 小时阈值，因此失败。

冻结旧源码的相同用例也出现该失败。修正为只冻结 `clock.now()` 这一共同时间源，`ms()` / `iso()` 自然派生，原有审批、单次重放及失联规则均未修改。

## 结果与证据

两个相关测试文件合计 32 项：31 通过、1 项文件符号链接因权限跳过、0 失败。最终完整回归 2285 项：2271 通过、14 项明确跳过、0 失败；14 项中包括本机无法创建文件符号链接这一项，跳过不计为通过。84 模块 preflight、549 条客户端断言及 10 项安装器自检通过。

仓外证据：`audits/mind-symlink-test-20261027/`。原文件符号链接失败见 `before-privileged.log`，旧源码时钟失败见 `baseline-clock-failure.log`，非权限错误校准见 `calibration-eio.log`。首次完整检查的时钟失败保留在 `full.log`，不改写为通过；修正后完整检查写入 `full-final.log`。
