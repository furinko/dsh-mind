## 修复内容

| 冲突 | 修复后的行为 |
|---|---|
| 复核任务终止或未派发仍可出票 | 对复核员自己的复核任务使用现有任务作用域判据，检查授权寿命、负责人和当前绑定凭证；在项目账本锁内再次核验。报告已交卷后的合法出票及 Lead 独立验收、审批重放保留。 |
| 人侧停用正式记忆后被成长回执恢复 | 治理操作读取正式记忆的处置历史，覆盖全部岗位副本及最多 16 个替代链节点。人侧停用、降权、更正和删除不能通过修订、重新分配或替代回执恢复。 |
| 跨聊天共享偏好但不共享删除屏障 | 正常记忆与仅保留会话散列的屏障共用同一关系解析规则。默认同主人和显式同关系均承接屏障，不扩大到不同关系；真正后续用户表达仍可生效。 |
| 淡去记录恢复时保存空正文并阻塞阅读 | 治理读面保留身份、项目和关系检查，同时允许读取合法停用正文；保存前核对完整正文。模型自己的淡去记录及能力候选可恢复，人侧可修复旧版空待处理回执。 |
| 系统提示否认目标持久化 | 说明持久目标已支持保存、查询和更新，当前范围可恢复工作资料；不承诺自动接管或持续执行。 |
| 关闭心智后的委派指路不可执行 | 保留安全闸。启用心智自主调度的项目中，关闭期间隐藏原本已被拒绝的创建工具，旧调用明确提示重新接入后再委派；非受管根聊天和其他聊天不受影响。界面及 README 同步说明。 |

记忆治理准备保留正文、状态及历史的指纹，并在正式写入的提交点复验。独立复查发现待处理替代记录在重新修订、再次被替代时可能丢失原记忆依赖；本轮进一步统一收集 `native`、`retire` 和已有见证中的依赖，要求提交见证完整覆盖，补上失败重现及正常重试回归。此机制不替代操作系统隔离，也不承诺跨账本原子事务。

对旧版缺失依赖见证的待处理替代记录，读取既有 `replaces` 关系图逐节点核验范围，限制为 16 层、64 个节点；缺链、循环或超界拒绝处理。依据不完整的旧记录拒绝模型自动恢复，完整关系图可供人侧明确核对恢复。新记录保存显式依赖见证，真正无依赖时也保存空见证，避免与旧格式混淆。独立测试用实际 `49a272c` 源码生成旧数据，确认三条绕过路径均被阻断，并确认人侧恢复后 Lead 仍可正常修订。
