# 会审（独立出方案 → 全员交卷 → 收敛）—— 做出来是什么样

> 这份文档是**跑出来的**，不是画的：用现有代码走通整条流程，把真实产出贴在这里。
> 三个成员的方案正文是样例文本（真实运行时它们来自三个独立 subagent），
> 除此之外的文件名、节点字段、线程消息、审计条目、投影结构都是程序真实生成的。
>
> **范围说明**：这里描述的是**会审**——它已经实现并在面板上（独立答案 / 交卷进度 /
> 分歧清单 / 反例面 / 零分歧告警）。文中的「讨论段」**已实现**（`6acf964`，2026-10-09 规格冻结）：
> 全员交卷解锁后，参与者轮流发言（`debate_say`，类型＝分歧/表态/答复）→ 换轮（`debate_round`，
> 预算重置、轮边界落一条系统消息切轮）→ **Lead 末位表态**收敛（`debate_converge`）。边界默认
> **轮次 2 · 人数 8 · 每轮 24 条 · 每人 4000 字**，可在私有 `部署.json` 的「会审讨论」键
> **部分覆盖**（缺键用默认；开启讨论时冻结快照，事后再改部署不追溯进行中的讨论）。
> 面板仍只读、**不显示讨论内容**（工作台 §7「不做讨论」，见文末第五节）：投影进去的是讨论的
> **状态读数**（轮次 / 本轮消息数 / 可收敛提示 / 讨论未收敛标注），不是发言正文。

## 一、你在会话里做什么

```
你    /mind task_create 描述=看板面板的数据怎么取：轮询/会话命令/自定义服务 \
      负责人=member-a,member-b,member-c \
      判据=不引入第二事实源,界面不可用时后端照常,失败要可解释 \
      模式=独立会审
Lead  建节点 → 派发（判据此刻冻结，之后谁也改不了）

      ── 独立段：三个成员各自出方案，互不可见 ──
      （真实运行时 = Lead 扇出三个 subagent，各自独立上下文，天然满足"交卷前不能互看"）

你    /mind workbench
      会审那一段显示：交卷 1/3 … 2/3 … 3/3
      3/3 之前，讨论段是**锁着的**，你只能看到进度，看不到任何人的答案

      ── 门：全员交卷 → 消息总线解锁并广播 ──

你    /mind bus_read 线程=<节点 id>
      现在能看到三份答案，以及揭名后的讨论

你    /mind task_review id=<节点 id> 三态=过 分歧清单=无会话首屏
      （或者不过 / 未验；未验既不算通过也不计打回）
```

**"实时"要这么理解**：你能随时发话、随时看，但成员之间是**轮流**发言的——
你一句话 → Lead 分发 → 各成员回答 → 回到线程。N 个成员 × M 轮 = N×M 次模型调用，
这是真金白银，所以必须设轮次与人数上限。


**面板上关于讨论，到此为止——正文不上板。** 上面那行 `💬 讨论：…` 就是讨论段在面板上的全部：
`row.讨论` 只渲染 `状态 / 轮次 / 本轮消息数 / 可收敛提示 / 未收敛标注`
（`components/board/lib/client.js:1809-1821`），**逐条发言只在线程账本里**。
所以图上「任务已采纳（复核已过）」与「讨论未收敛」同时出现是**正常且有意**的：复核对讨论是软约束，
这一格正是「Lead 不收敛」的可见信号（不许把它做成 review 的硬闸）。
要看正文，人侧显式读线程（下文这些线程消息是真实运行生成的，只是不属于面板）：

```
你    /mind bus_read 线程=<节点 id>
      [广播] system      全员已交，会审解锁：现在可以亮出彼此的答案。
      [分歧] member-b    同意用命令，但无会话首屏怎么办？兜底是上次快照
      [表态] member-c    我的方案被 B 的反例面驳倒了，我改投命令方案。
      [表态] lead        综合：用会话命令…（Lead 最后表态，不首发）
```

**另有一行不属于面板**：`强制反对者`（§10：系统随机指定一名未参与成员、且不重复）由
`review.pickDissenter` 指定并写进**审计详情**（`src/review.js:150-174`），既不在工作台会审行投影
（`src/workbench.js:325-367` 的字段表）里，也不在看板渲染里（`components/board/lib/client.js`
全文 grep「反对者」零命中）——本图早先画过的那一行是**设计意图**，不是今天的界面输出。

**锁着的时候是什么样**（3/3 之前）——这是设计最在意的那一格：

```
│ 会审 · 独立会审                                     交卷 2/3 未齐    │
│   🔒 未交齐，讨论保持锁定。你只能看到进度，看不到任何人的答案。        │
│      待 unlock 后揭名。                                               │
```

## 四、这一跑暴露的三个缺口

都是真跑才暴露的，写在文档里免得下次又忘：

| # | 缺口 | 依据 | 状态 |
|---|---|---|---|
| 1 | 成员交产物被拒：`ObjectStore.write` 没把任务上下文传下去，成员被判"任务外" | §2 任务内全权 | **已修** |
| 2 | 一岗多人匹配不上：`scopeOf` 拿字符串比数组，多负责人任务上谁也干不了活 | §10 一岗多人 | **已修** |
| 3 | 独立会审的 **N 份结论只留了最后一份**：节点上 `交卷结论` 被覆盖 | §10「独立会审 → N 份独立答案 + 分歧清单」 | **已修**（早于本波：本仓首个提交 `b68e24f` 导入时源码已如此） |

第 3 条已修，修法正是当时设想的那种：交卷折叠时把结论**按人**合进 `独立答案`
（`src/tasks.js:579-580`：`const 他人 = (node.独立答案 ?? []).filter((a) => a.成员 !== 交卷人);`），
工作台投影逐人出 `独立答案: [{成员, 结论, 反例面, 产出物引用}]`（`src/workbench.js:312-350`），
面板与工作台因此能说清"三份结论分别是什么"；**未交齐时只给 `{盲标}`**（W3 批2/批3 把遮罩
做在投影这一层，见 `INTERFACES.md` §2.10）。

**这个修复不在本仓的某一笔提交里**：`git log -S"独立答案" -- src/tasks.js src/workbench.js`
只命中本仓历史起点 `b68e24f`（2026-10-07 导入提交，**无父提交**）——也就是说，在导入那一刻
（`git show b68e24f:src/tasks.js` 第 332 行、`git show b68e24f:src/workbench.js` 第 210 行）
按人留 + 按人投影就已经在源码里了。本表这一行是文档没跟上，不是代码没修。
（同表第 1、2 两条同理，都已抽查过导入提交里的源码：`src/store.js` 的
`context: { reason, task: spec.task ?? null }`、`src/policy.js` 的 `scopeOf` 名单归一。）

顺带两条要加的边界：

- **讨论轮次 / 参会人数 / 每轮消息预算** ✅ 已落地（`6acf964`）：默认
  `{轮次上限 2, 人数上限 8, 每轮消息上限 24, 每人每轮字符上限 4000}`（`src/policy.js` 的
  `DEFAULT_DEBATE_BUDGET`，`README.md` §用法同款口径），私有 `部署.json` 的「会审讨论」键
  部分覆盖、加载期校验（坏值 fail-closed）；超限 `Denied` 给 `x/y` 读数，人数超限提示拆会审。
- **节点 id**（**仍未做**）：现在由描述 slug 出来，长描述会变成
  `看板面板的数据怎么取-轮询-会话命令-自定义服务-muy2t9om` 这种没法念的东西
  （`src/tasks.js:82`：`` `task-${slugOf(input.描述, 'x')}-${this.clock.ms().toString(36).slice(-5)}` ``）。
  要给人看，得让它可读（或者面板上只显示描述，id 收在折叠里）。
