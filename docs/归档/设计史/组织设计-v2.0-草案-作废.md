# 心智 · 数字组织设计 v2.0

> 本文件是唯一设计真源。实现与排期另文；设计确认后，`DESIGN-MAP` / `INTERFACES` 以本文件为准重写。

---

## 0 目的与判据

**目的**：让主权者把工作长期委托给数字组织；不依赖单次会话的上下文，也不依赖模型自觉。

**三条立项理由**：长期记忆装不住；防上下文污染与注意力分散；减少 LLM 讨好效应。

**成功判据**：同类问题解决成本随时间下降；同一个坑不踩第二次；知识被用起来，而不是只涨不用。

## 1 主体与身份

### 1.1 主体分类

系统主体分为五类：

| 主体 | 在编 | 权 |
|---|---|---|
| 主权者 | 不在编 | 立宪、立法、否决、撤回、查看、根参数 |
| 出厂作者 | 跨部署 | 出厂内容、防护机制、安全类强更 |
| Lead | 常驻岗位，实例多会话 | 执行首脑、提案、派活、汇总验收、采纳/结账 |
| 成员 | 岗位持久，实例临时 | 任务内全权，任务外无 |
| 系统 | 不在编 | 审计、探针、调度、版本失效等机制动作 |

**复核者属于成员岗位卡的一种特殊化，不是独立主体类别。** 其身份、实例、生命周期与审计规则继承成员，仅增加独立验收所需的权限与约束。

权限由岗位卡及其特殊化决定，不由主体类别字符串决定。策略判定以“主体 + 岗位 + 特殊化 + 任务作用域”为输入。

### 1.2 岗位卡

岗位卡是持久的身份定义，描述一个岗位“是谁、能做什么、受什么约束”。

| 字段 | 含义 |
|---|---|
| `roleId` | 岗位标识，稳定不变 |
| `cardVersion` | 岗位卡版本；任何修改递增 |
| L0 身份 | 岗位的核心身份与权限边界 |
| L1 规则 | 岗位必须遵守的行为规则 |
| L2 能力引用 | 指向能力库条目，不内嵌正文 |
| L3 经验引用 | 指向记忆服务中的经验条目，不内嵌正文 |
| `generation` | 代次；职责演进时递增 |
| `status` | 在编 / 封存 |

岗位卡是责任与学习的单位。岗位的经验、能力与履历归属于岗位卡，不归属于任一实例。

身份核心（L0）不可就地改写；复核特殊化的独立性与只读约束属于锁定内容，只允许出厂作者或主权者按版本更新。锁定必须依据卡结构与元数据判定，不允许由写入方自行声明“这不是锁定段”。

### 1.3 实例

实例是岗位卡的临时执行体，描述“这一次由谁、在什么范围内执行”。

| 字段 | 含义 |
|---|---|
| `instanceId` | 本次执行的唯一标识 |
| `roleId` + `cardVersion` | 启动时钉住的岗位与卡版本 |
| `taskId` / `project` | 任务与项目作用域 |
| `scope` | 写域、可用工具、时限 |
| `lifecycle` | 创建 → 绑定 → 活跃 → 交卷 → 封存 |
| `audit` | 绑定、动作、结论、退场记录 |

实例不持久保留权限、身份或上下文。任务结束或复核结论落账后，实例封存；审计记录保留，可回答“哪个岗位的哪次实例、使用哪版卡、做了什么”。

### 1.4 Lead

Lead 是岗位与决策责任的唯一承担者，不是单一进程实例。每个主会话窗口对应一个 Lead 实例。

所有 Lead 实例共用岗位卡、能力库、记忆服务、任务图与审计；当前会话上下文不互通。

多个 Lead 实例并发时，通过任务认领、租约、幂等派发与审计归属协调；同一任务不得被重复派发或重复采纳。

### 1.5 复核特殊化

复核者是成员岗位卡的复核特殊化，职责是：对已冻结判据的交付版本，做独立验收判定。

- **无任命**：不设复核者任命、候选、池、轮换或主权者逐案确认。
- **系统启用**：任务进入待复核状态时，由系统按复核策略启用复核实例；Lead 不点名。
- **同源同卡**：所有复核实例使用同一张复核特殊化岗位卡，权限与约束一致；不存在“不同的人可供指派”。
- **临时实例**：复核实例是成员实例的一种，用完即退；署名并对结论负责，岗位卡承担“人”的连续性。
- **冲突排除**：执行者、交卷人、任务负责人、与执行者共享执行上下文者，不得担任该任务的复核实例。

### 1.6 寻址与绑定

任务节点的负责人落为实例集合。创建任务时若填写岗位名，派发时展开为该岗位当前在岗实例集合；“全员已交”等判定一律以实例标识为准。

一次执行的完整身份由“实例 + 岗位 + `cardVersion` + 任务作用域”构成。绑定缺失或失效时，实例不得行动。绑定由系统自动完成，不依赖人工任命。

### 1.7 责任与学习归属

责任归属于岗位卡与审计记录：

- 岗位卡承担身份、能力与经验的连续性；
- 实例标识承担具体执行的追溯；
- 审计回答“谁、凭什么、在什么范围、做了什么、结果如何”。

学习归属于岗位：实例产出经复核/采纳后，经验与知识进入岗位命名空间或能力库，再由岗位卡引用。

## 2 治理结构

### 2.1 三档门槛

立宪 / 立法 / 自治。唯一分界线：主权者定的 > 组织定的。

- 立宪、立法：主权者主导；Lead 可提议、协助起草，不能自定。
- 自治：组织自决；主权者默认不参与。

### 2.2 三权

- **查看**：主权者随时可看任何对象、任何账本。
- **否决**：任意时刻否决任意一条；否决入审计。
- **撤回**：写拒绝名单，不删卡；卡与历史保留，新的写入一律不许。

### 2.3 介入度

四档表示组织对自治变更的检查强度，仅影响自治档：

| 档位 | 语义 |
|---|---|
| 零参与 | 自治写按策略放行，事后审计 |
| 事后抽检 | 放行 + 按比例抽检 |
| 变更预审 | 高风险自治写先过复核/验证闸，再落盘 |
| 逐条校验 | 每条自治写都过复核/验证闸 |

后两档由复核实例/验证闸执行，不要求主权者在线；主权者保留事后否决与申诉权。

介入度必须有设置项，仅主权者可改，变更入审计，非法值 fail-closed。

### 2.4 失联

失联指主权者超过自设响应期限未响应。

- 已授权业务与证据记录继续；
- 立宪、立法、扩权、根参数等治理变更冻结；
- 恢复为主权者任一交互；恢复不等于批准待决项；
- 失联期间的例外由值班 Lead 在既有授权内处理，不得扩权。

### 2.5 留痕

每次状态变更必须可回答：谁、凭什么、谁复核、结果、可回滚点。无留痕的自治变更无效。

### 2.6 授权模型

| 类型 | 签发人 | 用途 |
|---|---|---|
| 常任授权 | 主权者（部署配置） | 长期边界：项目、工具范围、复核策略、Lead 调度范围 |
| 任务授权 | Lead（不超过自身 scope） | 一次派活：节点、写域、工具、时限 |
| 决议 | 主权者（命令面/专用通道） | 根规则、宪章/法律、重大例外 |
| 例外授权 | Lead 或主权者按动作 | 临时扩权，必须有期限、范围与审计 |

约束：

- 不能越授：子 scope 必须是父 scope 的子集；
- 不能自授：主体不得给自己签发授权；
- 授权引用指向授权对象，并校验签发人、scope、期限、状态；不得用“任意存在的任务节点”代替授权；
- 授权签发、撤回、拒绝、使用均入审计。

## 3 八件基础设施

### 3.1 策略引擎

- 唯一判定点；写操作无旁路；fail-closed。
- 拒绝必须带可执行理由：哪条规则、改它要什么授权。
- 判定维度：主体、岗位、特殊化、实例、任务、项目、对象、动作、授权。
- 读面同样过判定：审计、能力、注册表、工作台、状态；只保留显式登记的特权读。
- 引擎加载失败、规则坏、身份档案坏，一律拒绝写并告警。

### 3.2 任务图

- append-only 事件流 + 折叠；任务状态权威。
- 验收标准必填；派发时冻结 `criteria@version`。
- 修改判据必须产生新版本、重新冻结、旧复核失效。
- 状态机：待派发 → 已派发 → 执行中 → 已交卷 → 复核 → 已采纳/已打回 → 已结账；待决是状态。
- 依赖在派发时校验：前置未完成不得派发。
- 一岗多人必须声明“并行分担 / 独立会审”。
- 负责人落实例集合；岗位名在派发时展开。
- 产出物只存引用：`artifact@version`，不存正文。
- 交卷冻结：提交后答案与产物版本不可静默替换；改版走新代或新版本。

### 3.3 消息总线

- 按项目、按线程 append-only；线程隔离。
- 支持暂不投递；历史不自动进入上下文。
- 会审讨论线程只允许会审发言；盲评期对成员遮罩他人消息。
- 读面按主体、线程与收件规则授权；收件人身份不等于读权限。
- 消息发件人恒为真实主体，不接受自报。

### 3.4 角色注册表

- 是索引，不是真源；真源为岗位卡与身份档案中的实例绑定。
- 记录岗位、实例、卡版本、任务范围、状态、代。
- 岗位卡定义“能做什么”；实例绑定定义“这次是谁、在什么任务”。
- 不承担复核者任命；复核实例由系统按复核策略启用并自动绑定。

### 3.5 共享工作台

- 纯投影，无存储；从任务图、日志、记忆读数重算。
- 只读；Lead 与复核者看全量，成员只读自己任务那片。
- 不显示讨论正文、他人未揭名答案、治理面私密数据。
- 分页、增量更新；不每次全量扫账本。

### 3.6 能力库

- 与记忆服务并列；单源；多岗位共用不复制。
- 双区各一份，同名不合并；默认使用自治版，冲突并列给 Lead/主权者。
- 能力卡带版本；角色卡 L2 引用 `能力 id@版本`。
- 能力修改或升级产生新版本；旧实例不受影响，新实例使用钉住版本。
- 能力升级须经评审/合并规则；安全类按安全类规则。

### 3.7 记忆服务

- 四类：知识、经历、偏好、作答。
- 只增不改；失效、降权、推翻均追加；物理删除仅限敏感数据或主权者要求。
- 归属：
  - 知识 = 岗位 + 项目双标签；
  - 经历 = 组织账本；
  - 偏好 = 部署；
  - 作答 = 实例，任务结束归档。
- 经验本体住岗位命名空间；角色卡 L3 只存引用。
- 读取按项目、岗位、任务作用域；跨项目默认禁止。
- 检索：BM25 + 过滤 + 长度归一；零命中须报搜索面、查询词、范围。
- 坏行可见；写入时校验正文结构，不合规拒写。

### 3.8 审计

- 只增；写入无条件；任何人不能改，只能追加更正。
- 记录：谁（岗位 + 实例 id + 卡版本）、动作、对象、依据、结果、时间、项目、轮。
- 分级：全记 / 记汇总 / 不逐次记。
- 链式哈希 + 检查点 + 锚；重启后可重建。
- 审计不承担业务状态；业务状态由任务图与对象存储负责。

## 4 岗位卡与实例架构

### 4.1 结构

```text
Role（岗位，持久）
  roleId · cardVersion · L0/L1/L2/L3 · generation · status
       │
       ├─ Instance { instanceId, roleId, cardVersion, taskId, scope, tools, lifecycle }
       │     ├─ 启动时钉住 cardVersion
       │     ├─ 系统自动绑定身份
       │     ├─ 权限 = 岗位卡 ∩ 特殊化 ∩ 任务 scope ∩ 项目 scope ∩ 工具范围
       │     └─ 用完 → 交卷/封存；审计留 instanceId + cardVersion
       │
       └─ Learning Loop：实例产出/经验 → 复核/采纳 → 记忆/能力 → 角色卡 L2/L3 引用
```

### 4.2 卡锁定与版本

- L0 身份核心锁定，只有出厂作者可改，随产品更新。
- 复核特殊化的独立性与只读规则锁定，只允许出厂作者或主权者按版本更新。
- 其他岗位的 L1/L2/L3 由组织按 authority 规则修改；改卡产生新版本并审计。
- 实例启动时钉住 `cardVersion`；旧实例不受新版本影响。
- 锁定判定必须从卡结构与元数据推导，不允许写入方自报 `segment` 绕过。

### 4.3 绑定与主体解析

- 系统创建实例时自动写绑定：`instanceId ↔ roleId ↔ cardVersion ↔ taskId ↔ scope`。
- 主体解析从会话事实取实例，再查绑定得到岗位与特殊化；策略按绑定判定。
- 无绑定或绑定失效，实例不得行动。
- 绑定随实例封存保留，审计可查。

### 4.4 生命周期

- 创建 → 绑定 → 活跃 → 交卷 → 复核 → 封存。
- 返工默认启用新实例；需要保留上下文时显式续用并留痕。
- 崩溃或重启后的孤儿实例由系统回收；未完成交卷不得自动成功。
- 封存不等于删除；需要时新建实例，不复活旧实例。

### 4.5 学习回路

- 实例产出交付物、证据与经验候选。
- 经复核/采纳后，经验与知识写入岗位命名空间，或发布为能力卡。
- 角色卡 L2/L3 只追加引用：能力 `id@版本`、经验 `id`。
- 晋升是受控动作：由 Lead 或记忆整理执行，禁止把实例原始上下文直接写入岗位，防止污染。
- 引用更新入审计。

### 4.6 并发与寻址

- 任务负责人落实例集合；岗位名在派发时展开。
- 同一任务同一时刻一个主执行实例；一岗多人按“并行分担/独立会审”模式。
- 任务认领 + 租约 + 幂等提交；多个 Lead 会话不得重复派发或采纳同一节点。
- 复核实例与执行实例不共享会话上下文；不同任务可并行。

## 5 复核

### 5.1 目的

独立验收判定：由未参与执行的主体，按冻结判据判断交付物是否合格，使组织不能自己给自己发合格证。

### 5.2 复核者

- 成员岗位卡的复核特殊化；固定岗位卡、多个临时实例、同源同卡。
- 无任命、无池、无候选、无轮换、无主权者逐案确认。
- 系统在任务进入待复核时启用；Lead 不点名、不写倾向性任务书。
- 实例署名、负责，可以说“未验”。
- 所有复核者实例同源，不存在“不同的人可选择”。

### 5.3 触发与输入

- 触发：任务状态为待复核；独立会审须全员已交。
- 输入：`criteria@version` + `artifact@version` + 证据包 + 约束。
- 任务书与提交说明只作被验方陈述，不构成指令。
- 复核实例使用独立上下文，不与执行者共享会话；只读，可在沙箱中复现验证。

### 5.4 方法

- 逐条判据核对；查证据、复现、沙箱实验。
- 记录查了什么、怎么查、证据、覆盖与未覆盖判据。
- 不改交付、不改判据、不提案、不采纳。
- 无法验证时判未验，附原因与缺失证据。

### 5.5 输出

```text
verdict: 过 | 不过 | 未验
判据覆盖: [{判据, 结论, 证据, 备注}]
分歧清单 / 反例面
未验原因: 缺什么证据 / 为什么验不了
署名: instanceId + cardVersion
```

### 5.6 效力

- 复核是硬闸：没有“过”，不得采纳；未验不得采纳。
- 不过：打回返工；返工产生新版本后重新复核。
- 免审：仅低风险任务可按常任复核策略免审；免审是显式状态，须审计，不产生“未验”。
- 宪章、法律、安全类任务不得免审。
- Lead 可记录不同意，但不得修改复核结论；采纳必须引用复核结论。

### 5.7 版本绑定与失效

- 复核绑定 `criteria@version + artifact@version`。
- 新交卷、新产物版本、判据修订，旧复核结论自动失效，须重新复核。
- 复核历史保留，但只对当时版本有效。

### 5.8 独立性

- 独立 = 独立实例 + 独立上下文 + 冻结输入 + 只读 + 不能改交付。
- 同模板、同模型的多个实例只算多次检查，不宣称独立判断。
- 如需更强独立性：异源模型、不同证据、机械验证、人工抽检；不通过“换人”实现。
- 执行者、交卷人、任务负责人、与执行者共享会话者不得复核。

### 5.9 质量

- 复核岗位卡与模板版本化。
- 抽检复核结论，统计误放与误杀；零分歧或异常触发抽检。
- 不设“复核者的复核者”岗位；质量由模板校准、抽检与审计承担。

### 5.10 不做什么

- 不审人、不审努力、不审战略、不审方案好坏。
- 不审过程合规；过程由审计与策略负责。发现越权或篡改可拒绝并升级。
- 不代替 Lead 采纳与结账，不代替主权者做价值裁量。

## 6 主干环路

```text
受理（Lead 接需求）
  → 定判据（Lead 写，映射回用户需求）
  → 判权限（策略引擎）
  → 派发（判据冻结；负责人展开为实例集合）
  → 执行（成员实例；任务 scope）
  → 交卷（冻结 artifact@version 与证据）
  → 复核（系统启用复核实例；三态 + 覆盖 + 证据）
  → 采纳 / 打回（Lead 按复核结论；不过则返工新版本）
  → 落记忆（经验/知识晋升到岗位/组织）
  → 结账（Lead；归档作答）
  → 刷新视图（工作台/看板）
```

每一步都有主体、输入、输出、状态迁移、审计与失败语义。

---

## 7 反趋同

- 提交后解锁：独立会审全员交齐后，才互相可见。
- 盲评：第一轮只显示 A/B/C，揭名在讨论阶段。
- 强制反对者：系统随机指定未参与、不重复的成员。
- Lead 不首发：征求意见时 Lead 最后表态。
- 零分歧报警：结论层一致且无人给出反例面，记“会审零分歧异常”并触发抽检；它是触发信号，不是判决。
- 反例面须带可核验引用；“未找到反例”须说明搜索过哪些面。
- 同模板、同模型的多个答案只算多次采样，不宣称独立。

---

## 8 记忆、检索、能力

- 记忆四类与归属见 3.7；写入必带“谁记的 + 怎么知道的”；悬空来源拒写。
- 知识晋升：项目知识默认不跨项目；可复用的一般知识提炼为岗位知识，经披露检查与审计后晋升。
- 跨项目检索项目记忆：默认关闭；只允许显式动作，需授权、理由、披露检查与审计。是否开放由常任策略决定；未开放时不得以参数绕过。
- 检索：BM25 + 过滤 + 长度归一化；零命中报口径；回归集与基线。
- 能力：双区、单源、版本化；角色卡引用 `id@版本`；升级与冲突按条款合并，冲突并列给 Lead/主权者。
- 作答归档：任务结束归档；归档后成员不可读；Lead/复核者可读；默认检索不返回，可显式查询。

---

## 9 项目隔离与上下文

- 项目是隔离单元：任务图、工作台、记忆命名空间按项目。
- 身份、岗位、履历跨项目统一；Lead 唯一身份，多会话实例。
- 岗位知识与能力随身份带，不算跨项目拉取。
- 上下文按需拉取：本轮线程、当前项目记忆、自己的任务；不推全量历史。
- 项目键由会话与任务确定，不由模型参数自由切换；显式跨项目需授权。

---

## 10 载体与升级

- 双区：出厂区（程序、模板、出厂默认值）与私有区（覆盖、数据、身份、审计、版本历史）。
- 升级：叠加层 + 条款级合并。
  - 用户没改过：直接替换；
  - 用户改了、出厂没改：保留用户版本；
  - 两边改同一条：私有优先并告警，或按主权者裁决挂起；
  - 安全类：强制替换，不可协商。
- 基线戳、不强制不等于不通知、可撤回。
- 身份核心与复核特殊化的独立性规则锁定；安全类不得被绕过。

---

## 11 安全类、威胁模型与审计

### 11.1 封闭清单

1. 用户数据或凭据外泄；
2. 防护机制被关闭或绕过；
3. 审计被篡改。

不允许以“其他类似情况”兜底。

### 11.2 探针

- 探针在机制就绪后运行，不以半成品回执判定。
- 探针版本由声明、实现指纹与数据兼容性共同确定。
- 探针红时定位“合格回滚集合”：探针通过、未被安全撤销、数据兼容。
- 恒红或恒绿均告警；探针自身故障也判红。

### 11.3 威胁模型

- **目标档 T1：越权代理。** 代理只能通过工具与参数越权，不能直接改写文件；策略、读面、授权、会审须在此档承重。
- **残余风险 T2：同机文件写者。** 不承诺防止本机进程或管理员直接修改文件；审计只承诺可检出代码路径篡改并可重建，不承诺不可篡改。
- T3：宿主或供应链被攻破，不承诺。
- 所有“安全、不可篡改、唯一”表述均按此分档限定；需要 T2 时另立隔离或外部锚项目。

### 11.4 审计完整性

- 只增；更正只能追加声明。
- 链式哈希、检查点、锚；检查点覆盖整片而非仅月尾。
- 审计目录之外保留存在性凭据；整删目录应见红。
- 写入前校验尾行完整；撕裂行不得吞掉下一条记录。

## 12 接口、权限与设置

- 模型侧 `mind` 工具、人侧 `/mind` 命令、同源 HTTP 路由共用同一动作表与同一实现。
- 动作面不列做不到的事；读面同样过判定。
- 工作台路由不冒充 Lead；读面按读者切片或宿主认证，写面要求认证。
- 设置项：介入度、响应期限、工具总范围、复核策略、根参数；主权者可改，变更入审计。
- 复核者不由任命产生；不存在复核候选指派语义；不存在复核者池。
- Lead 多实例通过任务认领、租约与审计归属协调；成员与复核者不因 Lead 实例不同而改变资格。

## 13 设计决定摘要

1. 主体五类；复核者是成员岗位卡的特殊化，不是独立主体。
2. 岗位卡持久，实例临时；实例用完即退，不保留权限/身份/上下文。
3. 复核者无任命、无池、无候选、无轮换、无主权者逐案确认；系统按任务状态启用实例。
4. 所有复核实例同源同卡，不存在“不同的人可供指派”。
5. 复核是独立验收判定：对 `criteria@version + artifact@version + 证据` 出三态，不审人、过程、战略。
6. 复核是硬闸；未验不等于通过；免审仅限低风险且须显式审计。
7. 判据派发时冻结；改判据须新版本、重冻结、重审。
8. 新交卷或新版本使旧复核失效。
9. 经验与知识归岗位；实例产出经复核/采纳后受控晋升到记忆或能力库，角色卡只存引用。
10. 岗位卡 L2/L3 引用带版本；实例启动钉住卡版本，审计可追溯。
11. 任务负责人落实例集合；依赖在派发时校验；一岗多人必须声明模式。
12. 介入度后两档由复核/验证闸执行，不要求主权者在线；失联只冻结治理变更。
13. 审计按 T1 目标、T2 残余限定承诺；探针回滚目标是合格集合。
14. Lead 是岗位/决策责任唯一，每会话一个实例；共用岗位、能力、记忆，上下文不互通。

---

## 14 验收判据

实现完成后，以下判据必须可执行验证：

1. 任何任务在未冻结判据前不得派发；判据修改后旧复核结论失效。
2. 未通过复核或未验的任务不得被采纳；复核结论不可被 Lead 修改。
3. 复核实例必须由系统启用并完成身份绑定；不存在点名、候选或池。
4. 复核输出必须含逐条判据覆盖与证据；无法验证时必须给出未验原因。
5. 执行者、交卷人、负责人、同会话者不能复核同一任务。
6. 新交卷或新产物版本后，旧复核结论自动失效。
7. 岗位卡、实例、卡版本、任务作用域的绑定可审计；实例退场后审计仍可追溯。
8. 经验/知识晋升后，岗位卡只追加引用；不存在实例直接改写岗位经验。
9. 读面（审计、能力、注册表、工作台、状态）全部经过策略判定；无只读暗门。
10. 审计整删、改历史后追加、撕裂尾写入三类攻击必须可检出或拒绝。
11. Lead 多实例并发时同一任务不得重复派发或重复采纳。
12. 任务依赖未完成时不得派发。

## 15 与 v1.5 的关系

本文件取代 v1.5 中与以下内容冲突的条款：

- 复核者不再由主权者确认，不作为独立主体类别；
- 复核者改为成员岗位卡的复核特殊化；
- 取消复核者任命、候选、池、轮换；
- 复核改为系统启用临时实例、用完即退；
- 复核绑定判据版本与产物版本，新版本失效；
- 复核输出增加逐条判据覆盖与证据；
- 经验回岗位改为受控晋升与岗位卡引用；
- 任务负责人落实例集合，依赖在派发时校验；
- 介入度后两档改为复核/验证闸；
- 审计与安全类承诺按 T1/T2 威胁模型限定。

v1.5 中未被本文件修改的条款继续有效；实现映射以本文件与更新后的 `DESIGN-MAP` / `INTERFACES` 为准。
