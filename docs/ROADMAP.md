## 维护与交付要求

1. **入口围绕工作。** README、架构、系统提示与出厂规程一致：普通问答不走完整组织流程，正式任务仍受当前权限和证据约束。删除过期的“尚未接线”及不符合当前实现的承诺。
2. **记忆按需返回。** 有文本查询只返回实际相关项，零命中不夹带账本尾部；默认摘要，详情显式取，整个响应受预算约束。项目、归档、失效与实际读域先于检索和分页；显式工具的岗位保持可选过滤，自动专业上下文另按真实岗位精确筛选。
3. **阻塞可以跟进。** 同一执行的拒绝不重复计数，后续成功、放弃和反馈可以追溯到原阻塞。模型声明与人侧确认分开，采集失败和未决结果不计零。
4. **界面消费同一读面。** 规则汇总和当前阻塞来自领域服务，不在浏览器重新判断权限或拼凑恢复。监控不能审批、改派、复活实例或自动续做。
5. **先冻结源码再统一验收。** 保留原池与有意义反例，另核查文档链接、包内资源、真实宿主假设及源码、装载与实机验收边界。

详细职责、信息归属和验收案例以[Lead与专业智能体](design/Lead与专业智能体-2026-10-22.md)为准。已有[专业知识默认装配](design/专业默认召回与上下文-2026-10-22.md)、[Lead连续性装配与更正](design/Lead连续性与更正-2026-10-22.md)及[需求解释与工作上下文](design/需求理解与工作上下文-2026-10-22.md)。下一步应以真实模糊需求、模型选人及整体交付收集反馈，并接续后续行为改善验证；原生宿主消费、主动记忆维护与实际收益仍需验收，自动装配不等于完整成长闭环。

首批[专业知识真实模型对照](归档/验收记录/专业知识效用对照-2026-10-23.md)确认岗位选材和干扰项过滤，但对照因错误预检未交付，不能认定收益。随后`115df1e`已补[预检纠错与采用提示](design/策略预检参数与知识采用提示-2026-10-23.md)并部署；[全新四次复验](归档/验收记录/预检纠错与知识采用复验-2026-10-23.md)均完成首版交付、12项检查及结账，两组有/无知识质量打平。两名带知识成员仍有历史自述冲突，提示未解决实际采用的可靠核对问题；一个Lead已正确把改口保留为自报而非历史认证。接下来围绕跨步骤资料事实和更有区分度的新任务取得质量、返工及包含维护的总成本证据；保持读权和当前限制，不为续记无条件重放旧知识，不补写或抹掉失败。

现已补[协作反馈与后续案例](design/协作反馈与后续案例-2026-10-22.md)的持久记录和自动装配，将原做法、反馈、改法及后续结果声明关联起来。后续优先补可信来源与主动维护，并取得后续独立案例的实际采用、重复纠正、返工、质量和成本证据；有界案例计数不当作统一成长指标。

已有[会话目标优先](design/Lead会话目标与相关教训-2026-10-22.md)与[同轮已接纳表达的教训选材](design/已接纳表达与教训选材-2026-10-22.md)，降低全项目近期记录对本会话工作的干扰。已核对SDK接纳时序和模型表面，只读当前Session，不增加消息或步骤钩子；下一步仍需首步当前输入的可靠选材、可信原话与语义焦点、主动维护及真实案例中的行为效果，不把词面命中当作需求理解或适用认证。

恢复、目标、预算和入口拆分继续作为可靠性工作维护，相关缺陷随纵向实现修复。它们共享执行归属和回执基础，应一起设计依赖关系；先做只读观测，不凭未经证明的宿主能力自动接管，不用完整后台执行协议替代产品主线。

第二轮已修复明确提交点的回执丢失及错误重试建议，完成 `member_spawn` 一条审批/执行计划共源。统一操作恢复与入口拆分尚未整体完成：跨进程操作对账、下游依赖迁移，以及其他领域宏动作仍需各自合同和实现。完整目标用量预算、知识采用效果闭环和大规模审计投影性能仍是开放工作。

第三轮进一步实现组织侧任务终止和正式后继关系：旧任务不能再提供新写资格，后继按原判据重新授权；已提交同规范请求只读认回，既往失败不清零。依赖仍按精确原id核验，自动迁依赖、宿主停止和副作用重放没有因此获得保证。

第四轮补齐目标最小持久合同、当前约束、任务证据和跨会话摘要。目标接续已有纵向实现，尚无可信对话来源和覆盖所有宿主工具的限制传播，不能宣称完整安全停点，也不证明Lead人格或用户偏好已自动装配。

第五轮先核对已安装 SDK 的 pre→审批→同步 guard→执行→result 合同，再实现可证明覆盖范围内的目标共享准入额度，并修复观测 pre 未透传 next 的接线缺陷。普通成员文件与成员创建共享累计，失败及未知不退款，额度不足不自动改目标状态；尚未接入真实 token、费用或全部执行者。后续先取得可靠模型尝试与用量归因、未知结果对账及真实宿主隔离验收，再扩展维度，不能以部分入口额度承诺总成本或后台安全持续执行。

第六轮新增独立只读模型观察，按真实 Agent 生命周期区分宿主可重用编号；每次尝试取最后 usage 快照，失败/放弃已知用量不丢，无样本、未结束与未归因另列。它不替代第五轮准入计数，不重算额度，不推算价格。后续仍需可靠持久会话对账、完整模型/辅助调用覆盖与真实宿主验证；自动接管、未知副作用核对和知识采用反馈仍开放。

第七轮补成员创建一条纵向恢复链：预留普通子会话身份、唯一意图先落线，后续阶段与部分提交确认凭据可重建查询；已有意图不因换人、改参数或重启重新签发。坏账不当无记录，已发生业务不因后阶段记账错而盲补偿。此项没有完成其他宏动作恢复、宿主自动对账、掉电原子持久或自动接管，后续扩展仍需各副作用的可查询提交/安全停点事实。

## 用什么决定继续扩展

第八轮让知识采用成为可选交卷声明，提供来源观察和治理反馈入口。历史无声明保持未知；负反馈是纠错线索，采纳事实不认证知识语义，不用频次自动排行。后续仍需结构化适用条件、可定位复验与纠错处理记录，以及真实任务收益对照；当前没有采用效果因果验证、完整知识质量分或自动维护循环。

第九轮增加可选作者适用说明与显式复验期限。时间到点后默认不再建议，原文仍可在既有读域显式核对，不由时钟把知识判错，也不自动更新旧期限。接口尚未记录一次独立复验的实际证据与处理结论；新说明仍是作者声明，不能据此宣称完成知识质量闭环。

第十轮复用失效、降权和替代动作，可选明确引用某次交卷负反馈，治理读面核对实际关联。旧无引用动作不猜关联，不因后来返工丢弃旧反馈；不可读或坏账保持未知。没有新增强制交卷字段、任务、审批层级或后台维护。后续仍需实际复验的结构化证据、纠错成功核验与真实收益对照，处置计数不能代替这些结果。

第十一轮收敛治理知识查询内部的重复读取与前缀投影，并补齐结束时的真实身份、读域和原文变化检查。减少重复工作不能靠缓存旧许可；查询变化时明确重新读取，来源故障不抹原声明。仍需实际大账本与跨进程压力验证，当前优化不等于持久索引、完整性能治理或跨账本事务。

沿用[效用验证方案](design/产品方向与效用验证-2026-10-20.md)：质量底线先满足，再比较耗时、工具调用、实际可取得的用量、用户介入及恢复成本。直接执行、协作和记忆复用分别比较，保留失败与未知样本。

误拦截必须有当时合法资格与规则判断错误的依据；配置缺失、后补授权和真实越界另列。拦截多只触发诊断，不能自动放权。用户处理时间没有实际来源时不报告节省。

专业岗位围绕真实任务有界试点，验证术业专攻与上下文选择的效果；暂停扩展无任务依据的岗位、治理层级、审批档位和常驻轮询。只有实际质量与成本证明需要，才扩展机制。无真实收益的新流程优先简化，真实权限和证据边界继续成立。
