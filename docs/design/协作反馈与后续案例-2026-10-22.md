# 协作反馈与后续案例

本轮接续[Lead连续性](Lead连续性与更正-2026-10-22.md)和[需求理解](需求理解与工作上下文-2026-10-22.md)，为“当时怎么做、用户怎样反馈、准备如何调整、后来发生什么”保留可核对记录。复用私有偏好账本、已有替代与停用动作及自动装配，不增加必填流程、审批层级、后台任务或成长评分。

## 记录合同

`memory_write 类=偏好`且`连续性.类别=协作教训`时，可选附`协作反馈`。工具使用对象，命令还可用JSON字符串；其他类别、错误动作、坏字符串、null和自报认证字段拒绝。普通无复盘教训保持兼容，不补猜测或迁移本机私人记录。

| 字段 | 含义与范围 |
|---|---|
| 基线 | 项目、目标及历史修订引用，说明问题发生在哪个案例 |
| 反馈 | 最多1000字符，记录者引用或转述的反馈 |
| 来源 | 用户转述 / 模型观察 / 未知，均为作者声明，不认证真实对话 |
| 原做法 | 最多1000字符，当时采取的做法声明 |
| 调整做法 | 最多1000字符，准备在适用情境中采用的改法 |
| 适用条件 | 1至6项，每项最多240字符，不将一次纠正推广到全部任务 |
| 后续案例 | 可选，最多6项；缺省为空，表示尚无后续记录 |

每条后续案例含`情境:{项目,目标,修订}`、`采用说明`（500字符）、`观察`（1000字符）、`结果声明`、`来源`和`依据`（500字符）。结果声明固定为改善 / 无改善 / 变差 / 未知，来源同上。未知保留为未知，不因未收到反馈就补成改善或无改善。

同一条复盘不接受重复项目、目标和修订，避免重复计数。同目标案例只允许引用晚于基线的修订，表示同案例迭代；更换目标也不自动证明案例独立、难度相当或结果具有因果关系。

## 机械核对与声明边界

审批准备及真实记忆写入前，沿原目标治理读权检查每个引用：目标必须在所指项目存在，修订必须是正整数且不超过真实当前修订。原目标账本保证修订连续，因此对应已存在的历史版本。不可读、缺失或未来修订不会生成有效复盘；非法引用在制造待审批前拒绝。

检查证明引用存在且当时可读，不证明转述准确、调整做法实际执行、后续结果真实或改善由该做法造成。程序不以目标完成、任务采纳、模型自评、表扬次数或记录数量认证成长；没有可信对话认证、额外理解模型或权重训练。历史引用不提供当前执行资格，跨项目仍逐项经过原读权限。

已完成或取消的目标仍可作为历史来源，写反馈不恢复目标，不改旧采纳证据、冻结判据或权限。当前需求解释有误时，Lead另用`goal_progress`修正；复盘不自动改写正式目标。两项动作分别提交，不承诺跨账本事务。

## 后续采用与更正

Lead形成可复用做法时写协作教训；后续确有采用与观察时，用`memory_lifecycle op=overturn`替代该教训，显式提供完整复盘及更新后的案例窗口。选择记录什么、观察结果和实际采用仍需模型判断，不逐条消息自动提取。

替代正文并省略`协作反馈`时，新条目不继承旧复盘，防止旧效果声明默认为新做法背书。连续性声明仍按原合同继承；原条目及复盘留在历史中，旧条目退出自动召回。新条目和旧状态仍同锁追加。

`invalidate`或`demote`使教训退出自动装配，`purge`继续沿原隐私删除合同处理。教训在`来源引用`中明确引用了被撤回的记忆时，既有传递阻断继续生效；本轮历史目标引用只描述案例，不将目标终态误判为教训失效。没有写明的语义依赖不能机械追踪。

## 自动装配与效果读数

沿`mind:lead-continuity`带入最近有效教训及`协作反馈摘要`：原做法、调整做法、适用条件、基线引用、已记录案例数、四类结果声明计数与最近一条案例。文本和列表省略明确标记，完整复盘用`memory_query id=... 返回模式=全文`核对。原每类至多3条、资料帧JSON至多6500字符的预算继续执行；专业成员不接收私人反馈。

计数只针对该条最多6个已记录案例；不同版本和不同教训可能重复引用同一案例，不能相加当作组织整体样本量。零条案例表示暂无后续记录，不表示效果为零；窗口之外的原记录可通过替代历史核对，不能只挑近期成功案例计算改善率。材料进入上下文不证明实际采用。

坏已存复盘不伪装为没有反馈：自动装配排除该条，显式摘要标为说明不可判，原全文保留供恢复。用户要求、真实身份、连续性来源撤回与当前策略检查继续生效，失败不沿用旧提示段。

## 验证与剩余工作

`test/collaboration-feedback-2026-10-22.test.js`覆盖真实记忆、目标、已完成交付、审批、工具/命令及新Lead装配；验证跨会话带入、替代停用、四类结果保留、引用真实性、成员隔离、预算、旧数据兼容和坏声明。测试使用隔离案例，没有调用模型或证明真实行为改善。

下一阶段需要真实模糊需求、模型选人和交付整合，以及后续独立案例中的采用、重复纠正、返工、质量和成本证据。可信来源、主动维护、语义相关召回、统一效果评估和真实客户端验收仍分别验证，不用现有结构字段宣布成长闭环完成。
