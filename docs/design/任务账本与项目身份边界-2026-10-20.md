# 任务账本与项目身份边界

引入日期：2026-10-20。当前代码已合入主线并同步本机源码，实机验收范围见[当前状态](../STATUS.md)。本文记录任务权威读取和项目寻址的工程边界；v2 的派发、交卷、复核、采纳和结账流程继续使用原任务事件流。

## 任务真源不能按剩余完好行授权

`src/task-ledger.js` 是任务账本严格读取的唯一入口。异步 `readTaskLedger` 与宿主同步工具闸使用的 `readTaskLedgerSync` 共用 `parseTaskLedger`。文件不存在回空数组；文件存在但有坏 JSON、不可识别的事件、缺少任务 id 或末尾缺少换行时，抛出 `TASK_LEDGER_INVALID`，带出文件与行号，不跳行、不修写原件。

UTF-8 BOM、CRLF 和空行仍兼容。未识别的新事件类型不能由旧引擎忽略：需要先更新引擎的事件合同，再读取该版本账本。历史事件仍在识别清单中。

严格读取用于任务读面及锁内写前复检、注册表生命周期重建、记忆来源任务查验、审计更正授权依据查验，以及普通成员和复核员的同步文件工具授权。冻结实验在自身健康检查之后也通过任务服务读取。注册表不再把读失败当作“该项目没有账本”。

任务解析缓存逐次读取真实原文，仅在原文完全相同时复用解析结果，并向调用者返回独立数据。恢复 mtime、保持文件尺寸或修改上次 `events()` 的返回值，均不能保留已失效的授权投影。成本是每次权威读取仍有整文件 I/O；本次没有引入新的权威状态副本。

### 损坏后的恢复步骤

1. 停止该部署相关任务写入，保留原始账本、审计、备份和故障读数。不要删除坏行后把剩余事件当成完整历史。
2. 根据异常的文件与行号，对照原始备份、已确认交付记录及审计核对缺失/损坏事件。审计链通过只能说明审计自身的检查结果，不能证明任务账本完整。
3. 恢复经核对的完整任务账本，保持事件原顺序及末尾换行。无法确定原事件时，继续保持拒绝；本次不提供自动猜测、自动补事件或恢复后自动采纳。
4. 重新读取任务、重建注册表投影，核对派发冻结、绑定、交卷和采纳读数，再恢复业务。审计更正仍使用原有受控入口，不改写原审计历史。

本次检测的是文件格式和可识别事件形状，不是密码学完整性证明。删除一条完整事件、合法 JSON 内的语义篡改、整份账本回滚及有效事件重排，仍需后续完整性锚与恢复协议；不能因严格读取通过就声称这些情况已经被排除。

## 项目身份不能由目录尾名决定

`src/project-identity.js` 按完整规范工作路径生成默认项目键：`p-<目录显示名>-<SHA-256前24位>`。存在的目录先 realpath；Windows 折大小写，junction、路径大小写和 `..` 别名解析到同一真实目录。同尾名的不同目录生成不同键。

内核的模型入口、命令、调度策略、成员维护宿主项目事实、咨询工具闸及复核读根使用同一个项目解析器。优先取宿主 `workingDirectory.get(session)` 已提交目录，服务取不到时才读会话头；没有目录时使用部署默认项目。提供了非绝对目录会拒绝，不退回 basename。

动作层接收的会话项目始终保留真实目录解析结果，显式 `args.project` 只表示动作的目标项目。成员不能靠显式参数同时覆盖会话项目和目标项目；Lead 的跨项目知识写入继续需要原规则要求的依据。

### 历史项目的显式认领

可信部署配置新增 `projectBindings`，只接受 `{path, project}` 数组，模型动作不能修改：

```json
{
  "projectBindings": [
    { "path": "C:/work/company-a/repo", "project": "repo" }
  ]
}
```

这表示旧 `repo` 账本明确属于给定真实目录。目录和项目键必须一一对应；不同真实目录不能被重复绑定到同一个项目键。若未配置绑定，且发现同 basename 的旧任务、总线或记忆目录，返回 `PROJECT_LEGACY_UNBOUND`，停止把该工作目录用于组织操作，不自动认领历史，也不静默呈现为新空项目。

确认旧账属于 company-a 后，company-b 的同名目录可使用自身派生的新键；它不会读取 company-a 的旧账。若旧 basename 账本本来就混有多个目录的数据，需要先人工核对并决定历史归属；新增绑定不能自动拆分已混合的历史。

迁移现有部署时，应先盘点旧项目键与真实目录，一一加入可信配置，并同步核对 `delegation.projects` 等按项目键授权的部署设置；再重载内核并核验当前项目归属。配置错误导致内核降级，不以继续运行补偿未知归属。本次不自动修改现役配置，不移动账本、不迁移历史任务、不重新签复核票。

目录移动或改名之前，可把原项目键显式绑定到新路径以保留身份；未给绑定时，新路径默认是新项目。不同 worktree 默认也有不同项目身份；明确的跨 worktree 项目关联、可携带项目 UUID 和多路径同时绑定未在本次实现。
