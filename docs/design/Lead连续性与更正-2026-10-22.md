# Lead 连续性与更正

本轮实现[Lead与专业智能体](Lead与专业智能体-2026-10-22.md)的第二个纵向切片：已记录的人格、用户偏好与协作教训，能在当前真实Lead的系统上下文中自动重建。持久化和装配已有实现；主动识别、提炼与实际行为改善分别验证，不把资料传入模型算成已经采用。

协作教训已补可选[协作反馈与后续案例](协作反馈与后续案例-2026-10-22.md)，在原预算内自动带入原做法、调整做法、适用条件及后续结果声明摘要；目标历史引用会核对，声明不认证反馈或成长。复盘替代时需显式提供，不默认为新正文继承旧效果。

## 归属与声明

复用部署私有的「偏好」账本及已有写入、替代、失效、删除流程，不另建一份人格真源，不迁移旧DSHOME或本机私有资料。旧偏好没有声明时仍可显式查询，不自动猜其类别和范围。

`memory_write`使用`类=偏好`，在必填正文、具体来源之外附`连续性`对象。工具支持结构对象，命令支持JSON对象或JSON字符串；坏串、空值和未知字段拒绝。仅Lead与主权者可写入和处置这些条目，仍执行原身份、策略、介入度及审批规则。

| 字段 | 合同 |
|---|---|
| 类别 | 用户偏好 / 人格 / 协作教训 |
| 主题 | 1至80字符的可读主题；不是自动合并键 |
| 依据 | 明确表达 / 推断 / 自省；用户偏好不接受自省 |
| 范围 | 部署 / 项目；项目范围必须带实际项目键 |

这些字段均为记录者声明。`明确表达`不能认证对话来源，也不证明用户曾授权某项操作；Lead不得把自己的建议写成用户要求。来源应能说明哪次表达、观察、纠正或实际结果。推断保持候选性质，不能当成永久要求；自省不等同于事实认证。

人格作为可更正的长期协作资料，不改写已钉岗位卡的身份核心、宪章、授权或审批。跨会话使用当前会话的真实身份和凭证，不复活旧实例或移交旧权限。

## 自动装配

内核沿现有`system-prompt/assemble`监听追加`mind:lead-continuity`。主体来自真实会话，核对在岗Lead、就绪岗位卡和版本；每次读取当前账本，不缓存旧许可或旧提示段。普通专业成员没有这个段，显式查询也不能读取带连续性声明的私人条目；共享任务只由Lead提取必要约束。

部署范围可在本部署不同项目与新会话使用；项目范围只自动进入同项目。分类及范围在分页前过滤，避免其他类别或项目的较新记录挤占正确候选。人格与用户偏好先优先明确表达，再在同档按账本顺序取最近记录。协作教训优先按[本轮已接纳用户来源文本](已接纳表达与教训选材-2026-10-22.md)词面检索；无可用表达时按[会话目标](Lead会话目标与相关教训-2026-10-22.md)，两种词面查询零命中均不补近期项；两种线索都无时沿用原浏览规则。每类最多3条，共最多9条，每条摘要最多160字符，资料帧JSON最多6500个UTF-16代码单元。正文及完整来源按id经`memory_query`核对。

当前已有本轮已接纳表达或目标线索下的教训词面检索，首步新输入仍有接纳时序限制，尚无可信当前对话意图提供的语义相关性排序。明确表达很多时也可能省略较旧偏好；未召回不能证明不存在。帧保留id、声明、项目、选用线索、每类数据版本及截断标志，不把遗漏算作已知偏好失效。

有资料进入模型前复核查询版本，再核对真实身份与当前读权；宿主会话、项目、身份或插件生命周期变化时丢弃旧帧。读取失败或空账移除旧段，保持宿主对话可继续；日志仅报错误类型，不输出私人正文。查询有来源引用时需核对来源账本，尚未完成大账本性能验证，也不承诺跨账本原子快照。

## 更正、停止使用与隐私

| 用户意图 | 现有动作及效果 |
|---|---|
| 查看与核对 | `memory_query 类=偏好`或按id取全文；原失效记录需显式`含失效=true` |
| 更正已有认识 | `memory_lifecycle op=overturn`指向原id，同时追加替代条目和旧条目状态；默认继承连续性声明，必要时显式提供新声明与纠正理由 |
| 停止使用 | `invalidate`使原条目退出默认召回；`demote`也使连续性资料退出自动装配，但显式查询仍沿用原“降权为冷”的语义 |
| 删除私人内容 | 沿用原`purge`敏感声明或主权者要求、审计与下游隔离合同；不增加新的物理删除资格 |

当前用户要求优先于旧资料。语义上冲突的记录不凭主题或时间自动合并；纠正应明确指向旧id。新写一条不会自动撤回其他记录，模型仍需识别冲突并使用已有替代动作。摘要或教训应在`来源引用`中关联所据记忆：来源失效、被替代、降权、隔离或删除后，引用它的连续性资料经传递闭包退出自动装配。`派生自`描述替代事实，不能把合法替代品因原文被替代而一并否掉。没有来源引用的隐含依赖无法机械追踪。

自动上下文要求保留当前请求优先、独立判断、具体来源与候选性质，并提示需要细节时读全文；机器并未验证模型实际遵守。暂未提供专用人格编辑界面、历史对话自动提取、用户表达认证或后台自我训练。

## 验证与后续

`test/lead-continuity-2026-10-22.test.js`使用真实领域服务、工具、命令和内核监听，覆盖新实例重建、分类和项目、明确表达优先、更正和多级来源撤回、隐私边界、预算、审批冻结及读取期间变化。已有专业上下文回归继续保留。

这验证了代码路径和机械接线；本机源码部署、实际宿主重载、真实用户验收和后续独立案例中的质量改善分别记录。下一步沿模糊需求的可修正理解、专业分配与整体结果核对推进，后续观察是否减少重复纠正和返工，不用记录数量或模型自评报告成长百分比。
