# 需求理解与当前工作上下文

本轮沿[Lead与专业智能体](Lead与专业智能体-2026-10-22.md)补第三个纵向切片：可修正的需求解释、Lead当前工作材料和专业成员任务简报。复用已有目标、任务、岗位与系统装配，不增加必填阶段、审批层级或后台调度。

## 理解是解释，不是用户意图认证

用户可先表达问题或不满意之处，Lead在已有授权内调查、给出小样例并检验假设，只把会显著改变目标、范围或关键取舍的问题交给用户。不要求用户先写完整任务书；资料记录也不构成新的操作授权。

`goal_create`和`goal_progress`可选附`需求理解`。工具接结构对象，命令还支持JSON字符串。省略时兼容旧请求；没有记录就保持未知，不从普通正文猜字段，不追补旧历史。

| 字段 | 含义与范围 |
|---|---|
| 原始表达 | 必填，1至1000字符，记录者对用户表达的引用或转述，不认证对话来源 |
| 当前理解 | 必填，1至1000字符，Lead可修正的结果解释，不替代正式期望结果 |
| 来源 | 必填，1至500字符，说明哪次表达、观察或纠正支持本次解释 |
| 待验证 | 可选，最多6项，每项240字符，仍需调查或尝试的假设 |
| 关键问题 | 可选，最多3项，每项240字符；不是自动要求用户逐项确认的门禁 |
| 分工 | 可选，最多6项岗位、工作与理由建议；分别最多80、500、240字符，不创建任务或授予权限 |

Lead根据当前情境选择自己处理、咨询或委派；岗位目录只是索引，不认证某岗位胜任某件工作。模型仍需核对真实岗位与能力、传递必要目标和约束，并走现有任务与受管委派入口。程序没有关键词路由、自动建岗或自动生成执行实例。

## 持久化与修正

声明随现有目标事件追加，审批准备、冻结与执行共用同一领域计划和输入摘要。`goal_progress`提供声明时整体替换当前解释；未提供时保留当前解释。原事件保留旧内容，新会话读取当前版本，不续用旧提示段。

解释修改不改变正式期望结果、完成依据、约束、禁止工具或任务冻结判据。旧目标修订冲突、暂停、取消、已完成、真实主体和原权限规则继续适用。`goal_revise`改变目标规格时，旧解释退出当前视图，需根据新规格重新记录，避免新约束配旧解释；历史事件仍可核对。

未知字段、伪认证、null、坏JSON、超长声明和借其他动作附带声明均拒绝。原账本没有可选声明仍可读，已有声明不可判时按既有坏目标账本规则报告故障，不静默跳过生成旧理解。已写入该新可选字段的目标账本需要支持本合同的代码读取；旧版回退不自动降级或重写账本。

## 自动装配

内核在现有`system-prompt/assemble`中维护`mind:current-work`。和专业知识、Lead连续性资料各自按真实读权装配；不改写已钉身份规程。

| 对象 | 默认材料 |
|---|---|
| Lead | 当前项目最近更新的最多3个未收尾目标（进行中、等待或暂停）、有界需求解释、下一步、完成依据摘要、关联任务总数及合法采纳数、每目标最多2条任务简报；最多12个可咨询岗位id |
| 普通专业成员 | 当前真实凭证绑定的最多4个已派发或执行中任务的描述、判据、依赖与状态摘要 |
| 无有效活动绑定或会审成员 | 不猜工作内容；会审仍使用原独立资料通道 |

成员资料不包含Lead的原始用户表达、私人解释、分工建议、其他专业任务或整个目标账本。专业所需目标与约束由Lead提炼进正式任务和任务书；系统不自行把所有用户材料下发。目标的原治理读面也未向成员开放。

资料帧JSON最多9000个UTF-16代码单元，超出时省略整个条目并标记；文本摘要及条目列表的省略另有标志。完整约束、依据和任务详情仍用`goal_query`或`task_criteria`核对。Lead有岗位目录但暂无目标时仍可得到目录与工作原则；不会自动创建一个目标。

这是本项目的近期工作列表，不保证已识别当前会话焦点，也没有基于对话含义的排序。目标在过滤终态后再限量，避免较新的已取消目标挤掉未完成工作。新会话、目标修正与任务结束后重新构建资料，当前用户要求优先。

进入模型前再次核对目标、交付与岗位来源摘要，并核对当前身份、凭证、任务绑定与读域。宿主会话、项目或插件生命周期改变时丢弃旧帧。读失败移除旧段并仅记录错误类型，保持对话继续；不把旧资料伪装为当前事实。不承诺跨账本原子快照或大规模账本性能。

## 从任务通过到整体效果

复用原`goal_complete`的逐条完成核对与真实任务证据合同，不新增一个“机器理解已正确”的状态。任务关联和合法采纳数只描述交付进展，不宣称整体问题已解决。Lead仍需检查遗漏、专业冲突及产物组合是否符合当前完成依据，按现有目标修订或合法承接处理新的需求。

`完成核对`必须精确覆盖当前每条完成依据，引用本目标的合法采纳任务，并绑定原采纳的产物清单；缺项、跨目标或变化证据继续拒绝。程序核对引用与事实，执行者判断语义；完成记录明确不表示机器已证明目标含义。

## 验证与剩余工作

`test/demand-work-context-2026-10-22.test.js`使用真实Org、目标、任务、审批、工具、命令与系统装配，覆盖两个专业的必要材料隔离、纠正替换、旧请求兼容、坏事件、权限和异步变化、预算及整体证据核对。测试没有调用模型，不据此报告理解准确率、路由质量或用户满意度提升。

后续需要真实用户的模糊需求、调查或样例、模型选择的专业与理由、交付整合及后续反馈；再用独立案例观察重复纠正、错误分配、返工和质量。可信对话来源、焦点识别、语义相关召回和反馈到实际行为改善仍开放。源码同步、实际宿主重载和人工验收分别保留证据。
