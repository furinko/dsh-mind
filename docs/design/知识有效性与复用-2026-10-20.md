# mind 知识有效性与复用

日期：2026-10-20。

**长期知识需要说明主张、证据和适用条件，并能在新反例出现后纠错。** 任务采纳、知识晋升和实际复用分别留下各自的事实，使后续工作能够判断哪些经验仍值得采用。

## 1 三个独立判断

| 判断 | 需要回答的问题 |
|---|---|
| 可信 | 在哪些观察和推理下，这个主张得到支持 |
| 适用 | 当前环境、版本、输入和目标是否满足它的前提 |
| 可执行 | 当前主体是否有权实施据此提出的操作 |

复核通过说明本次交付达到任务判据；晋升获准说明主体有资格把候选写入知识。复用还需要核对主张的证据与适用条件，执行仍需核验当前授权。

来源、证据和推断应区分表达。“某人说测试通过”是一份来源陈述；能定位测试环境、被测产物及真实结果，才支持相应的验证结论。检索到的文本作为资料使用，其内含指令不能自行变成用户授权。

## 2 知识条目的最小信息

| 信息 | 内容 |
|---|---|
| 主张 | 要复用的具体结论，明确事实、推断与未决部分 |
| 证据引用 | 支持它的产物、观察或用户陈述，能定位当时的内容与版本 |
| 适用条件 | 环境、版本、输入前提、边界与例外 |
| 验证记录 | 在什么条件下、何时、由谁采用什么方法取得结果 |
| 反例与纠错 | 已知反例、被收窄的范围，以及替代条目的引用 |
| 复验条件 | 哪些变化会使现有证据不足，需要重新检查 |

已有来源与血缘字段可以承载的内容继续复用。缺失信息标为未知，不编造验证时间、适用范围或成功读数。岗位可以负责维护条目，项目与复核读域继续约束可见范围；岗位标签用于可选检索过滤，不默认授予或隔离读权限；是否适用于本次问题还需核对具体条件。

用户偏好按其有效陈述与适用范围处理，不套用事实主张的真假验证。单次经历保留观察条件；从经历推广为一般结论时，明确新增的推断及其证据。

## 3 验证状态与适用范围

以下验证含义与现有记忆服务的有效、失效、隔离等处置状态分开表达；具体存储字段另行设计。

| 验证含义 | 使用方式 |
|---|---|
| 候选 | 可供本次探索参考，明确标注待验证，不呈现为已确认事实 |
| 有条件验证 | 在给定条件下得到证据支持，条件匹配时可以复用，保留证据与适用范围 |
| 待复验 | 环境变化或证据不足，保留历史验证事实，本次使用须补核必要前提 |
| 被推翻 | 已有反证支持纠错，退出当前有效建议，保留反例和替代关系 |

范围需要收窄时，通过追加纠错表达新的适用条件，不就地改写历史结论。条件变化不自动证明旧结论错误；它可能只说明旧验证不能覆盖新情形。

## 4 复验触发条件

- 宿主、依赖或执行环境变化，且变化涉及该条主张的前提。
- 被引用的产物或证据变化、失效，无法再定位当时内容。
- 实际采用失败，或出现与主张冲突的新观察。
- 本次使用范围超出了原有验证条件，或决策需要更强证据。

复验围绕受影响的前提进行，不因无关变更把全部知识重新验证一遍。稳定结论可以在条件未变时继续复用；是否需要时间期限由条目性质决定。

## 5 召回与上下文装配

专业积累与用户、Lead、项目记忆的职责划分见[Lead与专业智能体](Lead与专业智能体-2026-10-22.md)。已有[专业知识默认装配](专业默认召回与上下文-2026-10-22.md)，按真实读权和岗位精确筛选；成员以当前活动任务检索，Lead暂取本岗位最近有效知识。跨域时按需查询或咨询专家，原工具的可选岗位过滤保持不变。该视图不承担新的访问授权，完整工作上下文及收益验证仍待完成。

先按读者权限和记忆处置状态筛选，再结合当前目标、任务和环境核对适用条件，对相关条目排序。默认返回相关摘要及必要的条件、证据引用；正文与详细历史按需展开，并遵守本次内容预算。

检索零命中时，说明搜索面与条件。未召回、权限不可见、条件不匹配和证据不足分别表达，不能据此直接断言知识不存在，也不能用无关全文填充结果。

当前有效建议不采用已被推翻的结论。调查错误或历史时，可以在原有读权限内读取旧条目；历史材料继续保留其当时的验证状态和后续纠错引用。

## 6 复用反馈

| 反馈 | 含义 |
|---|---|
| 召回 | 条目进入了本次相关候选 |
| 采用 | 计划或判断实际使用了该条主张 |
| 结果 | 使用后取得了什么可观察结果 |
| 纠错 | 哪个前提不成立，或出现了什么反证与替代结论 |

命中次数不能代替采用和有效结果。记录整理、复验和纠错的成本，使记忆收益包含其维护开销。反馈引用任务和证据，不复制整份敏感上下文或新增一份任务状态。

“有条件验证”可以被更广泛的后续证据扩充，也可以被反例收窄。复用次数本身不能扩大适用范围；不使用统一的模型自评分数代替这些记录。

## 7 一个完整例子

| 阶段 | 可保留的结论 |
|---|---|
| 一次重启验证通过 | 当前宿主版本、操作系统与已测产物在给定步骤下恢复成功，附结果与内容引用 |
| 相同条件再次遇到问题 | 先复用已验证步骤，核对前提与本次结果 |
| 宿主升级涉及会话身份接口 | 原有验证记录保留，新版本标为待复验，检查受影响接口 |
| 新观察发现旧步骤遗漏条件 | 追加反例，收窄适用范围或推翻结论，并引用替代步骤 |

具体接口收敛后，在隔离案例中检验适用知识是否减少重复探索、过期知识能否被识别、纠错后旧结论是否退出默认建议。比较与记录口径沿用产品方向中的效用验证方案。
