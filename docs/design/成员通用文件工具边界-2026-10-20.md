# 成员通用文件工具边界

日期：2026-10-20。工程实现说明；不修改 v2 的主权者全局免审、Lead 手动派复核、不自授与不越授规则。

## 可信上限与派发范围

`dsh-mind-kernel` 的部署配置新增 `memberFileAccess`。它只从宿主装配参数读取，mind 工具和任务参数不能修改。缺省等于空集；坏配置使内核降级为只读自述。这里定义的是 Lead 可授给成员的通用文件读写上限，不替代宿主自身的权限，也不修改组织对象的标签权限。

```json
{
  "memberFileAccess": {
    "read": ["C:/work/project/src", "C:/work/project/test"],
    "write": ["C:/work/project/src"]
  }
}
```

路径必须绝对、存在且能解析。组织私有区和出厂区原始文件，以及能递归覆盖它们的父目录，不能成为可授根。不要把整个用户目录作为可授根。上限撤回或根路径失效后，旧任务的文件权限也失效。

Lead 通过 `task_dispatch` 或 `member_spawn` 的 `工具文件范围` 明确选择本任务的子集。读与写分别校验，写根不自动获得读权限。

```json
{
  "action": "task_dispatch",
  "id": "task-example",
  "工具文件范围": {
    "读": ["C:/work/project/src"],
    "写": ["C:/work/project/src"]
  }
}
```

派发事件冻结规范路径、授予者和版本；后续绑定实例继承本节点已经冻结的范围，不能新增范围。`member_spawn` 在创建宿主执行体之前先验证可授性，派发时再核验。要扩大范围需新建任务并重新派发。原始历史任务没有该字段时不会自动取得文件权限。

## 实际工具入口

普通成员使用通用文件工具时，同步 guard 每次从真实身份档案与严格任务账本求权限。必须在册在岗、钉卡就绪、存在可信且在岗的派发 Lead，并且本人实际绑定一条已派发或执行中的任务。新绑定由服务钉住岗位、实例代、卡内容摘要与宿主代次，逐次与当前身份核对；同 id 换岗、新代或新卡不能继承旧文件域。同岗、同代、同卡与同宿主代次的正规 seal→restore 保留原凭证。旧绑定没有这份凭证时不自动补证。岗位名匹配、当前工作目录、任务描述和成员提交的产物路径都不能授予通用文件权限。

文件域只是必要条件。`PolicyEngine.decideCurrentSync` 逐次同步读取成功加载时实际使用的全部授权原文，完全一致才复用现有策略判定本体。本人、父 Lead 与任务撤回、实时失联、规则收紧、介入度和策略故障继续有效；任一原文改变或重载未完成，旧内存权限立即失效，恢复配置并完成策略重载后才能重新使用。通用工具不消费组织动作的逐请求放行。工具总范围也逐次重读，不等待五秒节拍。交付物捕获同样核对当前资格，不能借提交哈希绕过撤权。

闭名单只包含 `read`、`read_image`、`glob`、`grep`、`write`、`edit`。每次解析真实 `exec.arguments.file_path/path`；工作目录只用于解析相对路径。新文件会解析最近存在的祖先，避免 junction 下的不存在路径绕过。普通文件的 `nlink` 必须为 1，根内硬链接到私有身份文件或外部普通文件都拒绝；普通目录不按这个文件规则判断。搜索目录含符号链接、硬链接普通文件或超过 10000 个条目时拒绝，需缩小搜索范围。复核、会审资料读域和交付证据也采用同样的链接约束。

shell、任意执行器、其他插件工具和未知工具不能凭文件根证明安全，因此对普通成员拒绝。成员把所需命令交给 Lead 执行；本轮不引入通用 shell 沙箱。交卷后通用文件读写窗口关闭；返工重新开工后可使用原冻结范围。

`mind`、`mind_guard` 仍由各自策略判定；`skill` 沿用既有规范读取入口。`send_message` 只允许向真实派发 Lead 报告，故障时仍可使用该通道。复核与会审实例继续遵守各自更窄的工具边界。

安全配置初始化前，范围闸已经同步注册。`memberFileAccess`、`projectBindings` 或组织装配失败时，所有原生工具、组织写动作与未知工具均拒绝，只有 `mind status` 自述诊断可用（空 action 仅作同一自述兼容入口），没有无身份的原生工具豁免；初始化未完成时无法确认父归属，所以不开放消息通道。健康启动后才接通真实范围判定。运行中工具配置故障也保留明确的 `mind status` 诊断，人侧恢复走原有命令/设置渠道。

首道范围闸本身注册抛错或宿主缺少 `tools.guard` 时，没有可承重的闸，不能注册诊断工具后正常返回。内核保留 error 日志并抛出 `Fault`（稳定 code `KERNEL_REQUIRED_GUARD_UNAVAILABLE`，保留原 cause），不注册工具、命令或提示词，由宿主装载错误与日志诊断。这只确认 Mind 组件加载失败，不能声称宿主所有原生工具已停止；整机依赖失效时是否停止工具，要由宿主将这项安全依赖设为必需并执行其装载策略。

## 验证与限制

`test/member-tool-files-2026-10-20.test.js` 覆盖无任务、合法绑定、同岗未绑定、默认空上限、越授、自授、上限撤回、交卷关闭窗口、双区 raw 文件、junction 下新目标、链接递归搜索，以及父报告通道。

该机制是宿主工具调用前的范围校验，不能阻止操作系统中其他进程在核验之后新建硬链接、更换链接或改文件；静态多硬链接拒绝不等同于 OS 沙箱隔离。部署者上限只证明 mind 内部的可授边界；宿主未公开的其他权限约束仍由宿主执行，不能宣称 mind 已验证那些外部约束。同步策略资格增加逐次授权原文 I/O；变更后先拒绝到重载完成，是明确的保守选择。运行目录和部署配置本轮没有修改，真实宿主行为需部署时另行验收。
