# mind 连续工作的端到端场景推演

日期：2026-10-20。

本篇依据已确认的[目标模型](目标模型与生命周期-2026-10-20.md)、[知识复用](知识有效性与复用-2026-10-20.md)及[持续执行](持续执行与预算-2026-10-20.md)原则，检查跨会话、目标变更与故障接管的接口要求。以下是设计推演与后续实现判据，不是现有运行态验收结果。

## 1 跨会话续做

### 场景

用户要求修复导出功能，允许在指定开发目录修改与验证，发布和部署不在本次范围内。旧会话已经定位原因，正在执行修复时中断；某次操作是否完成尚未确定。

### 推进过程

| 步骤 | 真源与允许的动作 |
|---|---|
| 旧会话中断 | 保留目标、任务、操作事实和证据引用；缺少回复不等于操作未发生 |
| 新会话接续 | 读取目标、约束、关联任务、关键决定及必要证据，重建工作摘要 |
| 核对执行状态 | 查询未决操作回执与任务状态；旧执行者是否停止必须有可靠依据 |
| 处理未知结果 | 可只读核查或推进其他独立任务；重复副作用须先确认旧操作结果，或经受控幂等恢复 |
| 合法移交 | 记录新执行归属，核对当前身份、授权与剩余预算，保留旧实例署名 |
| 继续验证 | 使用当前产物与证据完成任务验收，再核对目标是否达成 |

### 必须成立的判据

- 新会话能定位下一步与原始证据，不依赖旧会话仍在运行。
- 操作已经提交但回执丢失时，接续不会再次执行同一副作用。
- 新实例不能借旧任务自动继承已撤回或失效的授权。
- 文件变化或旧证据不再对应当前产物时，旧复核票不能支持新成果。
- 没有合法接管接口时，明确等待并报告缺口，不直接修改账本伪造归属。

### 接口缺口

目标与任务的关联需要包含项目身份和来源；任务接管需要可核验的执行归属；操作需要稳定回执与结果查询；摘要需要引用当前真源及其版本。持久格式与恢复顺序应一起设计。

## 2 执行中改变目标

### 场景

原目标是自动导出文件，任务已按此冻结判据。用户随后明确要求改为只显示预览，暂时不要写文件。

### 推进过程

| 步骤 | 真源与允许的动作 |
|---|---|
| 接收新意图 | 保留用户变更来源与旧目标历史，更新当前结果要求及限制 |
| 检查兼容性 | 判断已有任务、运行中操作和成果是否仍满足新约束；未受影响的合法工作可以继续 |
| 限制新增副作用 | 新增写文件不符合当前约束，应停止派发或继续执行该动作 |
| 核对运行中操作 | 已经发出的操作按其实际可取消性处理，保留已发生的副作用，报告无法立即停止的部分 |
| 承接新交付 | 旧任务判据保留，以合法承接或新任务完成预览要求，复用仍适用的成果 |
| 核对完成 | 用当前目标要求验收，旧目标下的通过记录只证明其原来覆盖的结果 |

### 必须成立的判据

- 用户明确改变限制后，旧实例不能凭旧任务继续发起与新限制冲突的动作。
- 已冻结判据不被事后改写，旧执行者也不被补签成新目标的交付者。
- 旧成果与知识保留；是否复用依据新目标与适用条件判断，不整批删除或无条件继承。
- 目标措辞澄清不自动废弃全部任务；只有受影响的范围需要重新处理。
- 扩展目标不会自行扩展权限；已有有效授权继续使用，新增权限按原规则处理。

### 接口缺口

需要可引用的目标修订、任务与目标修订的关联，以及副作用发起前对当前约束的核对。限制变化如何传播到正在运行的执行者、旧结果如何按修订归档，应与安全停点机制一起验证。

## 3 预算耗尽与执行者失联

### 场景

同一目标有两个并行任务。剩余额度不足以支持两者继续执行，其中一个执行者已发出操作但没有返回结果，之后失联。

### 推进过程

| 步骤 | 真源与允许的动作 |
|---|---|
| 争用剩余额度 | 在启动操作前统一核对并占用可用额度，不能让两个执行者同时花同一份预算 |
| 结果未返回 | 保留未决操作及其预算占用；未收到回执不等于未消耗资源 |
| 预算不足 | 停止新增推进，目标进入等待，说明已用额度、未决结果及剩余工作 |
| 用户补充预算 | 追加预算变更，历史消耗与未决占用继续保留，重新判断可推进工作 |
| 处理失联 | 查明旧执行状态，再合法移交；换实例不重置用量，也不直接重做未决副作用 |
| 旧结果迟到 | 核对原操作和执行归属，只结算与采纳一次，补充有效证据或保留冲突事实 |

### 必须成立的判据

- 目标预算包含全部执行者、复核、重试及失败调用，不因拆任务或换实例重新计零。
- 并发操作不能重复使用同一份可用额度，补充预算也不会抹掉已有消耗。
- 迟到回执与重复事件不会重复结算、重复采纳或再启动同一副作用。
- 计量不可用时如实标为未知，不把未知费用计零，也不承诺未被证明的硬上限。
- 自动等待不冒充用户暂停；恢复预算也不恢复已撤回授权。

### 接口缺口

需要目标级预算记录、并发占用与结算、未决操作对账，以及与接管一致的执行归属。具体限额、等待期间如何计时和未知用量如何处理，在接口设计时明确。

## 4 推演得到的接口优先级

| 优先接口 | 承担的职责 |
|---|---|
| 目标修订与任务关联 | 保留当前意图、约束与历史，任务结果能定位它所满足的目标要求 |
| 执行归属与操作回执 | 可确认谁在执行、操作是否发生，支持接管、幂等恢复及迟到结果处理 |
| 预算占用与结算 | 汇总整个目标的用量，处理并发、未决结果及补充预算 |
| 限制传播与安全停点 | 用户变更、撤权、暂停或取消后，阻止冲突的新增操作并处置在途工作 |

这些职责优先复用现有任务事件、实例凭证、审计和证据引用；新增的记录不成为第二套权限主体或任务状态。完成记录需要相应证据，无法确认的结果继续保留未知与等待原因。

后续工程先逐项验证这些接口，再检验完整场景。第一批成员工具、产物票、任务账本和项目隔离修复仍按各自工程证据验收。
