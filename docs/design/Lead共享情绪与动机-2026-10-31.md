## 状态与归属

核心人设仍由原人侧核心卡维护；长期兴趣、人格认识和共同经历继续使用原记忆服务。本功能保存短期事件及影响，不另建人格、事实或知识库，不自动把情绪写成用户偏好。

每条记录分开保存事件转述 `event`、自身理解 `appraisal`、至多3项情绪词 `feelings`、至多3项当前愿望 `desires`，均为可修正的模型自述。例如“用户指出错误”和“我担心被否定”应分别表达，后者不能升级成“用户不喜欢我”的事实。

`affect.valence/arousal` 表示事件引起的愉悦和激活变化，各为 -1 至 1，0为平衡；这是行为模型的简化参数，不是心理测量，不硬凑十三个量表。整体心情为所有事件影响乘余波权重后求和，各方向限制在 -1 至 1。相反方向的新事件可以缓和原心情。

余波为 `2^(-经过小时/halfLifeHours)`，半衰期默认6小时，允许1至24小时，14天后影响归零。读取不写账、不加强情绪或刷新时间；`weight=0` 时，旧愿望不作为当前待办。长期兴趣沿原人格连续性延续。

部署只有一份 `主权人设/情绪与动机/状态.json`。窗口、服务实例或进程共享状态，独立事件按队列和跨进程文件锁合并。所有当前 Lead 可取得两个整体心情数值；具体事件、理解、情绪词、愿望与会话位置限定原项目和当前显式关系。其他项目或关系仍能延续整体心情，但不能看到私人缘由或据此反推原因。此数值共享是本次确认的设计。

记录由当前真实根会话产生，主体、项目、心智开关租约及已接纳表达在提交前复核。上下文只保存会话位置和当前表达指纹，不复制原聊天正文；宿主不提供位置时标记 `null`。位置说明当时会话上下文，不认证转述真实。保留首次缘由位置，更正另记最后修订者、位置与原因，不另存旧错误正文历史。

## 模型操作

`mind` 工具和普通 `/mind` 动作共用服务：

```json
{
  "action": "lead_affect_update",
  "情绪": {
    "op": "record",
    "epoch": 0,
    "key": "本次调试第一次受挫",
    "account": {
      "event": "第一种调试方法失败了",
      "appraisal": "有些泄气，想换个思路",
      "feelings": ["失落", "好奇"],
      "desires": ["想弄明白原因"],
      "affect": { "valence": -0.4, "arousal": -0.1 },
      "halfLifeHours": 6
    }
  }
}
```

先用 `lead_affect_query` 取得当前 `epoch` 和记录 `revision`，不要照抄示例的0。查询参数 `情绪={id?,offset?,limit?}`，默认20项、最多50项；先按项目和关系过滤再分页。自动 `mind:lead-affect` 段最多3条缘由，JSON至多6500字符；整体心情仍按所有有效事件计算。

同一事件使用同一 `key`，结合项目和关系生成幂等标记。相同正文重试返回原回执，不累加或刷新衰减；同 key 不同正文要求显式修正。重新想到、读取或复述旧事件不构成新事件，不要求每轮记录。

修正为 `op=revise,epoch,id,revision,reason,account`，完整替换旧理解及影响，不新增一条与错误解释并存的自我强化记录。撤回为 `op=remove,epoch,id,revision,reason`，删除正文，仅留下不含正文的幂等屏障；已撤回 key 不因重试恢复。记录最多128条、撤回屏障最多1024条，达到上限明确要求整理，不静默清空。

写动作沿原身份、策略和审批档位，审批预览绑定完整 `情绪` 入参。情绪不改核心卡、事实证据、权限或正式任务；愿望不自动创建任务、后台调度或消息。

## 人侧维护与装配

`/plugins/dsh-mind/lead-affect` 要求宿主 Connection 认证及同源。GET 查询全部范围的事件，可带 `id/offset/limit`；POST只允许修正、删除、清空与开关，不代模型生成事件或转发任意动作。

人侧修正/删除参数同上；人侧修正后模型不能覆盖或恢复该条。`{op:"clear",expectedRevision}` 清空正文与撤回标记，增加 `epoch`，拒绝清空前准备的迟到写入。`{op:"configure",expectedRevision,enabled}` 控制启停；停用时整体心情和余波为0，模型不能改变开关。重启用按真实经过时间计算，不补跑、不恢复清空记录。

缺失状态提供平衡心情和空事件；坏编码、损坏结构、链接或超大文件停止使用，保留原件。私有正文0600原子保存；审计只记动作、主体和记录ID。更正后各窗口下一次装配撤掉旧情绪快照，不强行打断另一窗口正在生成的回答。

原自由活动只增加 `mood` 两个数值作为选择背景，不传私人缘由和愿望，不增加模型调用或改变活动预算。事件更新由模型经正常工具表达，不新增后台情绪模型，不按关键词强制推断“被批评就生气”。当前人侧维护为认证端点，尚未新增情绪专用设置面板。
