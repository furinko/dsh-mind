# 记忆目录分层整理

核对日期：2026-10-23。布局映射、项目枚举修复及停机迁移入口已实现；各机器是否已迁移以其部署回执为准。

## 旧布局的问题

`Layout` 把正式记忆范围和新增功能目录放在同一级：

```text
记忆服务/
  跨项目/                    正式知识、经历和偏好账本
  <项目键>/                  项目知识和作答账本
  轮级缓冲/<项目键>/<会话摘要>.json
  项目接续/<项目键>.json
  连续性提炼/<项目键>.json
```

前三类状态的寿命和来源不同。正式账本需要保留来源、撤回和治理历史；轮级缓冲可以按会话清空；项目接续是可重新提炼的派生资料；连续性提炼是自动提炼的处理状态，自动固化当前默认关闭。把这些全部摆在一个层级，会让人工检查、备份、容量统计和清理规则难以判断对象。

旧 `MemoryService.#projectScopes()` 把记忆服务目录中除“跨项目”外的所有子目录当作项目范围，因此功能目录也会被扫描为项目。正式账本读取仍指定四类 `.jsonl` 文件，这不等于把缓冲正文当作正式记忆读入。本版旧布局枚举显式排除三个功能目录；若同名功能目录含正式账本，则拒绝猜测归属。布局2只枚举 `长期记忆/项目`。

本机只读目录盘点见仓外 `audits/mind-startup-collaboration-20261023/evidence/memory-directory-inventory.json`，盘点没有读取记忆正文。空目录可能来自项目初始化，不能据此合并、认领或删除项目。

## 布局2

```text
主权人设/核心人设.md          人工维护，继续独立保护
记忆服务/
  布局.json                  {"version":2}
  长期记忆/
    跨项目/<记忆类>.jsonl
    项目/<项目键>/<记忆类>.jsonl
  工作记忆/
    会话缓冲/<项目键>/<会话摘要>.json
    项目接续/<项目键>.json
  提炼状态/
    连续性/<项目键>.json
```

整理按资料寿命和权威来源分层，项目与会话在各自层内继续隔离。知识、经历、偏好、作答等领域分类保持原语义；核心人设仍由人工维护，不并入模型可写记忆。

## 实施顺序与验收

1. 统一 `Layout` 路径和项目范围枚举。功能目录不得计为项目，正式账本查询、来源核对和容量读数共用这一映射。
2. 明确磁盘布局版本与兼容读写期限，再提供独立迁移入口；不能直接在资源管理器移动后让旧代码继续写原路径。
3. 迁移前备份并验证文件摘要，保留原项目键、账本原字节、条目ID和来源关系。不按目录同名合并项目，也不替历史项目补授权；`projectBindings` 继续逐路径核对。
4. 切换前确认所有写入者已停止或受同一迁移锁约束。迁移成功后只写新布局；旧副本作为可辨认的回退备份，不能被两个版本同时续写。
5. 核对新旧布局查询、项目隔离、撤回来源、单会话清空、项目接续重建、升级回退，以及 Windows 路径别名；运行中的旧客户端必须完整重启后再验收。

## 停机操作合同

无标记的既有目录及新建目录继续使用布局1，不自动搬迁。显式迁移后，所有路径统一经 `Layout` 映射；不双写、不按旧路径兜底。无效版本、未完成事务及布局2混入旧路径时拒绝读写。核心卡路径及保护机制不变。

独立入口不打开 `Org`，也不注册为模型动作：

```sh
node scripts/migrate-memory-layout.mjs --private-root <私有区>
node scripts/migrate-memory-layout.mjs --private-root <私有区> --check-offline --offline
node scripts/migrate-memory-layout.mjs --private-root <私有区> --apply --offline
node scripts/migrate-memory-layout.mjs --private-root <私有区> --recover --offline
node scripts/migrate-memory-layout.mjs --private-root <私有区> --rollback --offline
```

缺省只读预检。`--offline` 是部署者已停止全部写入者的确认，进程检查不能替代这一确认。Windows成功枚举系统进程后检查桌面客户端及身份档案PID；其他系统检查登记PID。查不到可靠事实时拒绝切换。不会强制关闭进程或修改身份档案。

Windows历史PID若被其他应用复用，部署者可另传 `--non-writer-proof <JSON>`：`version:1, processes:[...]`，逐项包含 `pid/executablePath/startedAt/parentPid/parentExecutablePath/parentStartedAt/confirmedNonWriter:true/reason`。父进程已不存在时改用 `parentAbsent:true`，仍保留其PID。必须先人工核对确实不是写入者；每次停机检查重取系统事实，任何路径、时间或父进程变化均拒绝，不能仅按PID忽略。桌面客户端始终拒绝，不能用证据文件豁免。

迁移逐文件复制到同父目录的唯一暂存路径，比较SHA-256与字节数，保留空目录、原项目键、条目ID、来源及BOM/换行。Windows逐项保留并比较DACL、所有者和组；Unix保留模式位并要求所有者及组相同。未知路径、链接、硬链接、特殊文件及等价名称冲突均先拒绝，不自动删除或合并。旧项目接续的 `.invalid-*` 诊断副本也属于需先人工归类的未知路径。

复制完成后写事务清单，切换前再核对停机状态及源摘要，旧目录重命名为 `记忆服务-布局1备份-<id>`，再启用暂存目录。准备完成后或切换中断可运行恢复，运行态在此期间拒绝读写。复制准备尚未写事务就失败时，源目录仍在，未启用的唯一暂存副本留供人工检查；不自动清扫。维护锁不抢占活进程；恢复仅隔离能证明进程已退出的旧锁。

回退必须停机，且新布局清单、旧备份均仍匹配迁移回执。布局2一旦产生新写入就拒绝回退覆盖。回退保留布局2副本；不能直接切回不识别布局2的旧源码。权限中额外Unix ACL、扩展属性及系统断电持久性未在本轮验证范围内。

本版专项覆盖旧/新布局查询、空项目、项目隔离、轮缓冲及接续读回、并发变化拒绝、准备和切换中断、回退中断、回退拒绝覆盖新数据、权限、无效版本及活跃PID拒绝。部署与私人数据迁移分别记录在仓外 `audits/mind-memory-layout-20261023`，不复用此前开机探针及委派指引的部署回执。
