# 模型用量只读观察

日期：2026-10-21。本文描述 `dsh-mind-dev` 的开发候选，尚未部署到运行目录。验证依据是已安装 SDK 的静态合同和临时组织中的隔离测试；未证明桌面宿主已装载该观察器，未通过运行宿主发起模型请求，也未取得费用账单。

## 入口与读数

模型与命令共用 `usage_query`。省略 `id` 时查看当前项目已记录的尝试；给出 `id` 时只选择观察开始就归属于该同项目目标的尝试。目标必须真实存在。治理读面仅开放给当前真实就绪的 Lead 或主权者，普通成员与复核员不能通过已知目标编号扩大读域。

```text
/mind usage_query 条数=20 偏移=0
/mind usage_query id=<目标id> 条数=20 偏移=0
```

返回包装为 `{用量: ...}`，包含所选范围的全量汇总及有界尝试页，默认每页 20 条、最大 50 条。分页只裁尝试页，不裁汇总。读取不会创建开始、样本或结束事实。

以下字段必须一起理解：

| 字段 | 含义 |
|---|---|
| `完整: false` | 只是已接线观察窗口，不承诺目标、项目或账户的完整模型用量 |
| `token: null`、`费用: null` | 完整 token 总量与金额未知，不能当作零 |
| `汇总.已报告token` | 每次尝试最后一个已观测 SDK usage 快照中，各已报告字段分别求和 |
| `汇总.字段覆盖` | 每个字段已知及缺失的尝试数量；没有任何已知值的字段为 null |
| `尝试页` | 已记录尝试的生命周期、归因、配置路由、最后 usage 与结束信息 |

`inputTokens`、`outputTokens`、`totalTokens`、缓存与推理字段分别保留来源口径。不能把 `totalTokens` 再与分项相加，也不能把 reasoning 再计入 output。SDK 缺少 total 时不以 input 与 output 补造总量。失败尝试、`assistant/attempt` 和 abandoned 尝试已经报告的字段同样纳入汇总，缺失样本保持未知。

`budget_query` 继续只统计受管准入尝试，`token` 与费用仍为 null。观察器不扣款、不调整上限、不返还额度、不完成目标，也不以估算数阻止业务。

## 来源与归因

观察器订阅当前安装合同中的 `agent/assistant-stream`，以真实 Agent 对象、生命周期及 attemptId 区分尝试。重复 usage 是快照替换，不是新增增量。配置项 `观测模型用量` 默认开启；显式设为 false 时不接监听，不清除既有记录。它与 `audit工具调用` 的开关独立。

开始帧到达时从同步真源冻结归因。只有本人有效活动任务能可靠落到同一目标时才按该目标归类；这种绑定归类不证明请求语义或实际计费归属。多目标、含未关联活动任务、无可信绑定、会审等情况保留未归因原因。Lead 的本次请求没有可信目标归属时也保持未归因，不能根据聊天、模型参数或后来绑定补分账。

异步落盘只保存已冻结的观察事实，不重新检查后来发生的撤权或任务变化；读取时重新核对当前读权。路由字段叫 `配置路由`，它来自 Agent 配置，不等于已经证明的实际计费模型或提供方账单路由。

记录仅含封闭计量与生命周期字段。不保存模型正文、思维内容、工具参数或消息内容。`recordStart`、`recordSample`、`recordEnd` 是服务器内部记录方法，不出现在模型或命令动作清单中；`usage`、主体、认证、执行计划或计量自报参数不能写入观察账本。
