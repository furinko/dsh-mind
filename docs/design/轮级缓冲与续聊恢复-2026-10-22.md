# 轮级缓冲与续聊恢复

本切片补上对话到正式记忆之间的空档：已接纳的用户文本、助手已提交的文本随宿主事件即时排队落盘，轮次结束追加结果；同一会话重启和压缩后可继续取得近期资料。它保留的是短期来源材料，长期偏好、需求解释和教训仍走已有正式写入与更正流程。后续已接[项目工作摘要与新会话接续](项目工作接续与自动提炼-2026-10-23.md)，轮缓冲本身不自动晋升。

## 采集与恢复

内核默认启用，可在部署配置`dsh-mind-kernel.轮级缓冲=false`关闭采集与自动装配；显式查询及人侧清空已有缓冲仍可使用。仅处理真实根会话，读取和落盘前核对当前在岗Lead、已钉岗位卡及当前记忆read权，成员与复核会话不进入私人缓冲。

`session/event`同步回调先把事件投影为有限文本及来源标识，再异步串行写盘，不保留原始流、推理、工具参数、工具结果、附件和RPC。用户消息须有`source.kind=user`且已进入模型表面；这说明宿主接纳的来源标记，不认证用户原话或授权。助手只取`assistant/message`已提交文本，包括标明`interrupted`的实际提交前缀，不把`assistant/attempt`失败流当作回答。图片等非文本内容不复制。

`turn/start`、`turn/end`组织轮次，保留`open/closed/unknown`及宿主结束原因；closed不等于目标完成。一个轮次中可有多条用户消息及多个助手步骤。只读到半轮或目录变化时保持未知，不补造已完成结果。

缓冲文件在私有区`集体L2-共享基础设施/记忆服务/轮级缓冲/<项目>/<会话SHA256>.json`。会话id不直接作为路径；文件使用0600权限，独占锁及进程内串行化保护读改写，同目录临时文件sync后原子替换，POSIX还同步目录。正文和`nextSeq`在同一份文件中提交，重复通知和重放不会重复正文。Windows目录同步不适用，掉电与真实设备故障仍不作绝对保证。

`session/flush`等待本会话同步；装配也先等待当前会话。首份缓冲最多从最近2048个本会话事件建立，早于起始位置的历史不承诺完整。已有缓冲重启后，从持久位置通过公开`sessionQuery.observeSession`补读遗漏，每次至多追加处理2048个事件；租约结束释放，不新增`eventAt`或原始宿主文件读取。检查点仍有后缀待补时明确报`TURN_BUFFER_RECOVERY_PENDING`，下次继续，不把已落部分报告为完整持久化；显式查询另给`待补事件数`。

恢复按原会话头目录和宿主`working-directory/change`折回每段项目归属，不能用当前目录给所有历史消息追授项目。fork继承前缀排除；队列冻结接纳时的项目，处理时范围变化则丢弃，稍后从可核历史补读。其他项目正文不复制，但表面替换元数据仍可撤回本项目原文。项目配置改变或历史目录不能解析时保持未知，不跨项目猜测归属。

SDK缺少可核观察接口时，新事件仍即时采集，缺口及历史读面不可用通过查询健康读数公开；生产接线不会只凭当前项目从旧式窗口读面猜历史归属。隔离的固定项目适配器可用受限`readEvent`窗口补读，窗口过小则退回单事件。过长积压需要多次同步，未追到当前水位时不自动装配旧帧。观察接口可能为目录归属重建提供完整事件快照；当前没有大历史压力测试。

Windows文件权限沿私有父目录ACL；Node的POSIX mode参数不能代表Windows访问控制，本切片不通过设置0600宣称完成Windows ACL加固。

## 保留、查询与清空

| 范围 | 上限与行为 |
|---|---|
| 每会话每项目 | 最多128轮、512条文本消息、2 MiB实际UTF-8文件内容 |
| 单条消息 | 最多16384个UTF-16代码单元，超出明确标记截断 |
| 有效期 | 轮次最近一次文本活动后30天；读取排除到期项，下一次采集或同步时物理清理 |
| 自动上下文 | 最近最多8条尚未在当前模型表面的消息；正文预算3600、资料JSON最多6000代码单元 |
| 显式查询 | 默认16条消息，limit为1至100；正文预算默认24000、可取1至24000 |

保留预算淘汰最旧轮次，单个大轮次还可淘汰最旧消息，`已清理消息数`说明已发生裁剪。未访问的旧会话文件目前没有定时全盘清理，过期逻辑不等于后台立即擦除；总会话数和部署总磁盘量没有额外全局配额。

工具`mind action=turn_buffer_query`或命令`/mind turn_buffer_query`读取当前真实会话、本项目资料。可给`limit`、`偏移`和`内容预算`，按`下一偏移`从新到旧续读，每页内部恢复时间顺序；可携带返回的`数据版本`防止混合内容版本。分页单位为消息，返回仍按轮次分组。可给`id=<消息id>`读取已缓冲正文详情；它不能恢复单消息保存上限外的字符。数据版本不因纯工具事件推进水位而变化，文本、撤回及保留集变化后从首页重新读。

查询返回起始和下次事件位置、未核事件数、已清理消息数、保留期、截断及采集健康；没有缓冲不冒称已记录全部对话。参数不能指定其他会话或跨项目读取。

人侧`/mind turn_buffer_forget`清空当前缓冲，保留宿主当前位置作为屏障，迟到通知和旧历史补读不能复活被清空的正文；后续新输入仍可记录。该动作不在模型工具动作表中，损坏缓冲也可由人明确清空。宿主原始聊天及已经写入的正式记忆分别管理。

## 上下文与撤回

系统装配追加`mind:turn-buffer`。只给当前本会话Lead，当前表面仍可见的消息不重复注入。压缩后保留历史正文作为有界资料，明确当前请求优先、助手建议不等于用户决定、未完成回复不等于工作完成。当前原始表达教训选材继续遵循其原合同，不拿旧缓冲冒认本轮新输入。

普通表面替换会物理移除被替换正文，并保存可识别的用户/助手替换文本；明确的`compact-checkpoint`压缩保留原文并转移表面锚点。后续替换该压缩节点时，其关联正文也撤回。缓冲清空、过期、身份、项目、Session对象、表面或组件生命周期在读取期间变化时，不提交旧帧。故障仅报告错误类型，旧文件保留，不将私人正文或宿主异常原文写入日志。
