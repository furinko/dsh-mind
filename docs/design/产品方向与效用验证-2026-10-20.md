# mind 产品方向与效用验证

日期：2026-10-20。

**产品方向：让每次工作留下可验证、可复用、可纠错的成果，并在协作收益明确时启用组织机制。** 衡量进展时，优先看任务质量、解决成本和用户介入；岗位数量、审计条数和知识存量用于诊断运行情况。

状态：产品方向，以及[目标模型与生命周期](目标模型与生命周期-2026-10-20.md)、[知识有效性与复用](知识有效性与复用-2026-10-20.md)、[持续执行与预算](持续执行与预算-2026-10-20.md)的基本原则已确认；具体执行接口、工作方式、存储字段和验证方案待下一阶段收敛。现行权限与流程仍以[组织设计 v2.0](组织设计.md)及[24 条确认决策](v2-口述收敛-2026-10-18.md)为准。

## 1 产品目标

mind 服务于需要持续积累经验、控制上下文并验证结果的工作。一次任务完成后，应能回答：交付了什么、证据是什么、下次遇到相似问题能复用什么，以及环境变化后如何纠错。

组织机制的扩展应有实际收益依据。优先验证三件事：

- **质量保持或提高**：用户目标得到满足，关键缺陷与越权操作没有增加。
- **同类任务成本下降**：重复探索、返工和无效调用减少；记忆维护与治理开销一起计入。
- **用户负担可控**：必要的授权与决定清楚集中，重复解释、重复确认和人工解堵减少。

单次成功用于形成候选经验。重复使用、反例与环境变化的结果共同决定经验能否继续适用。

### 长期连续性的载体

**长期连续性由用户目标、当前进展和已验证知识承载。Lead 会话与成员承担阶段性执行，岗位提供可调整的能力配置。**

后续目标模型围绕以下内容组织持久信息：

| 载体 | 延续的内容 |
|---|---|
| 用户目标 | 希望达成的结果、约束，以及判断结果是否达成的依据 |
| 当前进展 | 已确认完成的部分、证据、阻塞与下一步；待验证判断明确标注 |
| 已验证知识 | 可复用主张、适用条件、证据及纠错关系 |

一个目标可以通过多次任务逐步推进。目标描述持续意图，任务描述有边界的执行与交付；任务采纳不自动证明整个目标完成。会话关闭、实例封存或岗位调整，也不自动结束目标或删除相关知识。

交接应能从这些持久信息重建工作所需的上下文，引用原始证据与历史责任，不依赖前一个会话仍在运行或把全部聊天记录再次注入。目标、任务与知识之间保留关联，避免复制同一事实成为多个状态真源。

目标的建立、最小信息、五种状态与交接摘要见[目标模型与生命周期](目标模型与生命周期-2026-10-20.md)。具体持久化、变更与跨会话执行接口另行设计。保存目标与进展本身不增加执行授权，也不自动启动后台运行；既有岗位卡、实例凭证与任务权限继续适用。

## 2 采用组织机制的条件

Lead 在现有授权内选择工作方式。用户明确要求的协作方式优先；实际创建实例仍须满足部署授权。

| 工作情况 | 首选方式 | 选择依据 |
|---|---|---|
| 范围清楚、步骤相互依赖、单个上下文足够 | Lead 直接处理 | 能直接完成，额外实例难以减少等待或提高验证质量 |
| 存在可分离的子任务，输入和交付边界清楚 | 按需派发成员 | 并行收益或专业能力收益足以覆盖交接和汇总成本 |
| 方案存在实质不确定性，比较不同答案有助于决策 | 会话级会审 | 问题、材料范围、预算和收敛条件明确 |
| 需要正式验收的任务成果 | 按现行规则复核与采纳 | 直接执行与委派执行均遵守已有验收要求 |

选择前明确交付物、验收证据、允许的副作用和可用预算。无法说明成员的独立交付物时，先缩清问题；创建更多实例不作为默认解法。

工作方式的简化不改变授权、复核或记忆晋升资格。普通问答是否需要任务记录、哪些任务可以采用更轻流程，应单独设计；本轮不据此新增免审路径。

## 3 成果与知识的关系

任务采纳、证据强度和知识适用范围分别表达：采纳说明本次交付达到冻结判据；证据说明结论怎样得到支持；适用范围说明下一次能在什么条件下使用。

例如，“当前宿主版本在本机完成一次重启验证”可以支持这次交付，不能直接推出“所有版本的重启都可靠”。岗位负责维护相关知识，项目与岗位标签也参与权限判断；实际复用还要核对环境、版本和前提。

下一阶段知识条目设计至少应表达以下信息，具体格式与现有来源、标签和血缘字段共同收敛：

| 信息 | 要回答的问题 |
|---|---|
| 主张 | 到底知道了什么，哪些结论仍只是推测 |
| 证据引用 | 哪份产物或观察支持它，如何定位当时的内容与版本 |
| 适用条件 | 适用的环境、版本、输入前提和已知边界 |
| 反例与纠错 | 什么情况会推翻或收窄它，替代结论在哪里 |
| 复验条件 | 哪些版本或环境变化发生后，需要重新验证 |

复用时按需取证据与全文，限制返回内容预算。后续使用发现不适用或错误时，追加纠错并更新有效视图；原记录与责任归属保留。来源存在、格式合规和晋升获准，都不能单独充当正确性证明。

知识的验证含义、适用条件、复验触发与复用反馈见[知识有效性与复用](知识有效性与复用-2026-10-20.md)，具体存储字段与接口继续收敛。

## 4 现有决策与后续设计的边界

保留双区、岗位与实例分离、任务图、追加账本、纯投影工作台，以及不越授、不自授和故障时拒绝写入的原则。

| 现行决策 | 下一阶段需要补充的内容 |
|---|---|
| 授权采用天然载体，不立四类授权对象 | 统一说明各载体的范围、委派、有效性、撤回及冲突规则；落到真实副作用入口 |
| 复核员是普通岗位，Lead 手动派发，复核结论为硬闸 | 区分上下文隔离与证据独立；允许指出冻结判据不足以证明用户目标达成 |
| 免审是主权者全局开关，预审按既定动作清单 | 先记录治理成本与实际风险案例，再判断是否值得提出粒度调整 |
| 孤儿实例由系统回收，未完成不算成功 | 设计任务等待期限、移交、新执行代、取消与故障升级 |
| 采纳后按现有资格晋升知识，结账逐条处置候选 | 补充知识的适用性与复验规则，衡量后续使用效果 |

复核发现判据不足时，应明确记录缺口，并通过合法的补充决定或新节点承接；冻结判据继续有效。风险分级、自动复核、自动放行和新增管理层均不作为本轮方向调整的默认结果。

## 5 效用验证方案

### 比较对象

先采用小规模隔离试验。建议选择三类工作，各准备三组难度相近的匹配案例：范围明确的修复、可拆分的工程任务，以及带适用知识或过期知识的重复问题。

前两类比较 Lead 直接处理与按需组织协作，使用相同授权边界、验收要求、可用材料和运行预算，保留相同复核要求。第三类固定协作方式，比较检索复用与不复用，覆盖适用知识和过期知识案例。协作与记忆分别比较，避免混淆收益来源。

两条路径使用隔离副本和新上下文，交替执行顺序，避免先执行的一方把答案带给另一方。涉及读写、故障注入和外部副作用的案例均在夹具或隔离环境中运行。

这九组案例用于初步发现收益、开销与反例，不足以证明所有任务类型都适用。

### 记录口径

| 维度 | 记录内容 |
|---|---|
| 质量 | 冻结判据的逐项结果、遗漏缺陷、错误结论、越权或越界尝试 |
| 时间 | 开始至交付的耗时，执行、等待、复核和返工分别记录 |
| 调用成本 | 工具调用数、可取得的 token 与计费读数，包含所有成员和复核实例 |
| 用户注意力 | 介入次数与处理时间，标明必要授权、业务决定、重复确认和故障解堵 |
| 记忆效用 | 召回条目是否被采用、采用后是否有效、是否引入错误，以及整理和纠错耗时 |
| 恢复能力 | 注入故障后是否保留事实、可否恢复、需要多少人工处理 |

缺失读数记为未知，不填零。时间、token、费用和用户介入分别报告；需要合成总分时，先固定权重与换算口径。必要审批造成的成本如实计入，优化时继续满足其授权目的。

### 判定规则

先用探索案例取得成本范围，再为新一轮独立案例冻结质量底线与改善门槛。验收依据同时核对用户目标和实际交付物；评估者不得参与该案例的执行与结果改写。

只有质量达到底线，才比较成本收益。报告各类任务的结果分布、失败与最差案例，保留所有预先登记的案例及中途失败；环境不可用和证据不足单列。未取得的用户处理时间继续标为未知，不能宣称已降低用户负担。

满足预先约定门槛的机制可以在已验证任务类型中扩展；开销超过收益时采用更简单的合法路径；结果不足时维持小范围使用并补案例。知识数、审计数和实例数不作为扩展依据。

## 6 下一阶段工作顺序

跨会话续做、执行中改变目标、预算耗尽与执行者失联的完整推演见[连续工作的端到端场景推演](端到端场景推演-2026-10-20.md)，用于检查后续接口与验收判据。

1. **修复会使评估失真的边界。** 优先处理普通成员工具读写域、交付物内容与复核票绑定、任务账本损坏检测，以及项目身份碰撞。否则质量与隔离读数缺乏可靠基础。
2. **补齐恢复与内容预算。** 设计并验证执行中任务的接续、部分提交的幂等恢复，以及相关记忆的按需返回，记录必要的人工作业。
3. **建立最小评估记录。** 先使用明确的案例表和原始证据，复用已有任务与日志数据，补足取不到的指标。用小规模试验判断直接执行、委派与记忆复用各自的收益。
4. **按结果决定扩展。** 有稳定复用证据再完善知识字段与检索，有实际停滞或成本证据再评估新的协调和治理机制。

新岗位、新层级、更多审批档位和更复杂的会审流程暂不列为扩展重点。当前交付是产品方向与验证设计，工程验收和运行态发布各自保留独立证据。
