## 0 · 这份文档是什么

一份**从零设计**的数字组织方案：谁来治理、分成什么结构、靠什么机制运转。

它不回答"怎么实现"。它是**实现前的判据来源**——实现方案对不对，拿本文对照。

---

## 1 · 目的与理由

**最终目的**：更好地服务用户。

**为什么采用组织架构**（三条理由，缺一条就不必做组织）：

1. **需要长期记忆** —— 单会话装不住
2. **便于管理记忆，避免上下文污染与注意力分散**
3. **减少 LLM 的讨好效应**

**判据**：

- **成** = 同类问题的解决成本随时间下降
- **败** = 同一个坑踩第二次；或知识只涨不用

## 2 · 主体

| 主体 | 在编 | 权 |
|---|---|---|
| **主权者** | 不在编 | 立宪 · 立法 · 否决 · 撤回 · 查看 |
| **出厂作者** | 跨部署 | 出厂内容 + 防护机制 + 安全类强制更新 |
| **Lead** | 岗位唯一，多会话实例 | 执行首脑 · 提案权 · 派活 · 汇总验收 · **采纳** |
| **成员** | 岗位持久、实例临时 | 任务内全权，任务外无 |
| **系统** | 机制自身 | 审计 · 探针 · 失联冻结 · 孤儿回收等**机制动作的记账主体** |

**五类，不多不少。** 「系统」单列的理由：让机制动作与人 / 组织的动作在账本上一眼分得清——审计、探针、失联冻结这类事没有「谁派的活」，硬塞进 Lead 或成员就是把责任记到错的人头上。

**出厂作者与主权者的分工**：

- 出厂作者管：**出厂内容 + 防护机制**
- 主权者管：**这个部署的宪章、法律、红线内容**

**知识挂岗位，不挂实例。** 一次派活 = 该身份的一个实例，干完就散。

> **领域协调者**：暂不设。出现「Lead 成瓶颈」的实测再议。

### 2.1 复核 = 一张普通岗位卡

**复核不是主体类别，不是第二套编制，就是 `集体L3-成员角色卡/复核员.md`。** 与「插件工程」「文档整理」「记忆整理」同地位。

**砍掉的机制**（v2 明确删除，不得在实现里留半截）：

- 第五类主体「复核者」
- 主权者逐案任命（`registry_assign` 对复核员必填授权引用）
- 提名、池、轮派、在册复核员排队

**起实例的路只有一条**：任务到待复核后，**Lead 用 `member_spawn` 手动起一个复核实例**——与派任何成员同一条路，不引入「系统自动起」的新机制。

**复核实例的读范围**：按任务授权宽读——本任务的交付物、判据、相关账本与审计。比普通成员「只读自己那片」宽，但**限定在任务作用域内**，不是全局随便看。

**复核的硬约束由机制扛，不靠卡文本自觉**：「只读数、不改、不提案」是策略引擎对该岗位卡的硬规则，写操作一律拒。

**已知缺口（主权者认可）**：Lead 可以拖着不复核 ⇒ 任务停在待复核。这只是**停滞**，不产生错误采纳。

### 2.2 复核独立性扛在哪

不靠「复核者是特殊主体」这个设定，靠四件事同时成立：

| 支柱 | 怎么扛 |
|---|---|
| **冲突排除** | 执行者 / 交卷人 / 负责人 / 同会话者**不得复核本任务**；由机制判，不由人自觉 |
| **冻结判据** | 判据在派发时冻结 + `member_spawn` 由机制自动附上；Lead 的任务书只是补充说明，**改不了复核看什么** |
| **独立上下文** | 复核实例一个新会话，天然满足（这正是立项理由③的着陆点） |
| **采纳权在 Lead + 兜底** | 采纳是 Lead 的设计本意；Lead 越过硬闸强采纳，靠**审计留痕 + 主权者三权兜底**，不靠复核者 |

### 2.3 复核结论 = 硬闸

- 没有「过」**不得采纳**；「未验」**也不得采纳**。
- Lead 可**记录不同意**，但**不得修改复核结论**。
- **采纳必须引用复核结论**。
- 判据本体不在 Lead 手里（见 §2.2）。

### 2.4 免审 = 部署设置里的全局开关

复核可免审，但**免审是主权者的部署设置，不是 Lead 的裁量**：

- 一个全局开关，默认**关**；不设任务风险分级（真有感觉再加档）。配置位置 = 私有 `部署.json` 的 `复核免审`（**没有界面开关**）。
- 开关变更**入审计**。
- 免审生效时，机制在任务节点上**登记「豁免」事实**——豁免不是没发生，只是不拦。

> **落地状态**：开关本体与加载期布尔校验已落；**「变更入审计」未接线**（手改 `部署.json` 不产生「设置变更」事件），见 `DESIGN-MAP.md` §2 的「部分落」行。

### 2.5 统一实例模型（全岗位一套）

**卡恒久 · 实例临时 · 启动钉卡版本 · 绑定任务 · 用完封存。** Lead / 成员 / 复核员**同一套**，没有例外。

| 概念 | 规则 |
|---|---|
| 卡 | 永久对象，挂在 `集体L3-成员角色卡/`；带 `cardVersion` 元数据 |
| 实例 | 临时；出生时**钉当时的卡版本**；策略引擎只认「实例 + 卡版本 + 任务作用域」 |
| 绑定 | `member_spawn` 起实例时把实例绑到任务节点；Lead 实例随主会话出生，也钉当时的卡版本 |
| 封存 | 任务结束即封存；封存 ≠ 删除 |

**为什么钉卡版本**（主权者确认的三条理由）：审计能答「凭什么」· 规则不半途变脸 · 复核有基准。

**负责人寻址 = 写岗位名**；实例随派产生；「全员已交」这类判定按**已绑实例**算。
**明确否决**「派发时展开为在岗实例集合」——它与「实例随任务起、无常驻」直接矛盾。

**Lead = 岗位唯一、多会话实例**：每个主会话窗口一个 Lead 实例；共享岗位卡、能力库、记忆、任务图与审计，**会话上下文互不互通**。并发冲突靠**任务认领 + 审计归属**协调；同一任务不得重复派发或重复采纳。

**孤儿实例**（崩溃 / 重启）：由**系统**标封存；未完成的交卷**绝不自动算成**。

## 3 · 约束

**永不**：

1. 实例知识默认外流
2. 未经主权者的删除 / 发布 / 批量覆盖
3. 出厂件含任何用户特定信息
4. **组织给自己发合格证**（提案者不得自批）
5. 成员自扩权 / 再起成员
6. **安全闸静默失败**（坏了必须拦住或响亮告警）

**再加两条不变式**（进策略引擎，v2 新增）：

7. **不越授**——Lead 派活给出的写域 / 工具，不得超出 Lead 自身范围。
8. **不自授**——主体不得给自己扩权（第 5 条的推广：成员不能，Lead 也不能，复核员也不能）。

> 这两条不是新机制，是策略判定里的两条硬规则；它们是「不立统一授权对象模型」（§9）能成立的前提。

**不可逆资源**：已发布的版本 · 审计日志 · **待决项的记录**

> 队列本身可以被清空；不可逆的是**记录**——清空动作必须入账，被清掉的项**进账本而不是消失**。

## 4 · 治理结构

```
主权者
 └ 集体 L0 · 宪章 ────── 你立你修（Lead 只协助起草；修宪 Lead 不许发起）
    └ 集体 L1 · 法律 ──── 你定（Lead 可提议修）
       └ 自治 ────────── 组织自决（集体结构 / 共享基础设施 / 角色卡 / 个体 L0~L3）

审计日志 ──────────────── 只增不改（独立于以上全部）
```

> **L0~L3 有两个域**：**集体域只有 L0（宪章）和 L1（法律）**；**个体域才有 L0~L3**（身份 / 规则 / 能力 / 经验）。

**三档门槛**：立宪 / 立法 / 自治。**唯一分界线：你定的 > 组织定的。**

| 动作 | 发起 | 确定 |
|---|---|---|
| 立宪 | 你主导，Lead 协助起草 | **你** |
| 修宪 | **你主导**（Lead 不许发起） | **你** |
| 立法 | 你主导，Lead 协助起草 | **你** |
| 修法 | Lead 提议 / 或你提出 | **你** |
| 自治 | 组织 | 组织（你默认不参与） |

**三权**：查看 · 否决（任意时刻任意一条）· 撤回（= **写拒绝名单，不删卡**）

### 4.1 介入度 = 主权者本人的介入程度（三档）

**介入 = 要落盘的东西要经过主权者审核同意才能落盘。** 后两档的执行者是**主权者本人**，不是复核实例——复核实例是主干环路的验收闸（§8），不是主权者替身。

| 档 | 行为 |
|---|---|
| **放权**（默认） | 自治写直接落盘、留痕、事后可查可否决 |
| **预审** | **高风险**自治写停在「待你决定」，主权者批准后落盘；低风险直落 |
| **审批** | 每条自治写都等主权者放行 |

**预审档的「高风险」= 按动作类型的写死清单**（写死，好判好审）：

1. 改岗位卡
2. 发布能力
3. 物理删除记忆
4. 改设置

> 要扩清单 = 改设置，主权者动作。

**只影响自治档**：立宪 / 立法 / 否决 / 撤回不受影响。设置项**仅主权者可改**、变更入审计、非法值 **fail-closed**。

**与失联一致**：预审 / 审批档下主权者不在线，自治写自然排队；失联冻结再罩一层（§4.4）。

### 4.2 岗位与卡

**建 / 改 / 删卡 = Lead**（复核员卡**不再是例外**——它就是普通卡）· **工具总范围 = 主权者** · **派活 = Lead**。

「复核员卡不是例外」的代价要一并说清：改卡本身是**预审高危动作**（§4.1），所以「改复核员卡的判据」仍然过主权者，只是走介入度、不再走特殊任命。

### 4.3 授权标签

**授权是标签，不是路径**；粒度 = **段**。

```markdown
---
id: some-doc
---
<!-- authority: 法律 -->
## 权限矩阵
…
<!-- authority: 自治 -->
## 作业规程
…
```

**谁打**：出厂件由出厂作者 · 法律件由主权者 · 自治件由 Lead。
**标签的性质**：对象的**元数据**，写入时一并写入；**变更要走策略引擎**。
**冲突**：同一对象标签冲突时，**以更高 authority 为准**。

### 4.4 留痕 · 版本 · 继承 · 失联

**留痕是自治的门槛**：谁提的 / 凭什么 / 谁复核 / 结果 / 可回滚点。**无留痕的自治变更 = 无效。**

**版本与回滚**：

- 宪章与法律每次改动生成版本；**只有主权者能回滚文本版本**
- ⚠️ **回滚的是文本，不是世界**
- **安全类的自动回滚是「机制回滚」**，不是文本回滚——两者不是一回事

**继承**：岗位恒久，模型是发动机。「代」记在角色卡的元数据里（`cardVersion`）；审计日志记变更事件。

**失联**：

- 主体 = **主权者**
- **判定**：自**最后一次交互**起，超过**主权者自设的响应期限**未响应 ⇒ **系统自动标记失联**
- **恢复**：主权者任何一次交互即解除；**恢复 ≠ 批准待决项**
- 后果 = **所有自治变更冻结**（维持宪章，不松绑到「只冻结治理变更」）；服务与记忆照常；**安全类强更照常**

### 4.5 安全类（封闭清单）

**出厂作者只能在这些类别内强制更新，且只能更新机制的实现，不得改主权者的红线内容。**

1. 用户数据 / 凭据外泄
2. 防护机制被关闭或绕过
3. 审计被篡改

**不许「等其他类似情况」兜底。**

> 切法：**红线的内容归主权者，防护机制的存在归出厂作者。**

**五道配套**：

| 配套 | 内容 |
|---|---|
| **影响面声明** | 每次强更必须声明：动了哪些检测逻辑 |
| **红线索兵** | **主权者声明**探针，**出厂作者实现**；探针本身受安全类保护，**强更不能绕过它** |
| **探针红 ⇒ 自动回滚** | 回滚目标 = **探针全绿的最近一版**（不是紧邻上一版） |
| **自动回滚的定性** | **策略引擎内置行为**：**无条件执行 + 无条件入账** |
| **留痕 + 可申诉** | 全程入账；主权者可申诉并回滚机制版本 |

**探针本身的健康**：探针**恒红或恒绿**都要报警（恒亮的灯等于没灯）。

**失联期间**：安全类强更不受影响。影响面声明与探针照跑。

## 5 · 载体与升级

**目录只按升级边界分两区**；档与域落标签。

| 区 | 装 |
|---|---|
| **出厂** | 宪章 / 法律**默认文本** · 基础岗位卡 · **出厂能力库** · 基础设施**程序** · 出厂默认值 |
| **私有** | 主权者改过的宪章 / 法律 · **部署偏好** · 本机岗位卡 · **自治能力库** · 基础设施**数据** · 审计日志 · 身份档案 · 版本历史 |

**实例数据放私有区内部，不开第三区。**

### 5.1 两个能力库 = 双区各一份

| 库 | 位置 | 内容 | 升级 |
|---|---|---|---|
| **出厂能力库** | 出厂区 | 产品自带的技能规程 | **随产品更新** |
| **自治能力库** | 私有区 | 组织自己长出来的技能与经验 | **组织自治**，永不外流 |

**同名不合并**（是两条，不是一条被改写）。
**同名检索**：两条都返回并**标注来源**；**默认用自治版**；**冲突时并列给 Lead 判**。

### 5.2 升级：叠加层 + 条款级合并

- 出厂文件 = **只读模板** · 用户改动 = **叠加层** · 生效内容 = **合并结果**

| 情况 | 处置 |
|---|---|
| 用户没改过 | **直接替换成新版** |
| 用户改了、出厂没改 | **保留用户的** |
| 两边改了**同一条** | **私有优先** + 审计告警提示主权者（2026-10-08 裁决取代 v1.5 的「挂起」；新冲突不再挂起） |
| 安全类 | **强制替换**，不可协商 |

**遗留挂起项**（裁决前产生的）**不阻塞其他更新**，可裁决 / 撤回。

**主权者失联时**：非安全类 diff 不偷偷落地——按 §4.4 冻结；**安全类强制替换**；恢复后统一裁决。

**三个配套**：**基线戳** · **不强制 ≠ 不通知** · **可撤回**。

### 5.3 哪些内容用户不该改

| 内容 | 用户可改 | 升级行为 |
|---|---|---|
| 防护机制 / 引擎 | 不该 | **随产品更新** |
| 出厂能力库 | 不该 | **随产品更新** |
| 自治能力库 | —— | 组织自治 |
| 岗位卡 · **规则 / 能力 / 经验段** | 可以 | 叠加层 |
| 岗位卡 · **身份核心** | **锁定，不可叠加** | 随产品更新 |
| 宪章 / 法律默认文本 | 可以（那是他的权） | 叠加层 |
| 安全类 | 不该 | **强制更新** |

> **身份核心锁定**：身份若能被就地改写，「身份连续性」就断了——而那正是立项理由 1 的前提。

> **产品的价值在「机制与能力」，不在「内容与法律」。**

## 6 · 数据结构

每个对象带：

```
id · kind · authority · zone · domain · project · version · refs
```

- `kind` = 身份 / 规则 / 能力 / 知识 / 任务 / 消息 / 产物 / 账目
- `authority` = 宪章 / 法律 / 自治 / 只增
- `zone` = 出厂 / 私有 · `domain` = 集体 / 个体 · `project` = 项目键

**`kind = 消息` 是对象**；消息 `authority = 只增`。
**`kind = 产物`** = 任务产出物（存对象存储，任务节点只存引用）。

### 6.1 对象存储（底座，不是一件）

**对象存储 = 文件系统的约定层**（目录约定 + 命名规则 + 版本文件命名）。它在**八件之下**。

- **策略引擎是唯一写入口**
- **审计日志记录变更**
- **版本化在写时自动发生**：任何带 `version` 的对象，改动前自动留前一版
- 回滚动作**读历史版本**，审计日志**只记版本指针**

## 7 · 八件基础设施

| 件 | 职责 | 必须保证 | 不做 |
|---|---|---|---|
| **角色注册表** | 有哪些岗位、谁能干什么、谁在岗 | 封存 ≠ 删除 · 随时能答「这身份能碰什么」 · 实例权限只来自岗位 · **实例钉卡版本** | 不存卡正文、不存记忆 |
| **共享工作台** | 当前状态的**唯一视图** | **是投影**：能从任务图 + 日志重算 ⇒ 不许当第二事实源 · 成员只读自己任务那片 | 不做讨论、不做权威记录 |
| **任务图** | 任务依赖与状态 | **验收标准必填** · 派发后**判据冻结** · **待决项是节点状态** · **负责人写岗位名、实例随派绑定** · **产出物只存引用** | 不做调度决策、不存产出物本体 |
| **消息总线** | 结构化通信 | 支持**暂不投递** · 线程隔离 · **历史不入上下文** · Lead 表态可标记延后 · **发件人恒为真实主体** | 不做长期记忆、不做状态 |
| **策略引擎** | **唯一判定点** | 不能被绕过 · **fail-closed** · 拒绝带**可执行理由** · 判定只读标签不读路径 · **不越授 / 不自授两条不变式** | 不存规则、不自己记账 |
| **能力库** | **怎么做**（技能 / 规程） | 与记忆服务并列 · **单源**（多岗位共用同一项，不复制）· 双区各一份、**同名不合并** | 不装知识 / 经历 / 偏好 |
| **记忆服务** | **知道什么**（写入 / 检索 / 固化 / 失效 / 裁决） | 写入必带**谁记的 + 怎么知道的** · **不许改写只能追加** · **写入时校验正文结构，不合规拒写** · **「通用」是合法命名空间** | **不装能力**、不决定注入什么、不上数据库 |
| **审计日志** | **只增的事实记录** | 只增（**主权者也不能改，只能追加更正**） · 写入无条件 · **不承担回滚** · 记录分级 | 不做回滚、不做状态 |

### 7.1 能力库 ↔ 记忆服务的分工

| | 装什么 | 答什么问题 | 谁持有 |
|---|---|---|---|
| **能力库** | 技能 / 规程（怎么做） | 「这件事怎么做」 | 岗位（**可多岗位共用**） |
| **记忆服务** | 知识 / 经历 / 偏好 / 作答 | 「我们知道什么」 | 见下 |

**角色卡的 `个体L2` 段 = 引用能力库里的哪几项**，不内嵌全文（单源）。

### 7.2 存储归属

- **卡正文** = 普通对象，按 `zone` 存放，带 `authority` 标签；**注册表只存引用**
- **规则**（宪章 / 法律）= 带版本的对象库，按 zone 存放；**策略引擎启动时加载、变更时热更新**；**加载失败 fail-closed**
- **产出物** = 对象存储里的 `kind = 产物` 对象；**任务节点只存引用**
- **待决项** = **任务图里的一种节点状态**；工作台把它投影出来

### 7.3 记忆四类与写入权

**知识 / 经历 / 偏好 / 作答**

> **能力不在记忆服务里**——它在与记忆服务并列的**能力库**中。

**统一原则：不许改写，只能追加。**

| 情形 | 处置 |
|---|---|
| 经历 | 只增，不改 |
| 错误 / 过期 | **追加 `invalid` 状态** |
| 冷 | **追加降权状态**，不删 |
| 被推翻 | **追加**（双份留痕） |
| **物理删除** | 仅限：敏感数据、主权者明确要求 |

### 7.4 知识写入 = 晋升动作（任务内只写经历 / 作答）

**成员实例任务内**可写「经历」「作答」，交卷可附**知识候选**；**不得直接写「知识」类、不得改能力库、不得改角色卡引用**。

采纳后由 **Lead 或记忆整理岗**把候选蒸馏为知识条目（岗位 + 项目双标签）。

> 依据：复核硬闸（§2.3）的推论——**未验收的产出不进组织知识**；经历账本保底不丢信息。

**晋升的权责分层**：

| 范围 | 谁批 |
|---|---|
| 项目内知识 / 岗位经验 | **Lead** |
| 跨项目 | Lead + **披露检查**（契约C 保留） |
| 发能力 / 改卡引用 | Lead + **按介入度走**（§4.1 高危清单） |

**晋升不是新机制**，就是普通自治写，被介入度三档与失联冻结罩住，**无特例**。

**三个入口**（主动发起不靠 Lead 记得，靠环路不结案）：

| 入口 | 形态 |
|---|---|
| **主：结账强制** | `task_settle` 拒收无「记忆处置」声明的结账；机制在结账时把本任务经历 / 交卷候选列给 Lead 逐条判（晋升 / 留账本 / 丢弃） |
| **兜底：工作台** | 「已采纳但记忆处置为空」投到「待你决定」 |
| **补充** | Lead 随时手动晋升 |

### 7.5 记忆四类 ↔ 归属

| 类 | 归属 | 命名空间 |
|---|---|---|
| **知识** | **岗位 + 项目**双标签 | 跨项目（岗位）/ 本项目 / **通用** |
| **经历** | 组织账本 | 只增 |
| **偏好** | **部署** | 永不外流 |
| **作答** | 实例 | 私有区内部，任务结束归档 |

> 个体 L0（身份）与 L1（个体规则）**不是记忆**——它们是身份定义，住角色卡。

**知识标签的写入规则**：**项目标签恒打**（它产生于某个项目）；**岗位标签默认不打**，由 **Lead 判定「这条跨项目可复用」后追加**。

### 7.6 「通用」空间 + 跨项目规则

**「通用」是项目无关知识的合法住所**——记到通用里不必走晋升仪式，**但不省检查**：

- 写入闸与知识同款（§7.4）：成员只提候选，Lead / 记忆整理落笔；披露检查照跑；入审计。
- 通用条目不挂项目标签。

**跨项目**：

| 面 | 规则 |
|---|---|
| **写** | Lead 可显式传 `project` 写别的项目——**依据必填 + 入审计**（「合理」落在依据上，事后可判）；**成员实例禁止跨项目，无例外** |
| **读** | Lead 与主权者可跨项目读；成员只读本任务项目 |

`project` 参数保留；策略引擎按「**谁 + 写 / 读 + 有无依据**」判。

### 7.7 作答归档后的可读性

| 谁 | 归档后 |
|---|---|
| 主权者 / Lead | **可读** |
| 复核实例 | **可读**（按任务授权宽读，§2.1） |
| 成员 | **不可读**（自己那份除外） |
| 自动检索 | **不进默认检索面**；**可显式检索** |

### 7.8 消息总线的上下文来源

上下文 = **按需拉，不许全量推**：

- 岗位知识（随身份带）· 岗位能力（随身份带）· 任务节点 · 工作台（自己那一片）· 记忆检索（按需）
- **本轮线程**的消息 · **当前项目**的记忆（+ 通用空间的相关条目）

**不含**：其他线程、全量历史、群聊归档、其他项目。

### 7.9 审计记录分级

| 档 | 内容 |
|---|---|
| **全记** | 策略拒绝（含理由）· **工具调用失败（含原因）** · 状态变更 · 不可逆操作 |
| **记汇总** | 成员**成功**的工具调用 |
| **不逐次记** | 普通只读调用 |

> **「轮」的定义**：**一次任务实例从派发到交卷的一次执行段**。汇总按轮落一条。
> 失败**全记**：失败是最贵的学习信号。

### 7.10 项目隔离

**项目是隔离单元。**

| 对象 | 是否按项目隔离 |
|---|---|
| 任务图 · 工作台 · 记忆命名空间 · 会审存档 | 按项目 |
| **知识** | **双标签**：岗位（跨项目）+ 项目（本项目）；另有**通用** |
| 身份 / 岗位 / 履历 | **不按项目**——跨项目统一 |
| Lead | **唯一且跨项目** |

**三条硬规则**：

1. **身份跨项目统一，记忆命名空间按项目隔离**
2. **「跨项目拉取」专指「项目专属知识」**；**岗位知识与岗位能力随身份带，不算跨项目拉取**
3. **Lead 切换项目 = 换上下文，不是换 Lead**；项目键 = 工作区目录名

> 与立项理由 2 的关系：**项目隔离是「避免上下文污染」的物理实现**——靠目录边界挡，不靠纪律。

## 8 · 主干环路

```
受理 → 定判据 → 判权限 → 派发 → 执行 → 交卷 → 复核 → 采纳/打回 → 落记忆 → 结账 → 刷新视图
```

**四个「唯一」**：唯一入口（消息总线）· 唯一判定点（策略引擎）· 唯一出口（审计日志）· 唯一投影（工作台）

两个自治源：**任务图 = 状态权威**，**角色注册表 = 权限事实源**

### 8.1 复核流程

- **谁复核**：Lead 按任务用 `member_spawn` 起一个复核实例（§2.1）——没有常驻复核、没有排队
- **判据**：派发时冻结 + 机制自动附给实例；Lead 的任务书只是补充说明
- **冲突排除**：执行者 / 交卷人 / 负责人 / 同会话者不得复核本任务（机制判）
- **输出三态**：**过 / 不过 / 未验**（+ 分歧清单 + 反例面）
- **硬闸**：没有「过」不得采纳，「未验」也不得采纳；**采纳必须引用复核结论**
- **结论不经过 Lead 修改**；Lead 可「记录不同意」，**不能改结论**
- **打回计数**记在**任务节点**上：**同一节点打回 ≥2 次 ⇒ 升级主权者**
- **免审**：部署设置「复核免审」全局开关（默认关）生效时，机制登记豁免事实并不拦

**「未验」的定义**：

| | |
|---|---|
| **触发** | 复核实例在授权内**无法完成验证**（拿不到读数 / 证据不足 / 超时） |
| **算不算通过** | **不算。未验 ≠ 通过** |
| **计不计打回** | **不计** |
| **谁接手** | 升级 Lead 补材料；补不了 ⇒ **升级主权者** |

**Lead 拖着不复核**：任务停在待复核。这是**停滞**，不是错误采纳——不在机制里造自动复核来兜它。

## 9 · 接口契约

| 调用方 | 被调方 | 传 | 收 |
|---|---|---|---|
| 任何组件 | 策略引擎 | `{主体, 对象 id, 动作}` | `允许 / 拒绝 / 需确认` + **理由** |
| 任何组件 | 审计日志 | `{时间, 主体, 动作, 对象, 依据, 结果}` | 回执 |
| Lead | 角色注册表 | 岗位 / 实例定义 | id |
| Lead | 任务图 | `{描述, 负责人, 判据, 依赖}` | 节点 id |
| Lead | 成员席位（`member_spawn`） | `{岗位, 节点, 任务书}` | 实例 id（已绑节点） |
| Lead · 成员 | 消息总线 | `{线程, 发件, 收件, 类型, 内容}` | 投递状态 |
| 任何 | 记忆服务 | `{类, 内容, 归属, 来源, 项目}` | 条目 id |
| 任何 | 能力库 | `{名, 正文, 适用岗位}` | 能力 id |
| 组件 | 工作台 | **只读** | 状态视图 |

**三条硬规则**：① 写操作先过策略引擎，无旁路 ② 状态变更与敏感操作无条件落账 ③ 工作台只读

### 9.1 授权凭证：不立统一对象模型，用天然载体

**不立四类授权对象**（v2 明确否决）。各层权力用**天然凭证**：

| 层 | 凭证 |
|---|---|
| 主权者 | **身份本身**（设置项 / authority 标签 / 决议） |
| Lead | **任务节点**（冻结判据 + 绑定） |
| 成员 | **实例绑定**（岗位 + 卡版本 + 任务作用域） |

**两条红线进策略引擎不变式**：**不越授** · **不自授**（§3 第 7、8 条）。

审计照旧记「凭什么」（依据字段）。将来出现跨边界授权需求再立对象（先例：领域协调者、会审）。
**全组织仅剩的授权引用：更正审计须引主权者决议**。

### 9.2 特权读（解循环依赖）

**对象传的是 `id`，不是内容。**

> **唯一豁免：策略引擎为判定而读标签，是「特权读」，不经判定。**
> 它是判定点自己的输入，不是旁路——**且只有策略引擎拥有特权读**。

**其余一切读写都要过判定。**

**两处边界写死**：

- **会审解锁** = 本场会审按人交齐 → 揭名（仅 Lead 触发，§10）
- **拒绝必须带可执行理由**（哪条规则 + 改它要什么授权）

## 10 · 会审（独立功能，退出任务图）

**会审是一个与会话绑定的独立功能**，不是任务图的一种模式：

```
会话里抛问题 → N 个独立实例作答（互不可见） → 交齐解锁 → 收敛结论
```

- **不占任务节点、不走派发 / 复核 / 结账。** 它是**咨询工具**，不是工作台账。
- **想干活**：拿结论后往台账正常登活（另建任务节点）。
- **每次会审存档**：问题、各份答案、分歧、结论、来源会话、时间；**会审页**（看板既有 tab）列全部历史。
- **一岗多人模式字段取消**：会审独立后，多人派活只剩**并行分担**一种。

### 10.1 配件裁决

| 配件 | 裁决 | 说明 |
|---|---|---|
| **提交后解锁** | **留**（含盲评） | 未交齐只见盲标、交齐揭名；盲评不单列成一项 |
| **强制反对者** | **砍** | 轻量咨询不值一次实例调用；分歧不足由零分歧报警补位 |
| **零分歧报警** | **留** | 纯信号；存档记「零分歧异常」，**留给人看**（不自动触发抽检） |
| **讨论段** | **留但默认不开** | Lead 显式开启；预算上限照旧（轮 2 / 人 8 / 每轮 24 条 / 每人 4000 字） |

**零分歧的判据** = **结论层一致且无人给出反例面**（不是文本一致）——措辞不同不算分歧，没人给反例才是异常。

## 11 · 检索层

**默认词面检索**：BM25 + 长度归一化（治的是「分母膨胀」）。

- ⚠️ **排序各维必须同量纲或显式归一化**
- **必须有回归集 + 基线**，改任何检索口径必跑
- **报「0 命中」必须连口径一起报**（搜索面 / 查询词 / 范围）
- **正文结构是写入侧义务**：**写入时校验，不合规拒绝写入**（事后修违反「不许改写只能追加」）

**重开评估向量化的条件（须两条同时满足）**：

1. 出现**「答案根本不在候选里」**的实测案例（**排位问题不算**）
2. **算力约束解除**

**定性**：这是**当前部署决策**，不是设计原则。

## 12 · 约束清单（血换来的，必须带过来）

1. 闸**不许 fail-open**
2. 身份被停用 / 删除时，**权限判定必须有确定答案**（不许「查不到 = 放行」）
3. 权限来源必须唯一确定
4. **重启后所有判定必须能重建**（不依赖内存）
5. 出厂件不含任何用户特定信息
6. **全票一致 = 异常信号**

## 14 · 目录结构

> **来源**：解 §13 #1。**按主权者给的结构做**——看得懂的结构才是能用的结构。
> **一条纪律**：**目录负责「找得到」，标签负责「谁能改」。** 判定授权只读标签，不读路径。

### 14.1 出厂区 `mind/` —— 厂家给的模板

```
mind/
├── 集体L0-宪章/
│   └── 宪章.md              使命与价值观 / 权力结构与继承规则 / 不可违背原则
├── 集体L1-法律/
│   ├── 协作协议.md
│   ├── 权限矩阵.md
│   ├── 裁决流程.md
│   └── 审计要求.md
├── 集体L2-集体结构/
│   └── 编制.md              Lead / 成员（领域协调者暂不设）
├── 集体L2-共享基础设施/       出厂侧装的是【程序】
│   ├── 角色注册表/   共享工作台/   任务图/   消息总线/
│   ├── 策略引擎/     能力库/       记忆服务/ 审计日志/
│   └── defaults/            介入度 / 响应期限 / 工具总范围 / 安全类探针（`复核免审` / `会审讨论` 是内置键，只走私有 部署.json）

    ├── _模板.md             个体L0身份 / L1规则 / L2能力引用 / L3经验引用
    ├── 复核员.md            ← 普通岗位卡，不是特权席位（§2.1）

    ├── 文档整理.md
```

### 14.3 八件 ↔ 物理形态

| 件 | 物理形态 |
|---|---|
| 角色注册表 | **索引**（源头：`集体L3-成员角色卡/` + 身份档案） |
| 共享工作台 | **无存储**（投影） |
| 任务图 | `集体L2-共享基础设施/任务图/<项目>/` |
| 消息总线 | `集体L2-共享基础设施/消息总线/<项目>/*.jsonl` |
| 策略引擎 | `集体L2-共享基础设施/策略引擎/`（程序）+ 读宪章 / 法律 / 编制 |
| **能力库** | `集体L2-共享基础设施/能力库/`（出厂侧 = 出厂能力；私有侧 = 自治能力） |
| 记忆服务 | `集体L2-共享基础设施/记忆服务/`（`跨项目/` 与各项目；「通用」以 `项目=通用` 落 `跨项目/` 账） |
| 审计日志 | `集体L2-共享基础设施/审计日志/audit-YYYY-MM.jsonl` |

### 14.4 命名规则

1. **对象 id** —— 稳定、短、kebab；**引用一律用 id，不用路径**
2. **文件名** —— `<id>.md`，人可读
3. **账目 / 线程** —— append-only `.jsonl`，按月或按线程分片
4. **版本文件** —— `版本历史/<对象id>/<版本号>.md`；审计日志**只记版本指针**
5. **项目键** —— 目录名即项目键，同时写进 `project` 字段

### 14.5 为什么集体只有 L0 和 L1

**集体域只到 L1**（宪章 / 法律）——因为再往下都是**组织自决**，属于同一个授权档，分成 L2/L3 没有信息量。

`集体L2-集体结构/` 与 `集体L2-共享基础设施/` 里的 **L2 是分类标记，不是授权档**。
