## 0 · 这份文档是什么

一份**从零设计**的数字组织方案：谁来治理、分成什么结构、靠什么机制运转。

它不回答"怎么实现"。它是**实现前的判据来源**——实现方案对不对，拿本文对照。

## 1 · 目的与理由

**最终目的**：更好地服务用户。

**为什么采用组织架构**（三条理由，缺一条就不必做组织）：

1. **需要长期记忆** —— 单会话装不住
2. **便于管理记忆，避免上下文污染与注意力分散**
3. **减少 LLM 的讨好效应**

**判据**：
- **成** = 同类问题的解决成本随时间下降
- **败** = 同一个坑踩第二次；或知识只涨不用

## 2 · 主体

| 主体 | 在编 | 权 |
|---|---|---|
| **主权者** | 不在编 | 立宪 · 立法 · 否决 · 撤回 · 查看 |
| **出厂作者** | 跨部署 | 出厂内容 + 防护机制 + 安全类强制更新 |
| **Lead** | 常驻，唯一 | 执行首脑 · 提案权 · 派活 · 汇总验收 |
| **成员** | 岗位持久、实例临时 | 任务内全权，任务外无 |
| **复核者** | 常驻岗 | **只读数，不改，不参与提案** |
| 领域协调者 | —— | **暂不设**；出现"Lead 成瓶颈"的实测再议 |

**出厂作者与主权者的分工**：
- 出厂作者管：**出厂内容 + 防护机制**
- 主权者管：**这个部署的宪章、法律、红线内容**

**知识挂岗位，不挂实例。** 一次派活 = 该身份的一个实例，干完就散。

### 复核者（制衡角色）

**任命**：由**主权者确认**（Lead 可提名）。

**"建卡 = Lead"的例外——不只建卡，改卡也是：**

| 复核者卡的段 | 授权 | 谁改 |
|---|---|---|
| 身份 + 权限 + **判据** | **法律** | **主权者** |
| 能力 · 经验 | 自治 | 组织 |

> 理由：**被制衡者不得单独任命或改定制衡者。**

**权限**：
- 只读被验对象
- **跑命令限于只读命令白名单**；有副作用的命令默认拒绝
- 需要落盘的实验**走沙箱区**：单独授权 · 不进持久状态 · 任务结束即清 · 全程入账
- **不写、不派活、不提案**

**存储**：能力 / 经验存**私有区、独立命名空间**——Lead 可按权限读；被验方不可读。

## 3 · 约束

**永不**：

1. 实例知识默认外流
2. 未经主权者的删除 / 发布 / 批量覆盖
3. 出厂件含任何用户特定信息
4. **组织给自己发合格证**（提案者不得自批）
5. 成员自扩权 / 再起成员
6. **安全闸静默失败**（坏了必须拦住或响亮告警）

**不可逆资源**：已发布的版本 · 审计日志 · **待决项的记录**

> 队列本身可以被清空；不可逆的是**记录**——清空动作必须入账，被清掉的项**进账本而不是消失**。

## 4 · 治理结构

```
主权者
 └ 集体 L0 · 宪章 ────── 你立你修（Lead 只协助起草；修宪 Lead 不许发起）
    └ 集体 L1 · 法律 ──── 你定（Lead 可提议修）
       └ 自治 ────────── 组织自决（集体结构 / 共享基础设施 / 角色卡 / 个体 L0~L3）

审计日志 ──────────────── 只增不改（独立于以上全部）
```

> **L0~L3 有两个域**：**集体域只有 L0（宪章）和 L1（法律）**；**个体域才有 L0~L3**（身份 / 规则 / 能力 / 经验）。

**三档门槛**：立宪 / 立法 / 自治。**唯一分界线：你定的 > 组织定的。**

| 动作 | 发起 | 确定 |
|---|---|---|
| 立宪 | 你主导，Lead 协助起草 | **你** |
| 修宪 | **你主导**（Lead 不许发起） | **你** |
| 立法 | 你主导，Lead 协助起草 | **你** |
| 修法 | Lead 提议 / 或你提出 | **你** |
| 自治 | 组织 | 组织（你默认不参与） |

**三权**：查看 · 否决（任意时刻任意一条）· 撤回（= **写拒绝名单，不删卡**）

**介入度四档**：零参与（默认）/ 事后抽检 / 变更预审 / 逐条审批
> **只影响自治档。** 立宪 / 立法 / 否决 / 撤回不受影响。

**岗位与卡**：建 / 改 / 删卡 = **Lead**（**复核者卡例外**）· 工具总范围 = **主权者** · 派活 = **Lead**

### 授权标签

**授权是标签，不是路径**；粒度 = **段**。

```markdown
---
id: some-doc
---
<!-- authority: 法律 -->
## 权限矩阵
…
<!-- authority: 自治 -->
## 作业规程
…
```

**谁打**：出厂件由出厂作者 · 法律件由主权者 · 自治件由 Lead。
**标签的性质**：对象的**元数据**，写入时一并写入；**变更要走策略引擎**。
**冲突**：同一对象标签冲突时，**以更高 authority 为准**。

### 留痕 · 版本 · 继承 · 失联

**留痕是自治的门槛**：谁提的 / 凭什么 / 谁复核 / 结果 / 可回滚点。**无留痕的自治变更 = 无效。**

**版本与回滚**：
- 宪章与法律每次改动生成版本；**只有主权者能回滚文本版本**
- ⚠️ **回滚的是文本，不是世界**
- **安全类的自动回滚是"机制回滚"**，不是文本回滚——两者不是一回事

**继承**：岗位恒久，模型是发动机。
- **"代"记在角色卡的元数据里**（`generation` 字段）
- 审计日志记变更事件

**失联**：
- 主体 = **主权者**
- **判定**：自**最后一次交互**起，超过**主权者自设的响应期限**未响应 ⇒ **系统自动标记失联**
- **恢复**：主权者任何一次交互即解除
- 后果 = **所有自治变更冻结**；服务与记忆照常；**安全类强更照常**

### 安全类（封闭清单）

**出厂作者只能在这些类别内强制更新，且只能更新机制的实现，不得改主权者的红线内容。**

1. 用户数据 / 凭据外泄
2. 防护机制被关闭或绕过
3. 审计被篡改

**不许"等其他类似情况"兜底。**

> 切法：**红线的内容归主权者，防护机制的存在归出厂作者。**

**五道配套**：

| 配套 | 内容 |
|---|---|
| **影响面声明** | 每次强更必须声明：动了哪些检测逻辑 |
| **红线索兵** | **主权者声明**探针，**出厂作者实现**；探针本身受安全类保护，**强更不能绕过它** |
| **探针红 ⇒ 自动回滚** | 回滚目标 = **探针全绿的最近一版**（不是紧邻上一版） |
| **自动回滚的定性** | **策略引擎内置行为**：**无条件执行 + 无条件入账** |
| **留痕 + 可申诉** | 全程入账；主权者可申诉并回滚机制版本 |

**探针本身的健康**：探针**恒红或恒绿**都要报警（恒亮的灯等于没灯）。

**失联期间**：安全类强更不受影响。影响面声明与探针照跑。

## 5 · 载体与升级

**目录只按升级边界分两区**；档与域落标签。

| 区 | 装 |
|---|---|
| **出厂** | 宪章 / 法律**默认文本** · 基础岗位卡 · **出厂能力库** · 基础设施**程序** · 出厂默认值 |
| **私有** | 主权者改过的宪章 / 法律 · **部署偏好** · 本机岗位卡 · **自治能力库** · 基础设施**数据** · 审计日志 · 身份档案 · 版本历史 |

**实例数据放私有区内部，不开第三区。**

### 两个能力库 = 双区各一份

| 库 | 位置 | 内容 | 升级 |
|---|---|---|---|
| **出厂能力库** | 出厂区 | 产品自带的技能规程 | **随产品更新** |
| **自治能力库** | 私有区 | 组织自己长出来的技能与经验 | **组织自治**，永不外流 |

**同名不合并**（是两条，不是一条被改写）。
**同名检索**：两条都返回并**标注来源**；**默认用自治版**；**冲突时并列给 Lead 判**。

### 升级：叠加层 + 条款级合并

- 出厂文件 = **只读模板** · 用户改动 = **叠加层** · 生效内容 = **合并结果**

| 情况 | 处置 |
|---|---|
| 用户没改过 | **直接替换成新版** |
| 用户改了、出厂没改 | **保留用户的** |
| 两边改了**同一条** | **挂起，摆 diff 给主权者选** |
| 安全类 | **强制替换**，不可协商 |

**主权者失联时**：非安全类 diff **挂起进待决队列**（不消失）；**安全类强制替换**；恢复后统一裁决。**挂起不阻塞其他更新。**

**三个配套**：**基线戳** · **不强制 ≠ 不通知** · **可撤回**。

### 哪些内容用户不该改

| 内容 | 用户可改 | 升级行为 |
|---|---|---|
| 防护机制 / 引擎 | 不该 | **随产品更新** |
| 出厂能力库 | 不该 | **随产品更新** |
| 自治能力库 | —— | 组织自治 |
| 岗位卡 · **规则 / 能力 / 经验段** | 可以 | 叠加层 |
| 岗位卡 · **身份核心** | **锁定，不可叠加** | 随产品更新 |
| 宪章 / 法律默认文本 | 可以（那是他的权） | 叠加层 |
| 安全类 | 不该 | **强制更新** |

> **身份核心锁定**：身份若能被就地改写，"身份连续性"就断了——而那正是立项理由 1 的前提。

> **产品的价值在"机制与能力"，不在"内容与法律"。**

## 6 · 数据结构

每个对象带：

```
id · kind · authority · zone · domain · project · version · refs
```

- `kind` = 身份 / 规则 / 能力 / 知识 / 任务 / 消息 / 产物 / 账目
- `authority` = 宪章 / 法律 / 自治 / 只增
- `zone` = 出厂 / 私有 · `domain` = 集体 / 个体 · `project` = 项目键

**`kind = 消息` 是对象**；消息 `authority = 只增`。
**`kind = 产物`** = 任务产出物（存对象存储，任务节点只存引用）。

### 对象存储（底座，不是一件）

**对象存储 = 文件系统的约定层**（目录约定 + 命名规则 + 版本文件命名）。它在**八件之下**。

- **策略引擎是唯一写入口**
- **审计日志记录变更**
- **版本化在写时自动发生**：任何带 `version` 的对象，改动前自动留前一版
- 回滚动作**读历史版本**，审计日志**只记版本指针**

## 7 · 八件基础设施

| 件 | 职责 | 必须保证 | 不做 |
|---|---|---|---|
| **角色注册表** | 有哪些岗位、谁能干什么、谁在岗 | 封存 ≠ 删除 · 随时能答"这身份能碰什么" · 实例权限只来自岗位 | 不存卡正文、不存记忆 |
| **共享工作台** | 当前状态的**唯一视图** | **是投影**：能从任务图 + 日志重算 ⇒ 不许当第二事实源 · 成员只读自己任务那片 | 不做讨论、不做权威记录 |
| **任务图** | 任务依赖与状态 | **验收标准必填** · 派发后**判据冻结** · **待决项是节点状态** · 一岗多人必标模式 · **产出物只存引用** | 不做调度决策、不存产出物本体 |
| **消息总线** | 结构化通信 | 支持**暂不投递** · 线程隔离 · **历史不入上下文** · Lead 表态可标记延后 | 不做长期记忆、不做状态 |
| **策略引擎** | **唯一判定点** | 不能被绕过 · **fail-closed** · 拒绝带**可执行理由** · 判定只读标签不读路径 | 不存规则、不自己记账 |
| **能力库** | **怎么做**（技能 / 规程） | 与记忆服务并列 · **单源**（多岗位共用同一项，不复制）· 双区各一份、**同名不合并** | 不装知识 / 经历 / 偏好 |
| **记忆服务** | **知道什么**（写入 / 检索 / 固化 / 失效 / 裁决） | 写入必带**谁记的 + 怎么知道的** · **不许改写只能追加** · **写入时校验正文结构，不合规拒写** | **不装能力**、不决定注入什么、不上数据库 |
| **审计日志** | **只增的事实记录** | 只增（**主权者也不能改，只能追加更正**）· 写入无条件 · **不承担回滚** · 记录分级 | 不做回滚、不做状态 |

### 能力库 ↔ 记忆服务的分工

| | 装什么 | 答什么问题 | 谁持有 |
|---|---|---|---|
| **能力库** | 技能 / 规程（怎么做） | "这件事怎么做" | 岗位（**可多岗位共用**） |
| **记忆服务** | 知识 / 经历 / 偏好 / 作答 | "我们知道什么" | 见下 |

**角色卡的 `个体L2` 段 = 引用能力库里的哪几项**，不内嵌全文（单源）。

### 存储归属

- **卡正文** = 普通对象，按 `zone` 存放，带 `authority` 标签；**注册表只存引用**
- **规则**（宪章 / 法律）= 带版本的对象库，按 zone 存放；**策略引擎启动时加载、变更时热更新**；**加载失败 fail-closed**
- **产出物** = 对象存储里的 `kind = 产物` 对象；**任务节点只存引用**
- **待决项** = **任务图里的一种节点状态**；工作台把它投影出来

### 记忆服务的四类

**知识 / 经历 / 偏好 / 作答**

> **能力不在记忆服务里**——它在与记忆服务并列的**能力库**中。

**统一原则：不许改写，只能追加。**

| 情形 | 处置 |
|---|---|
| 经历 | 只增，不改 |
| 错误 / 过期 | **追加 `invalid` 状态** |
| 冷 | **追加降权状态**，不删 |
| 被推翻 | **追加**（双份留痕） |
| **物理删除** | 仅限：敏感数据、主权者明确要求 |

### 记忆四类 ↔ 归属

| 类 | 归属 | 命名空间 |
|---|---|---|
| **知识** | **岗位 + 项目**双标签 | 跨项目（岗位）/ 本项目 |
| **经历** | 组织账本 | 只增 |
| **偏好** | **部署** | 永不外流 |
| **作答** | 实例 | 私有区内部，任务结束归档 |

> 个体 L0（身份）与 L1（个体规则）**不是记忆**——它们是身份定义，住角色卡。

**知识标签的写入规则**：
- **项目标签恒打**（它产生于某个项目）
- **岗位标签默认不打**；由 **Lead 判定"这条跨项目可复用"后追加**

### 作答归档后的可读性

| 谁 | 归档后 |
|---|---|
| 主权者 / Lead / **复核者** | **可读**（会审分歧清单必须对复核者可见） |
| 成员 | **不可读** |
| 自动检索 | **不进默认检索面**；**可显式检索** |

### 消息总线的上下文来源

上下文 = **按需拉，不许全量推**：

- 岗位知识（随身份带）· 岗位能力（随身份带）· 任务节点 · 工作台（自己那一片）· 记忆检索（按需）
- **本轮线程**的消息 · **当前项目**的记忆

**不含**：其他线程、全量历史、群聊归档、其他项目。

### 审计记录分级

| 档 | 内容 |
|---|---|
| **全记** | 策略拒绝（含理由）· **工具调用失败（含原因）** · 状态变更 · 不可逆操作 |
| **记汇总** | 成员**成功**的工具调用 |
| **不逐次记** | 普通只读调用 |

> **"轮"的定义**：**一次任务实例从派发到交卷的一次执行段**。汇总按轮落一条。
> 失败**全记**：失败是最贵的学习信号。

### 7.5 · 项目隔离

**项目是隔离单元。**

| 对象 | 是否按项目隔离 |
|---|---|
| 任务图 · 工作台 · 记忆命名空间 | 按项目 |
| **知识** | **双标签**：岗位（跨项目）+ 项目（本项目） |
| 身份 / 岗位 / 履历 | **不按项目**——跨项目统一 |
| Lead | **唯一且跨项目** |

**三条硬规则**：

1. **身份跨项目统一，记忆命名空间按项目隔离**
2. **"跨项目拉取"专指"项目专属知识"**；**岗位知识与岗位能力随身份带，不算跨项目拉取**
3. **Lead 切换项目 = 换上下文，不是换 Lead**

> 与立项理由 2 的关系：**项目隔离是"避免上下文污染"的物理实现**——靠目录边界挡，不靠纪律。

## 8 · 主干环路

```
受理 → 定判据 → 判权限 → 派发 → 执行 → 交卷 → 复核 → 采纳/打回 → 落记忆 → 结账 → 刷新视图
```

**四个"唯一"**：唯一入口（消息总线）· 唯一判定点（策略引擎）· 唯一出口（审计日志）· 唯一投影（工作台）

两个自治源：**任务图 = 状态权威**，**角色注册表 = 权限事实源**

### 复核流程

- **谁复核**：由主权者确认的复核者（见 §2）
- **输出三态**：**过 / 不过 / 未验**（+ 分歧清单 + 反例面）
- **结论不经过 Lead 修改**；Lead 可"记录不同意"，**不能改结论**
- **打回计数**记在**任务节点**上：**同一节点打回 ≥2 次 ⇒ 升级主权者**

**"未验"的定义**：

| | |
|---|---|
| **触发** | 复核者在权限内**无法完成验证**（拿不到读数 / 证据不足 / 超时） |
| **算不算通过** | **不算。未验 ≠ 通过** |
| **计不计打回** | **不计** |
| **谁接手** | 升级 Lead 补材料；补不了 ⇒ **升级主权者** |

## 9 · 接口契约

| 调用方 | 被调方 | 传 | 收 |
|---|---|---|---|
| 任何组件 | 策略引擎 | `{主体, 对象 id, 动作}` | `允许 / 拒绝 / 需确认` + **理由** |
| 任何组件 | 审计日志 | `{时间, 主体, 动作, 对象, 依据, 结果}` | 回执 |
| Lead | 角色注册表 | 岗位 / 实例定义 | id |
| Lead · 成员 | 消息总线 | `{线程, 发件, 收件, 类型, 内容}` | 投递状态 |
| Lead | 任务图 | `{描述, 负责人, 判据, 依赖}` | 节点 id |
| 任何 | 记忆服务 | `{类, 内容, 归属, 来源}` | 条目 id |
| 任何 | 能力库 | `{名, 正文, 适用岗位}` | 能力 id |
| 组件 | 工作台 | **只读** | 状态视图 |

**三条硬规则**：① 写操作先过策略引擎，无旁路 ② 状态变更与敏感操作无条件落账 ③ 工作台只读

### 特权读（解循环依赖）

**对象传的是 `id`，不是内容。**

> **唯一豁免：策略引擎为判定而读标签，是"特权读"，不经判定。**
> 它是判定点自己的输入，不是旁路——**且只有策略引擎拥有特权读**。

**其余一切读写都要过判定。**

**两处边界写死**：

- **会审解锁** = 任务图报"全员已交" → 消息总线解锁并广播
- **拒绝必须带可执行理由**（哪条规则 + 改它要什么授权）

## 10 · 反趋同（对应立项理由 3）

| 机制 | 怎么做 |
|---|---|
| **提交后解锁** | 全员交卷后才亮出彼此答案 |
| **强制反对者** | **系统随机指定一名未参与成员**，且**不重复** |
| **Lead 不首发** | 征求意见时 Lead 最后表态 |
| **盲评** | 第一轮只显示"成员 A / B / C"，揭名在讨论阶段 |
| **零分歧报警** | 判据 = **结论层一致且无人给出反例面**（不是文本一致） |

**"三份全一致 ⇒ 记一笔"记在审计日志**，内容 = "**会审零分歧异常**"，并**触发人工抽检**。

**一岗多人必须显式声明模式**：

| | 并行分担 | 独立会审 |
|---|---|---|
| 互相可见 | 能 | **交卷前不能** |
| 共享 | 中间结果 | **只共享岗位知识与能力** |
| 产出 | 合起来的成果 | N 份独立答案 + **分歧清单** |

## 11 · 检索层

**默认词面检索**：BM25 + 长度归一化（治的是"分母膨胀"）。

- ⚠️ **排序各维必须同量纲或显式归一化**
- **必须有回归集 + 基线**，改任何检索口径必跑
- **报"0 命中"必须连口径一起报**（搜索面 / 查询词 / 范围）
- **正文结构是写入侧义务**：**写入时校验，不合规拒绝写入**（事后修违反"不许改写只能追加"）

**重开评估向量化的条件（须两条同时满足）**：

1. 出现**"答案根本不在候选里"**的实测案例（**排位问题不算**）
2. **算力约束解除**

**定性**：这是**当前部署决策**，不是设计原则。

### 14.3 八件 ↔ 物理形态

| 件 | 物理形态 |
|---|---|
| 角色注册表 | **索引**（源头：`集体L3-成员角色卡/` + 身份档案） |
| 共享工作台 | **无存储**（投影） |
| 任务图 | `集体L2-共享基础设施/任务图/<项目>/` |
| 消息总线 | `集体L2-共享基础设施/消息总线/<项目>/*.jsonl` |
| 策略引擎 | `集体L2-共享基础设施/策略引擎/`（程序）+ 读宪章 / 法律 / 编制 |
| **能力库** | `集体L2-共享基础设施/能力库/`（出厂侧 = 出厂能力；私有侧 = 自治能力） |
| 记忆服务 | `集体L2-共享基础设施/记忆服务/` |
| 审计日志 | `集体L2-共享基础设施/审计日志/audit-YYYY-MM.jsonl` |

### 14.4 命名规则

1. **对象 id** —— 稳定、短、kebab；**引用一律用 id，不用路径**
2. **文件名** —— `<id>.md`，人可读
3. **账目 / 线程** —— append-only `.jsonl`，按月或按线程分片
4. **版本文件** —— `版本历史/<对象id>/<版本号>.md`；审计日志**只记版本指针**
5. **项目键** —— 目录名即项目键，同时写进 `project` 字段

### 14.5 为什么集体只有 L0 和 L1

**集体域只到 L1**（宪章 / 法律）——因为再往下都是**组织自决**，属于同一个授权档，分成 L2/L3 没有信息量。

`集体L2-集体结构/` 与 `集体L2-共享基础设施/` 里的 **L2 是分类标记，不是授权档**。
