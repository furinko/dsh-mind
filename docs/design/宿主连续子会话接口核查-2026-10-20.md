# 宿主连续子会话公共接口核查与修复

本轮核查只读取已安装包和仓内源码，不创建真实成员、不编辑或部署运行链接目录。初始待命书被 inbox 接收只证明宿主接收消息，不代表组织登记、岗位卡钉版就绪、任务开工或执行完成；这些事实须分别核验。

## 已确认错配

`C:/Users/kuro/.dsh/profiles/node_modules/@deepseek-ai/dsh-subagent/package.json` 标记版本 `0.1.5-rc.2`。公开类型 `lib/types/index.d.ts:117/185` 与公开 class 实现 `lib/index.js:2881/2959` 一致：

- `startContinuable(spec)` 创建可接续的持久子会话，返回 `{childId,messageId}`。spec 的 `signal` 在顶层；request 的公开类型排除了 signal。返回只确认初始 prompt 被 inbox 接收，不确认模型开工、会话日志已写或任务完成。
- `sendMessage(exactLiveParent,id,content,{signal})` 返回接收消息的 `MessageId`，不是执行结果。当前公开输入没有客户端操作幂等键；结果丢失后不能靠组织自己保证恰好投递一次。
- `interrupt(id,{kind:'ancestor',agent})` 返回 void，只发取消请求；目标可能继续运行到观察信号。缺席/未知目标允许无操作。
- `drainContinuableChildren(exactLiveParent,[id])` 等待所选驻留 Activation 释放其 AgentHandle；缺席目标允许无操作，持久子会话不会因此删除，之后可由消息重新恢复。
- `listChildren` 的 running/inactive 是采样活动信息，不是持久终局、执行完成或停止证明。`subagent/start/end` 提供同一 runId 的观察事实，可用于后续观测，不能仅凭描述目录臆造停止。

原 Mind 适配调用了公共 class 不存在的 `startActivation/drainChildren`。安装包内部 manager 有 `drainChildren`，不能把内部方法误当公开服务。旧假宿主模拟了相同错误名称，因此原绿测不能证明当前宿主实际可派发。

## 本轮实现

新增 `lib/host-execution.js` 作为公共宿主适配单源，创建/消息/释放/中断与预检都在这里；actions 原中文 helpers 保留为薄代理。共享成员派发计划也直接消费同一预检与模型路由判据。

只认已经核实的公共 `startContinuable/sendMessage/drainContinuableChildren`，缺能力在创建前拒绝，不调用内部 manager、不回落 one-shot。子会话创建需 childId 与初始 messageId 双凭据；消息投递需 messageId，缺回执为 unknown、禁止盲重试。

受管子会话退役使用公开释放方法，报告 `当前驻留已释放:true`，同时保持 `已停:null / 持久子会话已删除:false`。普通 member_stop 只报告 `已请求中断:true / 已停:null`。Team 本机没有已安装公共包可独立证明其终局停止合同，沿已有 interrupt 请求合同报告，不把请求说成已停止。

原测试改为实际公开方法形状；既有待命、登记、绑定、判据冻结、审批一次性、精确 owned 补偿集合、错误合并等业务断言保留。会审退役的精确实例集合从 interrupt 请求集合改为实际 release 调用集合，没有减弱为只验计数或忽略失败。
