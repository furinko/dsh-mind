# 知识查询快照与投影

日期：2026-10-21。承接[知识负反馈与处置关联](知识负反馈与处置关联-2026-10-21.md)。本轮把单次治理知识查询的反复扫描收敛为请求内共享快照，不引入跨请求缓存、知识权限或验证状态。

## 当前问题与实证

原治理查询先按每16个知识id调用来源核验，再按每16个负反馈调用处置观察。两者各自枚举知识scope、读完整字节、严格解析、折叠及结束重读；K个知识、F个负反馈、S本知识账，约需 `2S×(ceil(K/16)+ceil(F/16))` 次知识文件读取，解析与fold同样随批数增长。同一知识重复交卷会让F远大K，增加读取量而没有增加真源。

旧实现只保证各子调用自身读取期间文件未变，不能保证整个治理查询的早批结果仍可公开。隔离Org内联夹具已经实际复现：17个来源第二批前真实purge第一个来源，或撤generic来源read，查询仍返回第一批旧hash；处置读取前撤task read或真实封存Lead，查询仍返回原任务声明与旧hash。这是本轮结束复核的目标，不把局部成功当成整次查询一致。

## 只活一轮的读frame

内部 `withKnowledgeReadSnapshot({subject,项目}, async reader => T)` 返回 `{有效:true,结果:T}` 或 `{有效:false,结果:null}`。callback异常原样抛出，finally关闭reader；成功、失败和异常之后都不能复用旧reader。接口没有模型动作或可自报snapshot参数。

reader保留 `readKnowledgeEvidence` 与 `readFeedbackDispositions` 旧签名并固定主体、项目，通过内部Symbol委托当前服务的旧方法，保留override故障接缝。初次真正需要知识时懒加载一次：记录完整scope集合和各本原始字节，严格解析、fold并建立投影索引。未核来源与不可核对处置仍分开，不能因为共享快照就把默认有效来源资格套在失效后的处置历史上。

请求内使用同一时刻计算期限资格。结束复核scope集合、完整字节、当前身份/卡/健康策略、generic来源read以及实际涉及的逐源和替代知识read；资格跨期限或任何观察漂移使整组失效，不把早批旧hash与晚批unknown拼起来。scope新增也需检出，不能只比较初读时已经存在的文件，不能用mtime/size相同代替字节核对。

失效frame只把来源统一未核验、处置统一不可核对，不洗掉仍有读权的任务声明和分母。外层治理查询另在memory收尾后复核治理身份、task真源与每个task read；当前任务声明本身已不可读时须拒绝或重新裁剪完整读面，不能仅隐藏hash继续回传原声明。无读者摘要不冒充主权者，也不签来源或处置。

## 保持的合同

旧普通成员、真实复核对象与任务交卷的来源观察权限保持，不能为共用代码而一律套仅Lead/主权者的处置资格。公共fold继续剥私有反馈关联；原始行只在内部匹配，legacy提交展示序号不冒充显式seq，SUBMITTED_SOURCE定位保留。未知与不可核对不伪报未处理或纠错成功。

返回Map与响应裁剪不回写快照对象。40k分页、完整分母、最近处置截断和数据版本仍按原读面收口；新捕获时间不进入稳定数据版本。下一次请求必须重新取得时刻、scope与原文；本轮不优化成跨请求缓存。

## 任务投影共用同一次扫描

`fold(rows,visitor)` 仅增加内部同步访问者：每个原始位置访问一次，before/after共用原有待采纳派生helper，不重新实现一套任务状态规则。`createKnowledgeFeedbackResolver({rows,项目,visit})` 返回 `{nodes,resolve}`，在同次扫描中建立显式seq的全账计数、提交前代与原文摘要，resolve继续精确核唯一序号、指定任务和原负面声明。

治理投影在同一visit生成提交/采纳关联，最新提交按“任务→作者Map”分组，处理采纳时只访问该任务的作者，不扫描整个项目的所有作者。原位置仍用于legacy展示与SUBMITTED_SOURCE内部来源定位，不能把展示fallback变成新反馈的显式凭据。

这些都是单次读取内可重建的内存索引，不新建持久索引，不更改task ledger。现有fold复制和累积答案/讨论等历史数组的成本仍存在；减少前缀重复fold及跨任务作者扫描，不等于证明整个任务系统或所有历史处理严格线性。验收应分别统计本次解析/访问工作量，避免以更快机器上的毫秒结果替代结构证据。

结束复核仍是有限观察窗口，不是任务、记忆和权限账本的全局原子事务，也不证明返回后权限或来源不再变化。本轮没有共享写锁、自动重试、修复坏账或补签来源。

## 独立验收口径

2026-10-21 在开发目录实际执行：

```text
node --test test/knowledge-observation-adversarial-2026-10-21.test.js
tests 13 / pass 13 / fail 0 / cancelled 0 / skipped 0
duration_ms 15800.2843
```

独立文件固化晚批真实purge与来源read收紧、处置子调用返回后的purge、逐源与替代知识read撤回、无文件字节/mtime变化的请求内到期、晚批撕裂等反例，均核整组unknown且合法任务声明/分母保留。另核callback原异常传播、reader完成或异常后关闭、主体/项目固定、并发frame隔离、初读不存在的项目scope出现、返回Map副本及未跨资格边界的时间推进不误杀。外层task read/治理身份/task追加的末尾复验由根集成反例覆盖，不与单独来源失败混为一类。

性能以真实知识文件read次数及真实知识行解析次数验收，不设毫秒阈值。完整13项通过后仅为输出具体读数重跑结构计数项：

```text
node --test --test-name-pattern='17知识与68负项' test/knowledge-observation-adversarial-2026-10-21.test.js
tests 1 / pass 1 / fail 0
知识=17，负项=68，纳入知识账本=2
首请求知识文件read=4，知识行parse=17
次请求知识文件read=4，知识行parse=17
```

因此本夹具每请求各读S次初始字节与S次结束比对，每条知识行只解析一次，不随来源/反馈批数增加；第二请求重新读取和解析。read统计包含对应缺文件的读取尝试，只覆盖隔离知识文件路径；原始readFile与JSON.parse钩在finally恢复，不把身份卡/策略读取或整体运行时间混作知识扫描收益。该例是可重跑的结构证据，不宣称所有项目固定4次文件读取，或整个系统不存在其他账本成本。

已有反例继续复用：知识采用独立文件的完整长正文hash、真实复核域、坏JSON/撕裂、当前来源read与零额外审计；知识适用说明文件的无文件变更跨期限、旧metadatahash稳定与新说明入hash；知识反馈文件的失效/due仍见处置、purge/坏账匿名未知、替代id独立读域、无引用不猜关联、40k分页和单条极限回执。
