## 2 可实施的最小实时合同

采用 `ctx.on('agent/assistant-stream', payload => observe(payload))`。这是 emit 观察事件，不存在要显式返回的 next，也不能据返回值 veto 模型请求。`dsh-agent/lib/index.js:221–229` 对同步抛错及返回 Promise 拒绝均只告警，宿主不等待观察持久化。

| 帧 | 精确字段 | 记录含义 |
|---|---|---|
| start | attemptId、revision、turn、step | loop 已准备开始消费本次模型流；不证明远端接受、生成或计费 |
| chunk | attemptId、revision、index、time、chunk | index 为本尝试从0递增的原始流块位置；time 为 loop 接收块时的墙钟 |
| end | attemptId、revision、index、outcome | index 为已发布 chunk 数；outcome 是 committed 的事件类型/seq，或 abandoned |

`attemptId` **仅在一个真实 Agent 生命周期内唯一**。实现 `agent-loop/lib/index.js:389` 生成 `${sessionId}:${attempt}`，749–750 的 attempt/revision 计数每个新 Agent 从0开始；同 session 被新 Agent 接续时编号会重用。不能持久用 `(sessionId, attemptId)` 去重掉新工作。

本轮最小方案为：服务私有 WeakMap 以真实 Agent 对象分配随机生命周期 UUID，再按该生命周期的 attemptId 识别尝试，另给每个持久观察分配服务生成的执行键。相同对象的重复帧不重复入账；新 Agent 对象即便复用 session/attemptId，仍是新的观察尝试。模型参数、自报角色、文本来源、sessionId 字符串都不能生成这只身份凭据。

### 2.1 当前分发链中的 Agent 对象身份

可读安装实现支持这个 WeakMap 前提，依据是当前分发链保留嵌套对象引用，而不是假设 Cordis 的所有 trace 代理有身份缓存：

1. `dsh-agent-loop/lib/index.js:760` 在 `ReactLoopAgent` 构造期间执行 `this.dispatch = agentEvents(loopCtx, this)`，原始 `this` 只闭包一次；1031–1032 的模型流回调持续使用该 dispatcher。
2. `dsh-agent/lib/index.js:209–220` 每次只创建 `{...payload, agent}`，将闭包内同一 Agent 作为字段注入；传给 `ctx.events.dispatch` 的普通 payload 自身没有 tracker。
3. `cordis/lib/index.js:258–264` 仅移除 carrier/name、筛选监听者并绑定调用 this，没有映射或克隆 payload 字段。370–376 的 `on` 用 `reflect.bind` 包住监听者；917–920 只对 this 和每一个**顶层参数**调用 trace。
4. `cordis/lib/index.js:84–89` 对没有 `symbols.tracker` 的普通 payload 直接返回原对象，不递归 trace `payload.agent`。因此当前内建流的 start/chunk/end 传到观察 hook 时，其 Agent 仍是构造时闭包中的同一对象。

`cordis/lib/index.js:123–157` 的 `createTraceable` 每次 `new Proxy`，这里未发现代理缓存；不能推广为“从任何服务或上下文取得的 Agent 代理都保持相同身份”。当前方案只依赖上述 assistant-stream payload 路径。可读的 `dsh-scope/lib/invariant.js:9、59–64` 另外要求流事件 carrier key 与 payload.agent 严格相等；这是分发不变式核验，不是代理身份缓存证明。

`dsh-scope/lib/index.js` 与其公共类型文件仍被环境拒绝读取，本次未绕过访问限制；未验证其内部实现，也未创建真实 Agent 进行端到端对象相等测试。上述结论限于已读的内建 loop/dispatch/Cordis 链；其他插件若主动修改事件 payload、将来分发改为递归 trace，须重新核查，不能用 sessionId 字符串补造对象身份。

revision 在同一 Agent 的**所有帧**间单调，不是一个 attempt 的固定版本号；不可把重复 start、乱序 chunk 或较低 revision 当成新样本。chunk.index 与 end.index 另有本尝试的密集顺序约束。时间不承担顺序：`Date.now()` 可以回拨，不能按 time 排序覆盖最后样本。

有界内存不能删除去重信息后又接受旧 start。可以用真实 Agent 生命周期的最高 revision 阻止旧帧重新成为新尝试，活跃/最近尝试索引另作有界保留。超界、孤立帧、乱序和无效计量应计入观察健康缺口，不能阻断模型或伪补正文、开始、结束事实。

## 3 用量是快照，缺失是未知

`dsh-llm/lib/index.js:942–943` 对 usage 执行赋值，后一个样本替换前一个。一次尝试应保存最后一个已验证 usage，不能把流中的累计样本逐个相加，也不能与 session 中重复出现的同一流再相加。

公开 TokenUsage 有必需 inputTokens、outputTokens，以及可选 totalTokens、cacheReadTokens、cacheWriteTokens、reasoningTokens，没有费用或币种。

- inputTokens 是未缓存输入；缓存读、缓存写另列，不能将它们再叠加到提供方 totalTokens。
- reasoningTokens 是额外分类信息，不能再加到 outputTokens 造出更大的输出总数。
- 没有 usage 时保持 null；可选字段未报告时保留未报告状态，不用猜测值补出完整计量。
- 可验证的数值应为有限、非负、可安全表示的整数；非法、冲突或撕裂样本不能污染已有合法计量。
- 聚合应标为“已报告用量小计”，并单列有报告次数、未报告次数和未结束次数；不能将已知小计包装为整个目标的完整 token 或费用。

帧包含的正文、推理文本、工具参数和消息内容不属于本轮计量，不能随 canonical(frame) 或调试记录进入持久账本。仅白名单保存身份/归因、计量数值、枚举终止标记及必要来源位置。

## 4 失败、结束与提交不能代替成功

`agent-loop/lib/index.js:1036–1046` 先取得流，再发布 start。发布前就失败或取消的请求可能没有 start 观察；不能因此声称该类工作为0或完整覆盖所有模型调用。

开始后的异常和取消分别在 1050–1087 保存 assistant/message 或 assistant/attempt：

- 取消时已有可见前缀，仍可 committed 为 assistant/message，并带 interrupted:true。
- 没有表面消息、流异常、失败或将重试的尝试，committed 为 assistant/attempt，仍可能含真实上报的 usage。
- max-tokens 在 1108–1115 也先提交 assistant/message；提交消息不表示按要求完成。
- session.append 失败会由 422–451 发布 abandoned。之前已经观察到的 usage 必须保留；abandoned 不代表未消耗。
- 没有 end 的尝试保持未结束；不能通过实例封存、会话关闭、进程重启或超时补成成功、失败或零消耗。

finish chunk 的 `reason` 是 `{kind: ...}` 对象，不是字符串；最小观察仅保存已知 kind（stop/tool-calls/max-tokens/error/aborted），不持久保存 failure 的原始错误正文。缺失 finish 不猜 stop。end/message 均不代表任务采纳、目标完成或宿主已停止。

committed end 只证明观察到宿主给出的 session 事件位置。本轮不回读核验该事件，也不将 end 解释为持久化后端已完成 flush；`dsh-session/lib/types/index.d.ts:64–71` 另有被等待的 session/flush 检查点。

## 5 配置路由提示与当次请求路由

start/chunk/end 均没有 provider/model 字段。Agent.options 提供的是实例配置提示；`agent-loop/lib/index.js:1143–1154` 的 agent/request 瀑布和 prepareCall 可以为当次解析别的配置，不能把初始 options 说成当次模型。

宿主在 live.start 前通过 1176–1201 记录 request/header 和 request/context，当次请求由 1211–1217 构建。未来若读取这些真源，可标为“宿主记录的本次请求路由”。即便如此，`dsh-llm/lib/index.js:2307` 的 llm/stream 瀑布允许插件短路流；message.source 的 provider/model 也是从 request 复制，不能证明远端实际服务或计费模型。

本轮不新增 requestHeader 读取依赖，provider/model 仅保留在明确命名的“配置路由”内，来源标为 Agent.options 提示，缺席为 null。费用一直为 null，不据模型名称补价格或声称账单核验。

## 6 归因冻结与持久重建边界

start 时读取真实成员/父 Lead 凭证、当前项目与本人活动任务绑定。全部有效活动绑定属于同一目标才归到该目标；混有未关联任务或多个目标时不猜分账。复核员可以经其本人的关联任务归因；会审当前保留未知。Lead 没有可信的本次目标归属，仍作为未知目标观察。

归因在 start 冻结：后来补绑定、换任务、改目标进展或身份失效不能把旧尝试重签到新目标。当前身份失效的开始仍可记录为未知归因；同一已开始尝试的迟到帧不因旧授权失效而被删除。会话或项目漂移应拒绝污染原尝试，并标观察异常。

session 的两类最终事件嵌入准确的 compact stream；未来可以据 session 事件序号和已验证流做独立重建，不能靠 derivedMessages() 丢掉 assistant/attempt。`dsh-session/lib/types/index.d.ts:178–198` 还区分 eventAt、snapshotEvents 与 fork 的 ownEvents，导入时必须避免父历史被子会话再算一次。

本轮只接进程内 assistant-stream，不实现 session 历史导入或跨进程补账。重启后既有观察事实可由 Mind 自己的账本重建，但此前未采集的模型用量仍未知；live 重放与历史补采没有被暗中假定为已完成。
