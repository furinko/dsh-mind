# 知识采用声明与反馈

日期：2026-10-21。本轮新增的是交卷人的知识使用声明，以及可追溯的提交/采纳关联；不把读取次数当采用、不把采纳当语义正确或收益，也不自动改变知识状态、排名、权限或目标完成。

本次工作只在 `dsh-mind-dev` 实现和验证。保留第六、七轮候选；不改运行链接目录，不启动真实 Agent 或调用模型。

## 1 当前实现决定的边界

`src/tasks.js` 的 submitted 事件按真实 `row.by.id` 保存独立答案；同人复交替换当前投影中自己的答案，原事件仍在账本。采用知识完整封套只留 submitted 原事件，普通任务投影仅增加提交序与代，不把封套放入 `node.独立答案`。因此 task_submit/task_pending 等合法任务回执也不会夹带历史来源 hash 或他人的声明。打回关闭当前代；正式后继是新节点，不能继承新人的采用声明。

复核票是 `rv-<reviewed事件序号>`。fold 中的“最近改成果序”使新 submitted 事件之后的旧票失效。accepted 事件保存本代、采纳人、票或豁免及交付物摘要，不逐一保存答案提交序号；需要在 accepted 前缀重建当时每人的最后 submitted 来关联。不能把后来答案接到历史采纳上。现有 artifact manifest 绑定文件/对象内容，不自动覆盖采用声明的语义。

`src/memory.js` 的 query 负责策略 read、当前项目、可选岗位过滤、归档作答、有效状态与响应预算；复核员显式读域由共享 `review-scope` 从同项目真实任务推导。岗位参数是可选检索过滤，不是默认本岗授权边界。内部调用不能只传 subject/id 就声称复用了完整模型读域。

记忆原查询会跳过坏 JSON 并告警。若坏行实际是失效、隔离或 purge 状态，剩余条目不能作为“当前来源版本已核”的证据。本轮来源捕获须新鲜严格读字节；坏行或撕裂不阻止合法交卷，但不能给来源签有效版本。

## 2 提交字段与诚实含义

`task_submit` 可选 `采用知识`，每项只接受 `id、用途、适用判断、使用结果、说明?`。使用结果只有“有帮助 / 不适用 / 发现问题 / 未知”；最多16项，id最多256字符、用途/适用判断各512字符、说明最多1024字符。同次重复id拒绝，不静默去重或改变效果声明。

- 省略整个字段：未说明，采用情况未知；旧提交不回填。
- 显式 `[]`：明确没有声明采用条目；不把它改写成“确定没有使用任何知识”。
- 非空数组：这些都是交卷人声明，来源版本能核对不认证用途、适用判断或效果。
- 模型不能传主体、代、已核验、hash、捕获时间或来源认证字段。结构不合法先拒，不能在提交后静默丢字段。

规范存储为：

```text
采用知识 = {
  版本: 1,
  声明状态: '显式空' | '已声明',
  条目: [{
    id, 用途, 适用判断, 使用结果, 说明?,
    来源: {状态:'可核来源版本', 内容哈希, 元数据哈希, 捕获于}
        | {状态:'来源未核验'}
  }]
}
```

提交事件自己保存真实本人、当前代与序号，来源只保存哈希，不复制正文进任务账本。采用字段应在首个 await 前规范化并深拷贝；不能让排队期间可变入参迁移声明。捕获是一次批量内部读取，不为每个 id 新增独立审批或多次查询审计。

## 3 来源读取与失败降级

`MemoryService.readKnowledgeEvidence({subject,项目,ids})` 复用共享服务器读域。真实主体及岗位来自当前身份/卡/策略；复核员沿同项目关联任务的显式复核对象裁剪。项目由受管任务或治理读入口提供，声明字段不能另报项目归属、读域或认证。只核“知识”，不借采用字段读取偏好、经历或归档作答。

来源 id 不存在、不可读、已 purge、账本损坏、内容/元数据不可完整核对，均保存同一 `{状态:'来源未核验'}`。不返回区分原因、标题、来源路径、错误正文或存在性提示。来源失败不能把本来合法的交卷变成死路。

可核来源使用完整条目正文和白名单元数据计算摘要，不用 `memory_query` 已截断摘要、全文分页片段、任意对象序列化或模型给出的 hash。捕获到可读版本不证明交卷人实际采用了该版，更不认证元数据里的来源声明。默认当前有效视图继续生效；显式反馈“不适用”或“发现问题”不授予读取已撤回内容的特权。

TaskGraph 仍遵守 goal→task 锁序；来源捕获不反向获取任务锁。没有与记忆 purge 建立跨账本事务，因此 hash 只标识捕获时观察到的可核版本，不能宣称任务提交瞬间或未来该来源仍有效。当前任务继续提交，不靠自动恢复来源来配合它。

## 4 只读反馈查询

首版只向当前真实 Lead（在岗、卡凭证健康、策略 read）或主权者开放；普通成员、复核员、会审均拒绝该汇总入口。知识对某成员可读，不等于别人的任务、提交人、用途、判断与负反馈对他可读。

查询参数为 `subject、项目、任务?、知识id?、条数?、偏移?、数据版本?`，不接受反馈写入或补签。先按每个任务当前 read 裁剪，再做知识筛选；返回逐提交投影及该可见集的完整分母，不展开结论、产物正文、讨论或任务书。默认20条、最多50条，每条采用的用途/判断/说明各截160字符并标字段截断；关联采纳只回最近5条并给总数。JSON响应最多40000字符，实际返回条目数、下一偏移与hasMore按预算真正放入的条目计算。非首页必须带数据版本，任务事件或当前来源/权限变化时拒旧版本，不能拼接旧 hash 和新权限。

关联采纳从同一任务事件前缀重建：沿当时的票/豁免、依据、当前代及交付物摘要核对关系，只关联当时本代每个提交者的最后一次 submitted，投影采纳序、时间与代。不能仅因 fold 的 accepted 分支把节点投影成已采纳就建立关联。代或证据不足的 legacy 保留未知，不根据当前任务已采纳状态给所有历史声明盖章。返工前的声明、同人旧提交和后继保持原归属。

这是历史记录及引用关系核验，不是逐事件重放当年的完整权限环境，也不证明整个账本没有遭到合法 JSON 形式的协同伪造、删除或回滚。查询不会用当前免审设置补造过去的授权，更不会把历史采纳升格为知识语义认证。

查询时再次核当前知识真源及读域。来源现在不可读时剥去历史 hash 和元数据，不泄漏不可见原因；历史本人声明仍只是治理读域内的任务声明。来源可读时保留提交时封套，另以“同一观察版本 / 版本已变 / 捕获未核验”和当前hash区分，不把本次新采集时间加入稳定分页版本，也不把旧 hash 伪装成现行知识。
