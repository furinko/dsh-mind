# 知识适用条件与复验期限

日期：2026-10-21。承接[知识采用声明与反馈](知识采用声明与反馈-2026-10-21.md)。本轮为知识增加作者适用说明和可选的显式复验期限，不引入自动复验、成功认证或完整验证状态机。

工作仅在开发目录进行。运行链接目录不改，不调用真实模型或启动成员；候选功能通过隔离服务与动作反例验证后交由主代理统一验收。

## 作者字段与派生资格

`memory_write` 可选 `知识说明`，只用于知识类：

```text
知识说明 = {
  适用条件?: string[1..16],
  已知反例?: string[1..16],
  复验条件?: string[1..16],
  复验期限?: canonical UTC ISO
}
```

每条文本1至512字符，至少一个属性；null、空对象、空数组、未知键、自报验证状态和非法时间拒绝。UTC时间接受标准秒Z或毫秒Z，拒绝无时区、本地偏移和日期溢出。字段在异步步骤前深拷贝，不因调用方事后改数组而改变本次写入。

正文仍承载知识主张；三组说明均为作者陈述，不代表系统已验证这些条件或反例。旧知识省略字段，不回填说明。没有期限称“未设期限”，不称“永远有效”；有期限且尚未到期称“期限内”，也不证明语义正确。

只有明确期限且当前时钟大于等于它，才派生“待复验”。派生不追加失效状态、不修改原始账本、不撤销任务、复核票或目标，也不触发后台模型执行。已有但非法说明为“说明不可判”，不能静默当成未设期限。

## 检索与来源的同一边界

默认 `memory_query` 排除待复验或说明不可判的知识。显式 `含待复验:true` 只放宽这个筛选，仍与当前项目、真实复核对象读域、归档与失效过滤取交集；不会因为请求了待复验而得到其他项目、别的复核对象或已隔离正文。

列表、文本检索、id详情和全文续页共用同一资格函数。摘要应有可理解的作者说明、期限和派生状态；大说明与来源等元数据都计入现有响应预算。首条超预算时先试完整元数据、至少一个完整Unicode码点和最终分页标记，能容纳就只分页正文；不能因为正文很长就永久丢掉原本可读全的条件。无法同时容纳最小正文时才明确缩减元数据，不能把截断的适用条件当作完整条件。最大32000字符内容预算可读取三组各16条、每条512字符的完整说明，并在同一数据版本下续读长正文。

全文详情只要还有正文，成功续页就必须推进正文偏移，不能返回空正文和原偏移让调用方无限重试。缩减后仍无法容纳一个完整码点时，明确返回 `MEMORY_RESPONSE_NO_PROGRESS` 并提示提高内容预算。分页边界继续保持UTF-16代理对完整；空正文或已到正文末尾的正常详情不触发此错误。

单次查询固定使用同一时刻，整个过滤和读数不跨两个“现在”。索引与数据版本依赖最终资格集合及稳定派生状态，时间越过期限但文件完全未变也必须失效；只过了一秒而没有越过资格边界，则旧分页仍可继续。原有含状态基数、最终可召回数、待复验数和实际排除数分别报告。

`readKnowledgeEvidence` 使用默认有效视图，待复验或说明不可判均为统一“来源未核验”；声明用途和实际交卷继续合法，不因知识来源需复验而卡住任务。新说明存在时计入完整元数据hash；旧知识没有该字段时维持原hash算法，不能无修改地把历史捕获都标成“版本已变”。

## 写入、晋升、删除

通用知识直写和跨项目晋升把说明文本一并纳入既有披露扫描，防止条件或反例成为绕过正文检查的附带正文。若新说明让检查面超出现有扫描上限，尾部未全检必须按既有规则拒绝或走已有明确豁免，不把未检尾部当作干净文本。

受限晋升和结账晋升透传显式说明，并把它纳入同一幂等业务比较。对象比较用规范序列化，不能把两个不同对象都变成 `[object Object]` 后静默认回旧产物。跨项目副本保留说明原文，派生的“待复验”等状态不落入新账本行。

purge 继续按真实id抹除源与所有跨项目副本的完整条目行，条件、反例、期限随正文一起删除；不可逆审计、状态记录、任务采用回执不能复制说明正文，避免删除后从只增记录取回。既有来源血缘仍保留标识及删除事实。

推翻旧主张并写新正文不自动继承旧适用说明。复验之后可以在原有权限内写新知识并保留来源，但“新写了一条”不能当作“已经复验成功”。本轮没有跳过权限、清空期限或人工补签验证状态的新增入口。
