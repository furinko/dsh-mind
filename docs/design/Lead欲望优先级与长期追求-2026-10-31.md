## 1 从想法到可持续的追求

瞬时念头仍可放在原情绪记录的 `desires` 文字中。值得持续的愿望显式进入 `LeadDesireService`：名称、想做的理由、满足判据、有限/持续类型、重要性、投入意愿、下一步及可执行活动。没有默认植入的愿望，不要求每次交流或休息生成追求。

正常对话通过 `lead_desire_update` 建立、调整和评价追求。原自由活动的同一次模型请求也可选填 `aspiration`，形成新的自身愿望，留待未来机会继续；不增加模型请求。由项目私人追求产生的新愿望继承项目范围，不能自动扩大到其他项目；纯公共自身自由活动形成的愿望保存在当前关系内。

持久状态在原核心人设目录旁的 `情绪与动机/追求.json`，独立版本1，不改旧情绪文件。各窗口共享记录；`scope=project` 限当前项目和关系，明确的 `scope=relationship` 允许同一关系跨项目延续自身兴趣。不同关系隔离，专业成员不可读。人侧可查看全部范围。

## 2 独立排序

每次查询重算：

```
need = 1 - 当前满足度
waiting = min(1, 距上次实际尝试的天数 / 7)
score = importance × (0.5 + 0.5 × commitment) × need
        × (0.8 + 0.2 × waiting) × (1 - 0.5 × frustration)
```

因子和结果均可查询，重要性、投入意愿、满足度、进度及受阻程度为0至1；等待增益有上限，不会因搁置无限加码。暂停、结束、人侧停止和整体停用不参与执行；冷却期、已有在途活动、当前较满足或没有相应材料时会给出不可执行原因。空闲活动选择得分最高且实际可执行的一项，不把无材料的阅读愿望堵在可执行的写作前。

这只决定个人自由活动的取舍，不替代用户任务的优先级，不创建正式任务、任意命令、发布或消息。

## 3 满足、受挫与证据

评价分为 `progress/fulfilled/setback/no-change`，明确填写满足度、进度、反思及下一步。当前会话评价由宿主关联真实会话位置；随笔评价核对实际id、版本与正文指纹；活动评价引用实际检查点。它们是可修正自评，不认证用户态度、外部任务完成或技能掌握。实际活动回执和对活动的评价分开存放。

同一依据的重复反馈不重复计入；版本冲突拒绝覆盖。随笔已改动/删除、阅读来源已撤回或尚未完成时，不能拿旧回执宣称满足。

有限追求 `finite` 在满足后进入 `fulfilled`，不会因时间经过自动恢复。持续兴趣 `ongoing` 满足后仍保留，满足度按 `satisfaction × 2^(-经过小时/renewalHours)` 逐渐下降，需求可以再次出现；恢复半衰期默认72小时，可设6至720小时。周期完成数是自评历史，不是能力认证。情绪仍由原情绪服务表达，不把每次产物存在硬编码成同一种感受。

受挫每次增加0.25受阻程度（最高1），并按连续次数退避2、4、8小时，最长168小时；成功评价降低受阻程度。前台工作打断只记录中断，不制造受挫。休息或暂缓不虚增满足度。人侧暂停和放下不能由模型自行恢复；人侧对描述和取舍的修订受保护，实际活动仍可更新下一步及进展。

## 4 长期追求如何实际接续

沿原自由时光开关、时段、每日4次准入和每段最多2次请求执行，无新后台模型、无新调度器。未开启自由时光时，只在正常会话中延续。任一前台回合会让自由活动等待或中断，不抢占当前工作。

每次先认领一项实际可执行的追求，持久保存代次、版本和有期限的认领凭据；模型取得满足判据、下一步及上次真实产物。它可以读、写或休息。追求相关创作保存到当前项目与关系，私人愿望不进入公共自身草稿；阅读仍限原可用公开材料并沿原来源和预算约束。

首次写作/阅读完成只留下真实回执，不自动宣称满足。下一次活动可以回读实际随笔或已完成阅读回执，并在原选择请求里返回 `review` 评价上一次；评价仅允许本次提供且仍可用的检查点。若评价已经满足，本次休息，有限追求结束，持续兴趣暂时平息。正常对话也可以直接按真实回执评价，无需等下一个时段。

写随笔前保存确定性活动标记，相同活动只生成同一份随笔。阅读前保存真实学习操作id。中途退出后，下一次认领只通过实际文件/学习完成回执恢复检查点；准备过但没有产物的记为中断，未知调用不猜成功、不自动重放、不返还原请求预算。人侧修订、清空、关系变化和旧认领失效会阻止迟到输出。已经保存的独立随笔不因追求清空被删除，也不因迟到的计量失败重做。

`mind:lead-desires` 每步提供最多4项当前追求及2项近七天已满足的回顾，JSON至多8000字符；回顾不是待办。更正、暂停、删除与清空后旧自动快照退出，不能沿旧快照恢复愿望。背景已完成的经历可在下一次正常对话自然带回，不强制逐项汇报。

## 5 操作与人侧界面

`lead_desire_query`：`欲望={id?,offset?,limit?,includeInactive?}`，默认20、最大64，先按范围筛选再排序分页。

`lead_desire_update`：

| op | 入参 |
|---|---|
| create | `epoch,key,scope?,content` |
| revise | `epoch,id,revision,reason,content` |
| state | `epoch,id,revision,reason,status=active/paused/released` |
| feedback | `epoch,id,revision,evaluation,evidence` |
| remove | `epoch,id,revision,reason` |

`content={title,reason,criterion,kind:finite/ongoing,importance,commitment,activities:[read/write/rest],nextStep,renewalHours?}`。`evaluation={outcome,satisfaction,progress,reflection,nextStep}`，fulfilled的满足度和进度须均为1。`evidence` 为 `{kind:conversation}`、`{kind:note,id,revision,hash}` 或 `{kind:activity,id}`。

所有写入沿现行身份、策略、锁和完整冻结审批，不另授权限。模型没有整体开关或清空入口。状态最多64项追求、256个撤回屏障、512个反馈幂等标记，每项保存最近8条活动/评价，文件最多256KiB；超限明确要求维护，不静默覆盖或把旧记录当新记录重算。

认证同源端点 `/plugins/dsh-mind/lead-desires`：GET分页读取全部范围；POST仅维护已有追求，支持上述修订/状态/反馈/删除，以及人侧 `{op:configure,expectedRevision,enabled}`、`{op:clear,expectedRevision}`。清空增加epoch，阻止旧请求恢复；人侧显式恢复已结束追求会重新打开需求，保留历史，不由模型自动复活。

设置 → 心智 → 个性与成长新增「愿望与长期追求」：查看排序原因、满足与进展、下一步及近期活动；可调整描述/取舍、暂停、恢复、放下、删除、整体启停及明确清空。保存后回读核对，冲突保留草稿，重复点击不重复写，坏响应不显示保存成功。整体追求开关与原自由时光安排分开，不能借开启追求自行开启后台活动。
