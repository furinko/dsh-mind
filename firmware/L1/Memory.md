## 一、记忆层三区边界

| 区 | 定位 | 生命周期 | 修改规则 |
|---|---|---|---|
| **common** | 通用结晶知识（踩坑沉淀/设计/速查），跨项目可调取 | 持续积累 | 增量覆写，删除须用户确认 |
| **projects** | 项目记忆（每个项目一个目录：导航 project.md + 记忆档案 + 知识\ 结晶） | 项目周期内 | 收工更新，完结归档 history |
| **history** | 项目闭包/旧版归档 | 永久 | 只写不改，入库即定稿 |

**存储位置**：实际内容一律在 `mind-private\L3\`（隐私，永不推送），下含 `common\`、`projects\`、`history\` 三区。`mind\L3\` 只保留模板与出厂示例。

**项目隔离（记忆层重构 2026-09-09）**：从 frontmatter `project` 字段过滤改为**物理目录隔离**——检索候选 = `L3\common\`（恒含）+ `L3\projects\<当前项目>\`（仅当前项目）；其它项目目录不扫描 → 结构上不串。

## 二、common 规则（通用结晶）

### 文件命名
`YYYY-MM-DD_描述.md`（迁移记忆可保留原名）

### 覆写规则
- 已有文件：**增量覆写**（保留原有信息追加），不追加补充文件
- 层级结构调整（重组章节/改分类）须用户确认
- 错误更正：原文修正，文件头标注 `(YYYY-MM-DD 修正)`

### 新建规则
1. 轮级缓冲写草稿 → 2. 按 §八 溯源门禁判定（有源直落 / 无源标 verified:false / 敏感·拿不准 → pending 等用户裁决）→ 3. 判断归属：**跨项目通用 → 写 `mind-private\L3\common\<主题>\`；项目专属 → 写 `mind-private\L3\projects\<项目>\知识\<主题>\`** → 4. 更新该目录 `_index.md` → 5. 更新 Tree.md

### 归属判据：看"可复用边界"，不看出处（2026-09-09）
> 一条记忆放哪个区，由**换项目还有没有用**决定，不由"从哪个项目踩的"决定。混载文件按主体归区，不搞条目级混区：
- **方法论/工具坑/通用规则**（换项目仍适用——如 Inno 转义、subprocess 编码、Windows 锁目录）→ **common**（即使是从 DSHOME 干活踩出来的）。
- **项目事件/决策/状态留档**（某日在某项目发生了什么、定了什么）→ **projects\<项目>**。
- **文件混载 + 主体通用** → 整个进 common；文件内的项目事件细节截断或另立项目事件档案。
- **文件混载 + 主体是项目 + 夹带通用教训** → 文件进项目区；**通用教训蒸馏复制到 common lessons（措辞不同：项目区=事件版带日期，common=规则版不带项目上下文）**——蒸馏≠备份，两版粒度不同、不构成重复。
- 蒸馏迁移后原文件保留事件记录（不删），项目区事件可留指针指回 common 规则版（related）。

### 删除规则
- 仅用户明确说"删除 xxx"时执行；删除前确认是否被引用

## 三、history 规则

- 命名：`YYYY-MM-DD_第{n}季_{标题}_全文留档.md`（或 `YYYY-MM-DD_<标题>_归档.md`）
- **只写不改**——时间是单向的；更正追加新记录，不修改已归档文件
- 每个子目录维护 `_index.md`：`| 日期 | 文件 | 类型 | 摘要 |`

## 四、projects 规则（项目记忆区）

> **定位**：`L3\projects\<项目名>\` = 项目记忆之家——导航 project.md（必需）+ 记忆档案（按需）+ 知识\ 子区（项目专属结晶）。
> **划界原则（2026-09-09）**：会动的资产（代码/数据/产物/工作区文档）跟项目工作区走；需续接的记忆（状态钟/操作史/决策/废止链/教训）跟心智走。项目工作区已有自建记忆文档 → **询问用户是否植入心智**；没有 → project.md 承担状态续接。
> **植入询问 + 防漂移铁律（2026-09-09）**：发现项目工作区有内置记忆文档 → **先询问用户：移植进心智 or 留在工作区**，不默认收编。两案皆须**单一真源**，另一方只留指针、不存内容副本：
> - **A 移植**：记忆档案入 `L3\projects\<项目>\` 成唯一真源，工作区原文件删除/指针化；自维护机制（如管线记忆红线 13「每轮完成必更新」）更新对象改为心智档案；档案内相对路径头注"以工作区为锚"（记忆只描述资产，不复制资产）。
> - **B 不移植**：心智不复制任何内容；project.md 强制依赖表登记"权威源 = 工作区文件"，上工直读真源；项目知识区只收"曾经发生"的教训结晶（call_api 返回值类），不收现行状态/译名值（会漂）。

### 目录结构

### 收工更新

## 五、蒸馏沉淀规则（L2→记忆区）

- **触发**：L2 Exp/Skill 踩坑 ≥3 条且同主题
- **计数认领（B1 闭环 2026-09-05）**：谁数——智能体自己；何时数——**收工 step8 机制体检**（本机启用自治任务时，其巡检同样是采集点；见 `mind\L1\Ritual.md` §一 step8 / §二），按 L2 文件的 `tags`/`topic` 聚合同主题踩坑条数；口径 = 同一主题下 Exp/Skill 的踩坑记录 ≥3 → 触发本流程（不靠"想起来"，收工/自维护必查）
- **流程**：识别主题 → 草稿（问题→根因→对策→判例）→ 按 §八 溯源门禁判定（有源直落 / 无源标 verified:false）→ 判断归属：跨项目通用 → `L3\common\<主题>\`；项目专属 → `L3\projects\<项目>\知识\<主题>\` → L2 加引用 → 更新 Tree.md
- **红线**：L3 沉淀后 L2 原始踩坑保留不删（L2 快速参考，L3 深度查询）；同主题多次沉淀增量覆写

## 六、TRASH 规则

- 不删除，除非用户明确要求；移入时同步更新 Tree.md 与 TRASH/_index.md（首次移入时若无则建——懒创建，非上工必读）
- TRASH 文件不参与知识加载；恢复 = 移回原路径

## 七、与 mind-private 的边界

- 出厂模板在 `mind\L3\`；**运行时记忆一律写 `mind-private\L3\`**（同名私有优先）
- 隐私红线：真实记忆内容永不写入出厂区、永不推送

## 八、记忆写入门（溯源信任 + 可选审阅）

> 哲学：信任靠溯源挣来，不靠人审预设（`mind\L1\Design-Philosophy.md`）。记忆进 L3 不再强制经人审。
> **日期锚**：条目/教训的日期以上工召回【系统日期】（机器时钟）为准——不自猜、不沿用旧文件日期（2026-09-06 全库超前错标 2 天教训，09-04 已校正）。
> 溯源契约（确定性内核，`mind-validate` §② 强制）：每条 L3 记忆 frontmatter 必须带 `source` **或** `verified: false`——二者至少其一。
> `source` = 外部可查证依据：文件 / 事件 / 用户明示 / 实测；**agent 自推理不算 source**（无 source 的自推理一律标 `verified: false` 降权）。
> **importance 判据（检索权重的质量分，写入时自评）**：绑**可观察事实信号**，不凭"我觉得重要"拍脑袋。五档语义——

| 分 | 语义 | 判据（可操作，宁低勿高，默认 2） |
|---|---|---|
| 5 | 关键 | **违反它代价大 / 高频依赖**：隐私红线、宪法条款、核心方法论——丢了会出事 |
| 4 | 重要 | **跨主题/跨项目复用**：多个场景都在用的设计决策、通用流程 |
| 3 | 常规 | 单主题内常参考：踩坑对策、领域知识 |
| 2 | 参考 | 特定场景才查：细节速查、背景资料（默认档） |
| 1 | 边缘 | 几乎不再用 / 可被替代——查到算赚，查不到不亏 |

> 自评问题：「丢了它，最坏会怎样？」代价大 → 5；没代价 → 2。**后果严重度 > 新鲜感**。用户明示「这个很重要」= 直接 5。importance 是写入时质量分，作为检索排序的分量之一（参与 §十 排序：相关 + 可信度 + scope + importance，见 `packages/dshome-mind/lib/index.cjs` searchMind），不引入自动热度计数——热度是流行度噪声，importance 才是分量信号。

> **importance 调整规则（重评事件驱动，不做定时重评）**：评分不是一次定终身——记忆被复用/过时/发现高估时该升该降。**谁能调**：智能体主动重评（按事件）；主人随时直接改 frontmatter 或明示「这条很重要/没用了」→ 主人明示 = 最高优先级，直接定档。**何时调（只在这 4 类事件触发）**：

| 触发事件 | 方向 | 判据 |
|---|---|---|
| 记忆被**复用/引用**（检索命中后真解决问题、被 skill/其他记忆 related） | ↑ 升 | 「它真的频繁在帮我干活」 |
| 记忆**内容过时/被替代**（新记忆覆盖、方案废弃） | ↓ 降 | 「它不再代表现状」 |
| 使用后发现**没那么关键**（当初 5 分实际少依赖） | ↓ 降 | 「丢了它的最坏后果」重估变小 |
| 主人**表态**（很重要/没用了/调成 X） | 按主人 | 主人明示直接定档 |

> **两条纪律（防抖动）**：① **事件驱动，不做定时重评**——不搞「每周给所有记忆重打分」，那是温度计的变体（繁冗罪）；② **调整后进冷静期**——同一条调完分，无新强信号不短期反复改（防「今天 5 明天 2」手抖）。调整本身 = 内容变更，按 §二 覆写规则走（增量覆写 + git/快照留痕），不另设日志字段。

- **有源可溯 → 直接落库**：记忆带 `source`（外部可查证依据：文件/事件/用户明示/实测，非 agent 自发推理）→ 判断归属：跨项目通用 → 写 `L3\common\<主题>\`；项目专属（frontmatter 带 `project: <key>`）→ 写 `L3\projects\<key>\知识\<主题>\`（frontmatter：kind/importance/scope/topic/tags/**project**(项目专属时)/**related**/source/proposedBy/proposedAt），即时生效，信任靠溯源。**顺手补 `related`**（关联记忆/技能/文档的**文件名**，图谱连线用——显式 related 比同 tags 自动成边更精准，落库时花 5 秒想想"谁和它相关"）。
- **无源 / 自推理 → 标 `verified: false`**：按上述归属写入并在 frontmatter 加该字段，**不参与权威裁决**（降权，可被有源记忆覆盖）。
- **存量迁移**：旧记忆（无 frontmatter / 用 `> date:` 引用式头）迁移时补 frontmatter；内容有出处 → 提为 `source`；确无外部依据 → 标 `verified: false`。校验不过即阻塞提交，不接受"先记着"绕过。
- **用户明示 / 敏感 / 拿不准**：才建议走 `mind-private\tasks\pending\<日期>_<名>.md` 等用户在图谱面板「⏳ 待放行」裁决（✓ 入库 / ✗ 入 TRASH）；**非强制门**，仅作可选审阅。
- **例外**：用户**直接要求记录**（"记一下/存下来"）→ 实时落盘，不入 pending。
- 🔍 **正文结构要"可召回"（2026-09-10 检索体检，A 兜底）**：检索按「整节 + 节内各段」切块打分，**块越小越容易被短查询命中**——所以正文**按 `## ` 分小节**（一节一件事），**含结论的句子单独成段**（标题行与首段一起参与打分）。实测：没有 `##` 的整篇（349–874 字）与短查询的相似度被分母稀释到阈值之下 → **写得进、召不回**（4 个 dated lessons 短查询 5/5 未命中；加 `##` 后 0→11~19%）。存量老记忆若发现召不回，**优先补 `## ` 小标题**（不动内容）；改完用 `node scripts\search-regression.mjs` 与上工召回自检。
- 🔍 **写入前自查（防重复）**：提议任何记忆前，先查同主题是否已有同一事实——`/api/mind/dup-check { topic, content, project? }` 返回相似命中（bigram-Jaccard，≥12% 提示）——**`project` 传当前项目 key（= cwd 目录名）时一并查 `projects\<项目>\知识\` 结晶区**，不传只查 common + user-rules（2026-09-11 补：此前 dupCheck 只扫 common + user-rules，项目区查重恒空 → 项目专属记忆可无限重复入库）。有高置信重复（≥30%）→ **不新增**，汇报"已有 X 相似 N%，更新旧条目还是新增？"；低分命中看 snippet 判断。**`topic` 必须是目录名**（与落点目录一致，如 `lessons` / `dshome-build`）——实现按 `L3/common/<topic>` + `L3/common/user-rules` + `projects/<key>/知识/<topic>` 寻址，写成自由主题词即**静默 0 命中**（假阴性，别读成"库里没有"）；拿 0 命中当证据前，先用一条**已知存在**的原文做正对照。⚠️ **扫描面不含 `L1/Learn.md`**（Learn 不在 L3 面）⇒ "与 Learn 既有条目重复"查不出来，涉及 Learn 时需另行比对。目标：同事实只存一份

## 九、整理队列（curate-jobs，内容级处置委托）

- **触发**：用户在整理区对候选点「🤝 让智能体处理」→ 后端写入 `mind-private\.curate-jobs.json`（{ file, at, status: assigned }）

  - `oversized`：蒸馏速查 / 拆分冗余（冗余内容入 history）
  - `thin`（合集）：并入同主题主文件或补全
  - `dup-tags` / 疑似重复：比较合并，保留更好的一份

- 边界：归档（整文件入 history）与保留（忽略）是用户自己在面板做的事；内容级改动才走此队列

## 十、记忆调取与评价（排序规则）

> ⚠️ **这节是该系统"给别人用"的关键**（公开仓库/传给别人/发视频）：记忆的评价必须**可解释、通用、诚实**——别人打开能看到"这条为什么靠前"，而不是玄学分数。
> 核心：**记忆优先级 = 它值不值得优先调取**，由 4 个维度综合判断，**粗分级、随真实事件修正、非热度**。

### 第 0 步：候选范围过滤（物理目录隔离，记忆层重构 2026-09-09）

- **物理隔离**：候选 = `L3\common\`（通用，恒含）+ `L3\projects\<当前项目>\`（专属，仅当前项目扫）。**其它项目目录不扫描**——结构上不串（此前靠 frontmatter `project` 字段过滤，因数据从未打标而形同虚设；改为目录隔离后无需字段即可保证）。
- 当前项目 key = 会话 cwd 目录名（如 `DSHOME`、其它项目目录名）；`/api/mind/search?q=…&project=<key>` 同样按此取候选。
- 项目专属结晶落 `projects\<项目>\知识\`；导航卡 project.md 与记忆档案类文件在项目根、不进检索候选（档案靠强制依赖上工直读）。
- **上工取用配额（2026-09-18 补，机制已实现）**：候选两层都有 ≠ 两层都会被取用——**上工装配（`mind-prime` 的 L3 段）取用时，通用层（`common`）保底最少 2 席**，其余按「项目优先保留」补满。原因：项目层用 `minScore: 0` **恒在场**，若不保底就会「**通用层一个席位都拿不到**」（项目层恒在场、吃满 limit ⇒ 通用层**零席位**，`common` 的通用结晶/参考**等于召不回**；实现＝`scripts/mind-prime.mjs` 的 `GENERAL_MIN`，2026-09-18 修）。

> ⚠️ **`project`（项目归属，frontmatter 可选标注）与 `scope`（user/self/project，来源类型·排序分量）是两个不同字段，别混。** 隔离靠目录结构；`project` 字段仅作内容归属标注（归档/溯源用），`scope` 参与排序。

### 调取一条记忆前的判断（前 3 维，调取时判定）

| 维度 | 问什么 | 分级 | 用途 |
|---|---|---|---|
| **相关度** | 这条跟当前问题相关吗（相似度） | 超过阈值才算"相关" | **检索第一闸**，不相关不调取（用 bigram-Jaccard） |
| **可信度** | 这条有据/验证过，还是推理？ | A 有据 / B 已验证 / C 待验证 | 决定"能不能当权威用"；C 级**不主动调取**、只作参考 |
| **时效性** | 这条现在还有效吗？ | 有效 / 过时 / 被替代 | 过时/被替代 → 降权、归档 |

### 调取记住一条后（第 4 维，事后修正）

| 维度 | 问什么 | 分级 | 用途 |
|---|---|---|---|
| **有用度** | 用了它真的帮到解决问题了吗？ | 常有用 / 偶有用 / 没证过有用 | **修正以后排序**——但**不是"用了多少次"（热度），是"有没有真解决"** |

### 排序规则（综合，粗分级不精细计分）

```
优先调取：相关且 A/B 级且有效
  同级内：scope（user > self > project）> **相关度** > importance
    · 相关度按**百分制**参与排序（实现：`score*100`）⇒ 可压过 importance 档，通常压不过 scope/conf 档
    · **2026-09-17 量纲修订（同类修复第二次）**：原 `sortKey = conf*1000 + scopeRank*100 + imp*10 + score*100` ——
      **scope 一档 100 恰好等于相关度的整条量程** ⇒ scope 差一档就盖过相关度全部变化（实测：`scope:self` 相关度 7
      击败 `scope:common` 相关度 14）⇒ **蒸馏产出的通用结晶系统性排在项目/自我文件之后**。现改为
      `conf*1000 + scopeRank*50 + imp*5 + score*100`（scope 半档 < 相关度量程；conf 仍最高，排序语义不变）。
      20 条回归：召回 7/20、精度 16/20 **两侧一致（不退化）**；相关度差距大的场景（50 vs 6）已能正确居首。
      回滚 = 用 `node scripts/evolve-log.mjs rollback --list` 按对象列出快照后取用（**不写死快照名**——快照按 §十一 时间窗裁剪，写死必被裁死；2026-09-24 订正）
    · 2026-09-11 精度修复：此前相关度项恒 <1、与 `importance*10` 差一个量级 ⇒ **实际是零权重**；实测 5 条 top1 错
      全是"期望文件相关度高 5~7 倍，却因 importance 差一档而输"。改百分制后 top1 5/10→7/10、召回 10/10 不退化
不主动调取：C 级（待验证）、过时/被替代
事后修正：被证有用 → 升；误导/被推反 → 降权
```

### 关键边界（对外可解释）
- **不用"热度"**（用了多少次）——常用≠重要，会自我强化。
- **不搞精细分数**（1-100）——分太细是"假装精确"，分不出就是欺骗。
- **每条变化都有依据**：找到来源→升；被验证→升；被推翻→过时→降。**别人看得到"为什么变"。**
- 本规则是 L1 公开版（出厂区，可解释给所有人）；**实际记忆数据仍在 `mind-private\L3\`（隐私）。**

> ⚠️ **实现状态（诚实标注）**：目前 `searchMind` 已实现"**相关 + 可信度(A/B/C) + scope + importance**"排序；"**时效性**（有效/过时/被替代）"与"**有用度**（反馈修正）"**待真实信号接入**——现在无"过时/被替代"字段、也无"调用后是否有效"反馈通道，强行实现只是空壳。**等这两类信号能采集时再补**，不假装已实现。

### 硬约束（6 条）

1. **淘汰只降权；"永不物理删除"只管"不可再生"的那一类**（2026-09-21 拍板 · **2026-09-23 收窄适用范围**）—— 系统自主的淘汰动作**一律移 `TRASH\`（不删只移）并留痕**，**不直接 `rm`**：淘汰判据本身可能错，判据错一次，物理删除就是**批量损失**。原文把"永不物理删除"套到 `TRASH\` 里**一切**东西上，实测暴露两个后果：① **管错了对象**——本机 `TRASH\` 实测（**2026-09-23 改本条当时**）**267 件 / 245.4 MB**（递归），最大一件是**可重建的旧安装包 204MB**（09-17 读数），而角色卡三份旧副本与活文件 **sha256 完全相同**（零信息量）；② **让报警恒亮**——`growth-audit` 判据 `trash.count > 100` 永不熄灭，违反 `limits.md`「恒亮灯＝没灯」（同型第三处）。⇒ **按"可再生性"分三档，举证责任在删方**：
   - **甲｜不可再生**（记忆条目 / 规则 / 快照字节 / 一切造不回来的）→ **永不物理删除**（原文范围，一个字不松）。
   - **乙｜可再生产物**（`build-stage` 产物、旧安装包、下载缓存等**可重建**件）→ **解除"永不"**：`TRASH\` 是回收站，不是仓库。
   - **丙｜逐字节重复件**（`sha256` 与**活文件**相同的副本）→ **解除"永不"**：恢复点就是活文件本身，删它**不损失任何信息**。
   - **举证责任在删方，且必须机器可证**（乙＝明确的构建产物路径/扩展名；丙＝`sha256` 相等）——**不许 agent 自己裁量"这东西大概不重要"**；举不出可证依据 ⇒ 落回**甲档**、按原文办。
   - ⚠️ **解除"永不" ≠ 一律免放行（2026-09-26 订正/收紧）**：按可逆性分三层——
     **(a) 可逆的移动：自动**。`node scripts/evolve-log.mjs snap-prune --apply`（快照超时间窗移 `TRASH\`）每次执行**双向留痕**、**随时可移回**，故可在**每日自维护**里自动跑。
     **(b) 认定范围：自动**。`node scripts/trash-sweep.mjs`（默认**只列清单**）按三档认定**候选**：乙＝**构建产物/分发包**扩展名（`zip/exe/msi/7z/iso/tar/gz/tgz/rar`）或单件 > 20MB；丙＝与活文件 `sha256` 相同。**`.bak/.tmp/.log` 一律落回甲档**（2026-09-26 复核实测：真库那两个 `.bak` 是手工备份，不是"可再生产物"）；另设**保护名**（`人设卡/AGENTS/SOUL/Memory/Ritual/Invariants/Concepts/Power/HUB/Design-Philosophy/Wisdom/Learn` 的 `.md`，**含 `.bak/.tmp` 等尾巴也不许绕过**）。
     **(c) 物理删除：按龄自动清（2026-09-27 主人放行 · 原「逐次点名」放开）**。`node scripts/trash-sweep.mjs --auto` ＝按**保留期**自动清：**大件（单件 > 20MB）满 30 天、小件满 180 天**即物理删除；**甲档与保护名永不自动清**（判据一个字没松）——唯一改的是**"到期判定"由人改成时间**。理由＝回收站的本质是**后悔药窗口**，不是永久仓库：替代"逐次点名"的不是更聪明的判据（判据仍只是**代理**），而是**时间**——"进站多久"机器可判、不需要知道内容值多少；窗口内可捞，窗口一过即说明无人需要。⚠️ 两条实测前提：**① 龄的基准＝条目名里的入站戳**（`YYYY-MM-DDTHH-mm-ss__…`，UTC），取不到才回退 `mtime`——**不能只用 mtime**：移入走 `rename`、mtime 保留的是**文件原来的修改时间**，会把「今天移入的老文件」算成「龄 700 天」、窗口＝0（2026-09-27 修，门禁用 ⑤⑥ 两个**方向相反**的 mtime 陷阱钉死）；**② 逐次点名并未废除**：`--sweep --only <条目名子串…>` 仍是"立刻清某件"的出口，`--auto --dry-run` 是**审阅口子**（只看不删）。
     ⚠️ 自动出口**只解"逐次请示移动/认定"，不解"举证责任"**：工具必须先跑分类、举不出机器可证依据的落回甲档、**默认只列清单**、不留痕不算执行。
   **唯一例外（不变）＝主人明确要求删除**（主人权利，见 §六）。

### 降权阶梯（淘汰的唯一形态——2026-09-21 定 · 决定5）

> 淘汰不是"删掉"，而是"**降一阶**"。四阶**全部可逆**；**删除不在阶梯内**。本节把散在 `§八`（`verified:false`）/ `§十`（时效降权）/ `§十一`（冻结位 · TRASH）的三处降权收敛为一条。

| 阶 | 触发 | 机制 | 怎么还原 |
|---|---|---|---|
| ① **时效降权** | 过时 / 被替代 | 排序后置（`§十` 第 3 维） | 改判断 |
| ② **溯源降权** | 无 `source` / agent 自推理 | 标 `verified: false` → **不参与权威裁决**（可被有源记忆覆盖） | 补 `source` |
| ③ **冻结位** | 冷 / 想留痕但不进召回 | `status: frozen` → 不进默认召回，**显式检索仍可查** | 改一个字段 |
| ④ **移出（TRASH）** | 同主题归并 / 整层退役 | `evolve-log trash <path> --reason "…"` 移入 `TRASH\` + 留痕 | 移回原路径 |
| — **物理删除** | — | **不采用**（唯一例外＝主人明确要求） | ❌ 不可逆 |

**为什么不做第 ⑤ 阶**：判据错一次，删除就是**批量损失**；而"库里多留一条"的代价只是**检索噪声**。两边的代价不对称 ⇒ 永远选便宜的那边。

### 压缩阶梯（与「降权阶梯」并列 · 2026-09-26 加）

> 缘起：实测"记忆越积越多"的真实形态**不是篇数多**（L3 活档 23 篇 / 358 KB、中位数 4.2 KB），而是**单篇条目多**（`project.md` 218 KB / 143 行、`Learn.md` 121 KB / 106 行）——而检索按 ~60 字分块 ⇒ 大文档的几千片近重复会吃满 top-N 配额。外部调研（2026-09-26）：rate–distortion 综述把记忆压缩统一成"预算下留什么"的问题，并给出一条**可证伪**的结论——**反复做不可逆摘要的系统，误差随压缩次数超线性增长；而可逆、可检索的记忆保持平坦**（[arXiv 2607.08032](https://ar5iv.labs.arxiv.org/html/2607.08032)）；[Mem0 v3](https://docs.mem0.ai/migration/platform-v2-to-v3) 的主流形态是**累积 + 检索**（ADD-only，不再改写旧记忆）。⇒ 所以**先做零损失、不需要"合并判断"的那几档**。

| 档 | 动作 | 损失 | 要人判吗 | 机器件 |
|---|---|---|---|---|
| 0 **冻结** | `status: frozen` ⇒ 不进默认召回（字节不动、显式检索仍可查） | 零 | 否 | 字段已有（`mind-search-lib` 的 `isFrozen`）；**至今 0 篇用过** |
| 1 **指针化** | 长 `##` 小节正文搬到 `L3\history\<日期>_<组名>\<来源>\<锚点>.md`，原处只留指针块 | 零（原文逐字节保存） | 否 | `node scripts/memory-archive.mjs`（默认只列候选；`--apply --file <文件> --only <锚点>` 才动手；门禁 `verify-memory-archive` 17 条） |
| 2 **字段化** | 散文条目改成 `- 结论 / 依据 / 日期` 三段 | 近无损 | 否 | 缺（待建） |
| 3 **归并** | 同主题多条 → 一条 | **有损** | **是**（机器判不了"该不该合"） | 缺判据 + 缺人 |
| 4 物理删除 | — | 不可逆 | 是 | `trash-sweep --sweep --only`（见硬约束 1） |

- **秩序铁律**：低档先做，别跳档。**0/1/2 都不需要判断**（零损失 ⇒ 不涉及"值不值得留"），能机器化；3 才涉及判断，必须人参与。
- **配额**：单篇活档建议 **≤ 30 KB**（`memory-archive --quota` 可调）——**例外**：`project.md` 是**里程碑账本不是知识**，它的解法是"里程碑归档进 `history` + 正文留指针"，不是条目归并；`user-rules` 属主人权利域，机器不碰。
- **可逆性**：1 档的 history 原文 = 逐字节副本，改前另留 `<文件>.bak-before-archive-<时间戳>`；还原 = 把原文粘回 + 删指针块。

### 冻结位（`status: active | frozen`）—— **2026-09-12 已落地**

> §十一 说的"不删只移"，在**召回层**的落地就是这一位：**frozen = 留库但不进默认召回**。

- **语义**：`frozen` 记忆仍在盘上、仍可 `read`、仍可**显式检索**（`/api/mind/search`）；只是**不再被自动召回**（上工 `mind-prime` 不传 `includeFrozen`）与不再进默认排序。
- **实现**：`scripts/mind-search-lib.cjs` 的 `isFrozen()` + `searchL3(..., { includeFrozen })` —— **默认排除**；`packages/dshome-mind/lib/index.cjs` 的 `/api/mind/search` 显式传 `includeFrozen: true`（**显式检索应当查得到**，否则冻结＝记忆凭空消失）。
- **零迁移**：无该字段 = `active`（存量 0 个已冻结）。**可逆**：改一个字段即还原 —— 比删除安全，比衰减可验证。
