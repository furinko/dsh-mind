## 一、收工闭环（9 步）

触发词：「收工」「沉淀」，或主动收工提醒后用户确认。

| 步 | 操作 |
|---|---|
| 1 | 更新 project.md（进度状态 + 版本 +0.1 + 日期） |
| 2 | 更新待办清单（✅ 完成移入已完成区；新条目入对应分类）——**顺手通读一遍全量未结项**：完成判据已满足的一并销账（**触达即清**——别攒到"病发了"才动；重型批量核账另有独立技能，触发词「核账」） |
| 3 | 更新 L2 Skill/Exp（如涉及变更，版本号 +0.1/+1.0，见 `mind\L1\Power.md` §三 沉淀路径 的 `### 更新 Skill/Exp`） |
| 4 | **蒸馏轮级缓冲**（`mind-private\tasks\pending\` 待放行 + `mind-private\L1\Dream.md` 灵感池）逐条提炼并入 L3；临时性丢弃——**先蒸馏后同步 Tree**，让 step5 覆盖新落库 |
| 5 | **更新 Tree.md**（新文件/版本/索引同步——含 step4 刚蒸馏落的 L3 主题） |
| 6 | 清理 tasks\（轮级缓冲归档/删除，中介文件清空）——**顺带检查 `.curate-jobs.json`**（剪枝面板「🤝 委托」的内容级整理：读文件按 reason 执行 → 移除 job + 记 kept，见 `Memory.md` §九） |
| 7 | 汇报收工摘要（改了什么 + 版本变更清单） |
| 8 | **机制体检**（元进化，见 §三）：跑 `node scripts/evolve-log.mjs health` 看「未回填 / 判效覆盖 / 未裁决」；有未回填就 `effect auto` **机器判定**（读主信号基线+**方向**，去自评）；再 `pending-invalid` 列出机器判「无效/恶化」**待人拍**（见 step9）。信号够用？能简化吗？ |
| 9 | **收工自省**（行为问题尺，见 §五）：逐条问自己（可答是/否）——该修的沉淀 Learn（💢），该保持的固化（🤗）。**写前先读 `Learn.md` 头部「条目纪律」并查当天同主题条目**：同主题复发**在原条目追加计数、不新开**（🔴 消费点，2026-09-24 补——该纪律原先只写在 `Learn.md` 头部、此处不引用 ⇒ **立规当天即失真 11 倍**）；**新条目一律 append 到 `Learn.md` 文件末尾**（上工召回 `mind-prime` 取**末尾 3 条 + 按任务检索 2 条**，插进分区中间 = 写了却召不回）；**收工必走，不靠"想起来"。** 顺带对 step8 的 `pending-invalid` 逐条**人拍**：留观 / 回滚 / 改进化（**机器只标，回滚由你定**）——拍完用 `evolve-log decide <对象> <裁决> "<理由>"` 记账，**不记账下次还会被列出来**（消费端）。 |

**实时 vs 缓冲判据**：正式拍板（有定性结论）→ **实时落**（不等收工）；未定型（过程笔记/待验证想法）→ **轮级缓冲**（`mind-private\tasks\pending\` 待放行；灵感/点子 → `mind-private\L1\Dream.md` 灵感池）。

### 换会话接续（收工之后 · 条件触发）

> **触发只有一个：确认要换会话**——主人说「换会话 / 开新窗口 / 明天接着做 / 今天就到这，下次继续」之类。
> **不预测、不主动给**：agent 侧读不到自己上下文的占用读数（`tokenMeter` 是宿主侧服务）⇒「我觉得快满了」**不是**触发条件（`Invariants` #14：缺能力不假装）。
> **时机＝收工之后**：提示词的素材**大部分来自收工产物**（`project.md` 进度/待办 · 沉淀 · Learn）⇒ 先走完 step1–9 再给；顺序颠倒 = 交一份过期现场。主人中途确认换会话、本轮**没走收工** ⇒ 照给，但顶部标「**本轮未收工**：`project.md` / 待办未同步到最新」。

产出＝一段**自包含**的《接续提示词》（代码块包住，主人可直接粘进新会话），写给**没有本轮上下文的接手者**：

```text
【接续提示词】<项目> · <日期>
① 任务：<要什么>｜判据：<怎么算完成>
② 已定方案：<关键决策>（为什么：<一句话>）
③ 已完成：<做了什么>｜证据：<文件路径 · 命令 · 读数 · 提交号>
④ 下一步第一件事：<一个具体动作>
⑤ 入口：读 <哪些文件>；跑 <哪些命令>
⑥ 边界：不碰 <X>｜等主人放行 <Y>｜私密区 <Z>
⑦ 现场：cwd <路径>｜分支 <名> / 未提交 <清单>｜进程 / 端口 <状态>
```

**三条口径**：**代词还原成实体名**（"那个文件" → 写全路径）· **不写"见上文"**（接手者没有上文）· 与 `project.md` 分工＝它管跨会话长期记忆（进度 + 待办），本条管**当轮现场**（含未落盘的临时状态），**不替代上面的收工闭环**（step1–9 该走还得走）。

## 二、自主维护与自主内化（清与长）

> 清 vs 长：成长让智能体变强，自维护让智能体不脏。**自主维护 / 自主内化是出厂提供的「能力 + 处方」**：机制在 `packages\dshome-mind\lib\cron.cjs`、处方在 `cron-recipes.cjs`，入口 = 面板「⏰ 定时 → 建默认自治任务」（按**当前工作区** seed 成实例）。
> 🔴 **出厂不含任务实例、默认不启用**：实例（周期 / prompt / 启用状态）落**本机私有区** `mind-private\tasks\cron.json`——启用会花 token、并会改使用者自己的 `mind-private`，故**由使用者点一次 = 同意**（对齐 2026-09-10 定案「出厂只放机制、内容私有」）。下面的清单与边界，对**任何启用了自治的本机**都成立。

### 自主维护清单（安全，自己做）
- 临时/中介/日志/`__pycache__` 等**自己产生**的中间物
- **机器判「无效」的进化：列出待人拍**（回滚由用户拍板——若自主回滚，又变成「机器判有害→机器回滚」的递归自利偏差；**回滚按 step9 人拍**）
- **轮级缓冲**（`mind-private\tasks\pending\` 待放行 + `mind-private\L1\Dream.md` 灵感池）蒸馏 / 清空
- **pending 堆积检查**（超 7 天 → 列出提醒，不擅毁）
- **`Learn.md` 超线即归并**（`growth-audit` 的 `Learn.md` 行出 ⚠️ 时）：本轮派 `memory-tidy` 做一次同族归并，或**退役判据已被 L2 承接的条目**（判据见 `Memory §十一`）。两条附带口径：㈠ **归并只是"降压"、不是"治愈"**（2026-09-27 实测：归并到 130,700 B 后，同轮自己追加教训即回到 129 KB）⇒ 它需要**每轮触发**，这正是本条存在的理由；㈡ **不给写入侧加闸**——`Learn` 在 `mind-private\`（被 `.gitignore` 忽略、不进 git）⇒ **没有任何机器闸的落点**（hook/门禁都看不到它），而"超线就不许写"是**拿正确性换体积**（好教训漏记比库胖更贵）。**缺的从来不是"限写"，是"按时归并"的触发**——本条就是那个触发。
- **角色卡池体检**（`mind-private\L2\agents\` + 项目 `.agent-roles\`）：**重影**（同岗位两张卡）/ **一次性卡已交付** / **id 不可读**（`inline-<hex>`）/ **正文里的幽灵引用**（引的文件已不存在）⇒ 处置走卡线的正规通道：**退役 = `role_card_retire`** · **改名 = `role_card_rename`**（两者都**不物理删、可恢复、留台账**）

### 🔴 不自主维护（要用户，别越界）
- **删/归档用户记忆内容**（curate 归档/删记忆——用户的东西，人确认）
- **改动用户路径/配置**（settings / 凭证）

> **边界：自维护处理的是"自己弄脏的"，不碰"用户的东西"。** 用户内容的价值判断永远归用户。

### 自主内化（自我生长）— 事件驱动 + 定期兜底
> 上面清的是"自己不脏"，这里长的是"自己变强"。**内化本是事件驱动的**（`§一 step4` 收工蒸馏 / `§四` 蒸馏闭环 / `Power §三` 自主收录授权）——**不靠"想起来"**；事件没触发或被跳过时，由本机定时任务兜底一次。
> **周期属本机配置**（取值见私有区 `cron.json`），**不写进本规则**——规则只管"该兜底、兜底时做什么、边界在哪"；任务配置见私有区 `cron.json`，出厂默认无。
- **盘存货**：轮级缓冲（`mind-private\tasks\pending\` + `mind-private\L1\Dream.md` 灵感池）/ `Learn.md` 未固化条目 / 未蒸馏的踩坑与产物
- **逐条过判据**：跨项目可复用 / 有验证过的逻辑 / 以后还会遇到（`Power §三`，≥2 条才沉淀）——不过的留缓冲或不记
- **按落点入库 + 同步索引**（`Power §三`：Skill→`_index`+`Tree`；Exp→该目录 `README` 表；lessons/user-rules/项目知识→对应 `_index`）
- 🔴 **刹闸**：**行为规则类**改动仍**等放行**——`mind\L0\` SOUL/AGENTS + `mind\L1\` 八件（HUB/Wisdom/Memory/Power/Invariants/Design-Philosophy/Ritual/Concepts；名单真源＝`mind-guard.js` 的 `inHighRiskyZone`，`L0` TOOL.md 自 09-06 起不在内）；护栏/插件代码、运行时注册、git 提交同样**等放行**（**行为承诺**——代码面护栏不拦，靠这条纪律）；`mind\L1\` 文档/记录类（README/Tree/Dream/Learn）与 L2 生长区**免放行但要汇报**（`Power §三`）

## 三、元进化（进化机制的自我优化）

> 自举的自举：进化机制（进化档案/能力积木/确定性内核/可测指标/蒸馏判据）**本身**也能被审视、优化、演进。
> **主触发 = 自主信号**：智能体在进化/做事中**自己嗅到**（用 `node scripts/evolve-log.mjs health` 自查），命中即**自主**做体检+优化，不等收工、不等用户。收工/用户请求 = 兜底。

### 自主触发信号（`health` 自查命中即做）
① **判效空转**（一条信号绑定都没有）→ 补绑主信号——"效果验证"空转=进化只剩记录（**注**：新账覆盖率 `<50%` 这类**固定阈值不再是报警条件**，改判为信息行，理由见下）
② **未回填 ≥5**（绑了信号没回填 effect）→ 跑 `effect auto` 机器判定
③ **未裁决「无效/恶化」≥2** → **列给人拍**（留观/回滚/改进化），不擅自回滚；拍完用 `decide` 记账
④ **改得多却重复踩坑**（记录 ≥8 且 `repeat-mistakes` ≥2）→ 审视进化是否有用。**〔2026-09-24 降为信息行（主人「放」）〕** `repeat-mistakes` 是**人工记账、只增不减**的量，拿累计值当阈值 ⇒ **恒亮灯**（同族：09-10 两条 · 09-18 ① · 09-23 `TRASH count>100`——这是**第四处**），并与 `evolve-log.mjs` 自己印的「人工记账**不参与报警**」口径**自相矛盾**（还把 `health` 永久置 exit 1）⇒ 改为 ℹ️ 打读数（累计计数，只作趋势）；**审视仍要做**，但由**可判事件**触发（同主题复发 / 判断失误当场），**不由累计阈值触发**

> **报警信号必须"可熄灭"**：① 全库记录条数、② `corrections` 这类**人工记账 / 只增不减**的量、③ **新账判效覆盖率**（`<50%` 这类固定阈值——实测覆盖率远低于它，且多数进化**天生没有可测信号** ⇒ 做不到）、④ **`repeat-mistakes` 累计值**（2026-09-24 加）——**四者一律只作信息行、不报警**（读数照打、**能绑就绑**；想要更可判的度量 → 走待办「进化信号的度量设计」，别在此处硬设阈值）。覆盖率的**分母按新账算**（不含封存旧账，否则阈值永远达不到=又一盏恒亮灯）。——恒亮的警告等于没警告（2026-09-10 深度体检结论：两条 ⚠️ 曾恒亮 6 天）。**2026-09-18 订正**：原 ① 把 `<50%` 写成**报警条件**，与实现（`evolve-log.mjs`「新账覆盖率只作信息行」）和本节自己的"可熄灭"判据**同时**矛盾 ⇒ 按机制收窄为信息行。

### 机制体检清单（命中后检查）
1. **审核机器判「无效/恶化」**：`pending-invalid` 列出未裁决的 → **列给人拍**（留观/回滚/改进化）——不自动回滚（回滚是自我修改，须人拍，递归停在你主人那是正解）；**拍完必须 `decide` 记账**，否则无消费端=每次收工重复审同一件事
2. **信号够用吗**：可测指标缺关键信号 → 加（`evolve-log.mjs` 的 `METRIC_DIRECTION`，含**方向**：越高越好 / 越低越好）；**信号还得有采集点**——无自动来源的人工记账信号只作信息行、不参与报警
3. **机制过重吗**：蒸馏判据/进化档案纪律会不会拖慢日常 → 简化
4. **有没有引入偏差/误导**：一次进化带来的副作用 → 调整

发现要改 → 走进化档案纪律（snapshot + log）；没问题就不动。

## 四、行为纪律（细则——AGENTS 常驻只留核心，这些按需读）

> AGENTS 指针区指向这里。常驻注入只留灵魂/铁律/核心，以下细则按需读。

- 🟡 **蒸馏闭环** — 重要任务完成/收工时，按 `mind\L1\Power.md` §蒸馏判据**主动判断**该沉淀啥（Skill 积木/Exp/教训/偏好/决策）→ 落点 → 更新索引（`_index`/`Tree`）→ 进化档案 `log`。让能力自增长，不靠手动。
- 🟡 **元进化（自主）** — 不止等收工：进化/做事中**自己嗅到**该审视进化机制（跑 `node scripts/evolve-log.mjs health`，命中即做）→ **自主**做体检+优化（§三）。收工体检、用户请求只是兜底。
- 🟡 **自主维护+巡检**（定期兜底；配套的**自主内化**见 §二） — 自己定期做（**本机启用自治任务后**，**一次会话边维护边巡检**；实例与周期属私有配置、出厂默认无，见 §二）：维护=清中间物/机器判「无效」列人拍/轮级缓冲/pending 检查；**巡检=主动找隐患** → **处置口径（2026-09-23 主人定）：能处理的就处理掉；需要决策的进待办；不要在任务中留未决项**——① **能处理**＝不需主人取向 / 放行的（低危、可逆、本轮有验证手段）⇒ **本轮做完 + 给证据**，**不许只写进报告或待办**；② **需决策**＝需主人取向或放行的 ⇒ 追加 `mind-private\L3\projects\<项目>\project.md`（项目 key = 当前 cwd 目录名）待办，**一条一句取向问题**并提示主人；③ **不留未决项**＝禁止"待查 / 待定 / 待实测"悬空：要么本轮**实测钉死**（给判据 + 读数），要么明写"**已登记待办第 N 条，等主人一句**"。🔴 不碰用户的东西（§二）。
- 🟡 **极限记录** — 遇到确认不可达（做不到但有依据）→ 记 `mind-private\tasks\evolution\limits.md`（**无则新建**；**记录在案 = 闭环**）；**没试就说不做 / 本可达到没做到 = 尾巴**。
- 🟡 **写前查重** — 提议记忆前先做近重复自查（`/api/mind/dup-check`，同主题 bigram 比对）；≥30% 相似不新增，先汇报"更新旧条目 or 新增"。🔴 **串行前置**：顺序固定为「查重 → 读结果 → 定 `verified` → 再写」，四步**不可并发**——并行跑就是"先写后查"，查重结果拦不下已经写好的文件（L3 结晶「查重必须串行前置」（私有区，不推送）：并发 = 没查）。
- 🟡 **整理队列** — 收工闭环时检查 `mind-private\.curate-jobs.json`（用户在整理区点「🤝 让智能体处理」挂的作业）：读文件按 reason 做内容级整理，完成移除 job + 记入 kept，结果汇报用户。
