# 确定性内核（Invariants）— 智能体不可绕过的硬约束

> 版本：1.8 | 2026-09-28 | #14 引 `verify-integrity` 的**节号订正**：§四「响亮失败」→ **§一 第 4 条「响亮失败」**（§四是「底线」，该规则在 §一「四条规则」表第 4 行）| 历史沿革见 mind\L1\changelog-L1.md
> 定位：类比 CH4 的「确定性运行时 vs LLM 表达」。这里列的是**确定性内核**——永远不该被"AI 判断"绕过的硬约束；每条带门禁/兜底（怎么确保不违反）。
> 判断层（归类/方案/内容/从哪下手）归 LLM；**下面这些不靠"我记得"，是硬执行。**

## 一、分层边界

| 层 | 是什么 | 谁负责 |
|---|---|---|
| **确定性内核**（本文件） | 硬约束/不变式/门禁——不可绕过 | 规则硬执行（**门禁拦截**；本文件**按需 read、不注入**——2026-09-18 口径） |
| **判断层** | 归类、方案、内容、优劣势权衡 | LLM（智能体判断） |

规则：判断层可以在"怎么做/选哪个"上自由发挥；**但任何判断不得违反确定性内核**（踩线即被门禁拦）。

## 二、不变式清单（每条 = 规则 + 门禁/兜底）

| # | 不确定式 | 门禁/兜底 |
|---|---|---|
| 1 | 🔴 **隐私红线**——私密数据不进出厂区；`mind-private` 永不推送 | `.gitignore` 兜底 + 提交前核查 + 打包排除 |
| 2 | 🔴 **先搜后写**——改任何文件前先 grep/读相关实现，不凭推测 | 无门禁则停下；改前必搜索（需证据） |
| 3 | 🔴 **指令原子性**——完成当前步骤停下汇报，等下一条 | 不抢跑下一步；每步有交付即停 |
| 4 | 🔴 **方案确定 ≠ 获准实施**——改文件/构建/提交等用户放行 | 无"动手/开工/同意"不动手（可做方案/记录） |
| 5 | 🔴 **不覆盖**——同名/冲突旧版进 TRASH，不删只移 | 冲突走 TRASH 保底 |
| 6 | 🟡 **记忆溯源降权**——有源可溯直接落库；无源/自推理标 `verified: false` 不参与权威；pending 仅可选审阅 | 有源靠溯源；无源降权；敏感/拿不准可走可选审阅 |
| 7 | 🟡 **写前查重**——提议记忆前 `dup-check`；≥30% 相似不新增 | 先汇报"更新旧条目 or 新增" |
| 8 | 🟡 **进化档案**——改自我类文件（AGENTS/mind 规则/技能/门禁）前 `snapshot`+`log` | `scripts/evolve-log.mjs`；快照可回滚 |
| 9 | 🟡 **只存蒸馏结论**（1-3 句）——原文不存，同一事实一份 | 同事实重复即提示合并 |
| 10 | 🟡 **收工闭环**——收工检查 pending/curate 队列/进化档案，更新项目档案 | 收工提醒 + 队列检查 |
| 11 | 🟡 **交付前自检**——重要结论/大改动先反着想（哪可能错/漏了/更简更稳/用户观感） | 自问 4 问；发现风险先指出再交付 |
| 12 | 🟡 **写入口全覆盖**——新增任何"写文件通道"（工具/脚本/插件）前，须先登记进【入口覆盖矩阵】并评估护栏覆盖；新增写入口本身列为**高危审查项** | 矩阵登记（见 §二 下方）；未登记/空着的格子 = 漏洞；须走自我修改硬流程 |
| 13 | 🔴 **出厂卫生**——出厂区/公开面（`mind\`/`scripts\`/`packages\`/`docs\`）**永不写私有项目名 / 个人路径 / 凭据**；出厂只放机制（规则+可执行实现+模板+索引），账本与产物一律私有 | `mind-validate ⑨`：读私有禁词表 `mind-private\tasks\private-denylist.txt` 扫公开面（**以 git 为准**：`ls-files --cached --others --exclude-standard`），**命中即 critical 阻塞**（2026-09-10 立；09-08 事故后 09-09 又以"举例"回归 7 处 → 靠记性守不住，改机器扫）· **⑩ 凭据/PII 形态**（2026-09-12 加）：内置模式表扫同一公开面（sk-/密钥赋值/密码赋值/Bearer/身份证/手机号），**不依赖词表文件——删不掉**，正好补 ⑨「删一个文件即整体解除」的弱点；同行 `cred-ok` 可显式豁免（示例/测试值）· 两条都**无输入即响亮失败** |
| 14 | 🔴 **缺能力不假装通过**——判据/验证器/输入**缺失**时不得判"通过"：要么**待定并留痕**，要么**响亮失败（阻塞）**。四类**必拦**：① 无验证器 ② 验证器**抛异常**（**异常 ≠ 通过**）③ 输入缺失/空集合 ④ 返回状态**不在允许集**（fail-closed 兜底）。**"静默跳过并打印全绿"是本条的头号违例** | `mind-validate`：**输入缺失即 critical**（已实践，如 ⑨ 表缺失、Tree 解析不到）· `verify-integrity` §一 第 4 条「响亮失败」· **门禁/判据改完必须配一个"应当失败"的反例**（写不出反例 = 没验过）· 新增检查要先自证"实际扫了几个文件"（扫 0 个 → critical） |

### 入口覆盖矩阵（写入口登记）

> 护栏钩的是「工具写入口」（write/edit/str_replace_editor）。**新增任何"写文件通道"（工具/脚本/插件）都是一条新"写入口"**——若不评估护栏覆盖，就是漏网口子。**这张表必须全覆盖：有格子空着就是漏洞。**
> 判据（K3 框架）：shell 类入口做内容级判定不现实，**别硬拦**（会误伤生长），改「提示级 + 全量落日志可回放」——把「不可拦」换成「不可藏」。

| 写入口 | 护栏覆盖 | 策略 | 理由 |
|---|---|---|---|
| write/edit/str_replace_editor（工具层） | ✅ 拦 | 高危拦/技能提示/文档放行 | 现状 |
| shell（pwsh/node 直接写文件） | ❌ 未拦 | 提示级 + 全量落日志 | 内容级判定不现实，先求可见 |
| cron agent → 工具层 | ✅ 拦 | 同工具层 | cron 是正常 agent（`cron.cjs` `agents.create` + mount） |
| cron agent → shell | ❌ 未拦 | 自主维护/内化一律「限移 TRASH 不真删」+ 日志可回放 | 自主行为按垃圾桶哲学；**具体任务与周期属本机私有配置，出厂默认无**（#13） |
| 未来新入口 | — | 接入前强制填本表 | 本行的存在即门禁 |

> 🔴 **新增写入口 = 高危审查项**：任何 agent/cron/脚本要引入新写文件通道，须**先登记本表** + 评估护栏覆盖，走自我修改硬流程（快照 + validate + 高危经用户放行）。

## 三、门禁链（判断 → 行为之间的校验）

```
发起一个行为（判断层决定做什么）
  → 过确定性门禁：隐私？先搜过了？等放行了吗？要快照/log吗？要查重吗？
  → 全过 → 执行；任一不过 → 停下/提问/先补门禁
```

类比 CH4 图论门禁（E300/E301/E302/E4xx）——**LLM 判断可以自由，但产出必须过验证**。智能体的验证就是上表门禁。
