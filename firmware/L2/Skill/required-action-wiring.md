# required-action-wiring — 必需动作接线三判据

> 心法一句话：**"必须发生"的动作不能只活在某条可选链路里，更不许失败后静默通过。**
> 来源：2026-09-12 实景——某桌面端打包流程的图标补丁只挂在 `setup-dev.cmd → pnpm run setup → install-electron.mjs` 这条**可选**链上，且补丁失败只 `console.warn`、退出码仍为 0；于是 clone 出来的机器（`node_modules` 不跟踪 ⇒ 必重下原版 exe）只要跳过或没走完 setup，就**静默**带着错误图标一路跑到用户来问。

## 一、使用流程（Step 1→N）

1. **点名那条动作**：写出"正确性所必需"的动作（给产物打补丁 / 生成某必需产物 / 同步某份配置 / 校验某前置条件）。
2. **查它的挂载链**：grep 谁调用它、失败时怎么处理、退出码是什么。核心判据 = **"有没有一条路径能绕过它而一切照绿"**。
3. **过三判据**（§二），每条给 verdict：有 / 半 / 无。
4. **按缺口改造**：补落点 / 改硬失败 / 加自检命令。
5. **验证三件**：① 正例（正常路径跑通）② 反例（人为跳过或让那个必需动作失败 ⇒ 必须**响亮失败**，不是 WARN + exit 0）③ 设备侧那条只读自检命令真能读出当前态。

## 二、核心规则（硬约束 · 三判据）

| # | 判据 | 合格线 | 不合格的样子 |
|---|---|---|---|
| ① | **唯一权威落点** | 该动作只有一条权威链路（启动 / 安装 / 构建的必经路径），不依赖使用者"记得"跑某个可选命令 | 只活在 `setup-dev.cmd` 里；跳过 setup 就静默降级 |
| ② | **没跑就硬失败** | 失败 ⇒ 非零退出 + 明确原因；报"就绪"之前必须**先验它** | `console.warn` 后 `exit 0`；拿"命令返回成功"当就绪判据 |
| ③ | **设备侧可自检** | 给使用者一条**只读**命令判定现状（在不在 / 是不是对的） | 只能"再跑一遍安装"或"看界面猜" |

**三判据必须都过**：缺 ① ⇒ 有路径能绕过；缺 ② ⇒ 绕过时静默；缺 ③ ⇒ 出了事只能重装。

## 三、行为准则（软技能）

- 先问"**这个动作为什么必须发生**"，再问"它现在靠什么保证"——保证必须是**机制**（落点 / 退出码 / 自检），不能是纪律或自觉。
- **检查与改造分离**：启动路径只体检、不改二进制；判定失败就打印原因 + 指路 + 中止（`开发启动.cmd` 的做法值得复用）。破坏性动作留给专门的安装 / 修复入口。
- 改造优先"**加一个响亮失败**"，而不是"再加一个检查"——后者只是多一个可能被忽略的绿。
- 拿它当审计清单用：问"**这个必需动作的盲区是什么**"（与 `verify-integrity` 配方⑪配套）。
- 落地后**量产物**：回执（成功日志 / exit 0）不算数，产物变了才算（数值 / 文件数 / 计算样式）。

## 四、踩坑记录（每条 ≤100 字）

- 判"环境就绪"用退出码不用产物 ⇒ 补丁没打、bundle 没进、产物目录是空的，统统报"成功"。
- **检查命令被 shell 吞掉参数 ⇒ 恒报绿**：`git status --porcelain --untracked-files=no` 在 cmd 的 `for /f` 里一行都读不到（同命令在 `for /f` **外**跑正常、真树有 4 行改动）⇒ 脏工作树被判"干净"（2026-09-14 实测，改用 `-uno` 后读到 4 行）。**"恒报绿的检查"比"报红的检查"危险**。
- 失败路径只 `console.warn`、退出码仍 0 ⇒ 静默跳过，等用户来问才发现（2026-09-12 图标补丁）。
- **命令回执 ≠ 动作发生**：一个批量快照工具连打 4 行"已快照"，而同名文件互相覆盖只活 1 个（2026-09-14 实测）——批量动作后必须核产物个数与内容。
- **拿"端口能回 200"当就绪 ⇒ 抢在初始化完成前放行消费者**：本地服务 HTTP 一起来就 200，而"整树挂完"还晚 1.5~2.4s ⇒ 首屏残缺、刷新才好。改用对方**自己声明的就绪行**，并给近似判据留兜底（2026-09-17 实测）。
- 缓解 / 修复落地后没量产出、只凭"没再复发" ⇒ 死代码可能挂好几天（2026-09-12：主轴 `flex-basis` 压过 `height`，inline 值与实测值不一致才是实锤）。
