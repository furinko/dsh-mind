# visual-verification — 视觉/UI 类交付的验证法

> 心法一句话：**视觉交付的验收标准 ＝ 我真的看了渲染结果**（不是"逻辑跑通了"、不是"桩测试绿了"）。
> 来源：Learn 多条复发（09-05 猜 CSS 三次都复发 / 09-11 只在主屏拍了任务栏就报生效 / 09-12 把死代码当"缓解"挂了 4 天 /
> 09-16 鹈鹕测试靠放大镜与逐帧才逼出两处真缺陷）+ 仓库既有教训「**桩不解析 CSS**：1801 个公式全绿，交付物仍有一条关不掉的浮层」。
> 配套工具：`scripts/shot.mjs`（一条命令拿渲染图：`--at` 定格 / `--frames` 多帧 / `--zoom` 放大镜）。

## 一、使用流程（Step 1→N）

1. **先划"呈现面"再动手**：这件事在几个面上呈现？**多显示器 ⇒ 逐块**（副屏任务栏曾漏验：主屏已是新图标，副屏还是旧的）· **多入口 ⇒ 逐个** · **多尺寸/主题/缩放 ⇒ 逐个**。**漏一个面＝漏一个缺陷**。
2. **别猜 CSS，只读实测值**：拿 `getComputedStyle` / `getBoundingClientRect` / 截图量像素，先看清 **谁在压谁**（`display` / `height` / `flex-basis` / `overflow` / `z-index` / `position`）。反面判例：我凭感觉改"去 `max-height`、`flex:none`、余量 −16"，**三次都"好了又复发"**；拿到 computed 值后一眼定位。
3. **桩测 ≠ 渲染测**：DOM 桩不解析 CSS ⇒ 断言全绿也可能交出一条**关不掉的浮层**。凡是"看不见的层"（CSS/布局/层叠/动画），**必须看渲染结果**才算验过。
4. **一条命令拿渲染**：`node scripts/shot.mjs <file.html|url> [--at ms] [--frames n] [--zoom x y w h]` → 再 `read_image`**自己看**。局部对位一律用 `--zoom`（**放大镜 > 整图缩略图**：脚吞掉脚蹬、远脚画在车架之下，都是放大后才看清的）。
5. **动画逐帧看**：`--frames n` 定格多帧，检查**首/中/尾**每个关键状态；静图看不出时序错（腿没落在脚蹬圆上、反向不同步）。
6. **改完立刻复看**：挪一个元素、改一句样式都重拍一次（成本 20 秒）——"改完再看一眼"是默认动作，不是额外步骤。
7. **"缓解措施"也要证明真在跑**：设了 `max-height`/`overflow`/`z-index`/`pointer-events` 这类缓解，要证明**它真的被执行**（加日志、看 computed 值、或故意去掉看是否复发）。反面判例：一条缓解**从落地那天起就是死代码**，被我当"生效"挂了 **4 天**。
8. **收口写"看到的"**：哪一面、多少像素、谁压谁、哪一帧——**不写"应该好了"**。

## 二、核心规则（硬约束）

- **呈现面全覆盖**：多显示器/多入口/多尺寸，逐个验；漏一个不算验过。
- **不猜 CSS**：只读实测值（computed / rect / 像素）；推断必须标注，并写清"要什么条件才能证实"。
- **桩测不算渲染测**：视觉类产物的验收必须落在**渲染结果**上。
- **缓解须证真在跑**：不能只"看起来生效"——要有执行证据。
- **跨口径不相减**：不同视口/缩放/主题下的像素与截图**不可直接比**（先统一口径）。
- **改完必复看**：任何视觉改动都重拍一次。
- **"自己算位置/尺寸"的缓存键必须含全部影响该值的输入**：命中缓存即跳过重算，**漏一格 ⇒ 那一格永远不更新，而且不报错**（比崩溃更难查）。凡自算几何/尺寸并缓存，先列全输入清单（视口 / 侧栏 / 缩放 / 字体 / 主题 / 数据长度 / 相邻元素宽度…），再逐个进键。
- **覆盖层的联动别等 `ResizeObserver` / `window.resize`**：覆盖层靠 `transform` / `absolute` 进出时**布局一个像素都不变** ⇒ **没有任何 resize 事件**。正解＝**语义属性观察器**（`MutationObserver` + `attributeFilter`，认官方**语义属性**、**别认打包哈希类名**）+ **过渡结束后补算一次**（`prefers-reduced-motion` 下没有 `transitionend` ⇒ 必须有定时兜底）。
- **审美/风格类判定先声明"这是印象分"**：模型看图只给**印象**、**不是可复现判据**；同时给主人**可自查的判据清单**（头身比数几个头 / 有无统一白描边 / 平涂还是喷枪 / 背景是否纯白），条件允许就把"眼神变成数字"（底色占比、描边占比脚本）。

## 三、行为准则（软技能）

- 改之前先问**"作用范围是哪些面"**（我曾把"对所有页签生效"说窄成"只关自家两个面板"，被纠正后回头重查）。
- **一次只改一个变量**（别同时改样式与结构，否则数读不出来）。
- 被纠正时**先认再改**，别先辩护。
- 结论标证据级（已证实 / 推断 / 未测）；未测的不许用陈述句。

## 四、踩坑记录（每条 ≤100 字）

- **凭感觉猜 CSS 三次都"好了又复发"**（去 `max-height` / `flex:none` / 余量 −16）——直到拿 devtools **computed 值**一眼定位（Learn 2026-09-05）。
- **桩不解析 CSS**：1801 个公式全绿，交付物仍是一条**关不掉的浮层** ⇒ 绿 ≠ 对。
- **"缓解措施"从落地那天就是死代码**，被当生效挂了 **4 天**（Learn 2026-09-12）⇒ 缓解也要证明被执行。
- **只在主屏拍任务栏就报"已生效"**，副屏还是旧图标（Learn 2026-09-11）⇒ 呈现面漏一块＝验证漏一块。
- **整图缩略图看不出对位错**：脚吞掉脚蹬 / 远脚被画在车架之下，**放大镜 + 逐帧**才逼出来（Learn 2026-09-16）。
- **改视觉前没问作用范围**：我把"所有页签"说窄成"只关自家两个面板"，被主人当场纠正（Learn 2026-09-11）。
- **覆盖层压住固定缩略条**：右侧边栏（`absolute`+`transform` 覆盖层）压住 `position:fixed` 缩略条——250ms 轮询在跑，但几何缓存键只含导轨右缘 ⇒ **命中即不更新**；"有概率"＝该键当时有没有被别处顶掉。修法＝避让量 `min(导轨右缘, 边栏左缘 − 8)` **进比较键** + 语义属性观察器（Learn 2026-09-27）。
- **"模型视觉"不是尺子**：我断言"9 张同族 / 1 张出格 / 3 张带灰底"，主人回"**你眼神不好**"明确不信 ⇒ 印象 ≠ 测量；审美判定**先声明"印象分"**、并给主人可自查的判据清单（Learn 2026-09-27）。
