# distillation — 蒸馏与压缩

> 定位：把「多份材料」收成「一份唯一态」的通用动作，含**执行**与**验收**两半。
> 与邻卡分工（避免三份真相）：`recall-tuning` 管**召回侧验收**——压完还能不能被取到（判据是位次）；`prompt-surface-audit` 管**注入面**——每行值不值得每个会话看到；本卡管**减肥侧**——改完有没有变短、条目有没有只增不减。
> 一句话心法：**验收要能说出"少了哪几条、为什么不少"——说不出就是没验。**

## 一、使用流程（Step 1→6）

| 步 | 动作 | 判据 |
|:--:|:--|:--|
| 1 | **定范围** | 蒸哪个对象（规则件 / 能力包 / 主题）+ 哪批材料；产出输入地图＝实测基线（真跑字节 / 条数）+ 分组草图 + 分流预判 |
| 2 | **读全文** | 🔴 读**原件全文**，不读摘要、不读召回片段——摘要是快照且可能带旧读数，拿它蒸＝蒸出二手规则 |
| 3 | **分流** | 每条落三档之一：**必要**（可复用 + 未覆盖 + 可操作）→ 进唯一态；**无价值**（一次性 / 已覆盖）→ 下沉归档；**素材**（灵感 / 远期）→ 灵感池 |
| 4 | **改唯一态** | 直接改**正文**（不是另写一份并列文档）；同一事实只留一份，原处留指针 |
| 5 | **归位与留痕** | 必要项已进正文；无价值项移出待蒸区；演进台账记一条（日期 + 变更动机） |
| 6 | **验收** | 两把尺——**节点数**与**覆盖**，见 §二 规则 1、2 |

**压缩（既有文档瘦身）另走一遍**：实测基线 → 侦察（grep 骨架）→ **活跃性核查先行**（权威是否已转移）→ 七形态逐条过 → 全文重写 → 字节核对 + 门禁 → 演进台账落账。**判例号保留**（事故坐标）。

## 二、核心规则（硬约束）

1. **验收读节点数，不读体积**——改完路由后：**节点数应下降或持平，而覆盖上升**。只报"X KB 压到 Y KB"**不构成验收**（压得动不等于还在）。
2. 🔴 **条目只增不减 = 用堆规则掩盖路由缺陷**——每次蒸馏若净增条目，先回答"这是新事实，还是我没敢删旧路"。只长的包，病在**路由**不在容量；条目只增不减时不许宣称"已蒸馏"。
3. **蒸前读全文，不读摘要**（Step 2）；判断"某条是否已被覆盖"必须落到**行号级证据**，不靠印象。
4. **改唯一态、不留副本**——修正即改正文，不为同一知识开第二份文档（双写是七形态的头号病）。
5. **压缩七形态**（**逐文件语义压缩**，不是文件级删减）：
   | # | 形态 | 处置 |
   |:--:|:--|:--|
   | ① | **双写**——同知识两处各写 | 留权威，删冗余 |
   | ② | **双源**——跨文件 / 跨包重复 | 统一单源 + 指针 |
   | ③ | **过时**——指向已完成 / 已退役流程 | 删 |
   | ④ | **无意义版本元数据** | 删（沿革台账才是历史真相） |
   | ⑤ | **低信息密度**——段落可表格化 | 段落 → 表 / 行 |
   | ⑥ | **易过时数据**——行数 / 动态计数写死 | 删，改指向**活读数** |
   | ⑦ | **兑现后降级**——设计文档承载的规格已实现 | 骨架留、细节归台账 |
6. **包体精简第一判据＝条目与包定位的一致性**——定位不符的条目**先移出**（去权威文档，或压成一行指针），**再**谈删冗余；顺序反了会删掉搬走才对的东西。
7. **拆包优于报裁**——单包超线且内容**消费频率分层**时，按**工件类型**切包（高频面留核心、轮次型面独立成包），各自独立计预算。
8. **秩序：低损档先做，别跳档**——零损失档（冻结 / 指针化 / 字段化）不需要判断，可机器化；有损档（归并 / 删除）才需要人判，且必须留**可回滚副本**。

## 三、行为准则（软技能）

- **先量基线再动手**：说"压了多少"之前先测；汇报写「改前 → 改后」两个读数，不写形容词。
- **判例号保留，叙事可删**——坐标没了，下次复发认不出是复发。
- **别把"说不清"记成"没必要"**：判不了该不该合的，进待办挂理由，不静默丢弃。
- **一次只改一类病**：同一批里既搬元数据又重写正文，出问题分不清是谁的锅。

## 四、踩坑记录（每条 ≤100 字）

1. **只报体积不报覆盖**：体积读数很容易好看（删几段就行），难的是"删完还找得到"。验收必须落在消费端。
2. **拿摘要当原文蒸**：召回摘要是**快照**且可能带旧读数——蒸出的规则会继承旧错，且错得看不出来。
3. **改唯一态写成了"新增一份"**：新旧并列＝双写，下一次蒸馏要处理两份，越蒸越多（正是要治的病）。
4. **压缩做成文件级删减**：整段砍掉看着干净，连判据的理由一起砍了——七形态是**语义**压缩，不是删文件。
5. **验收只看体积不看条数**：条目数净增而体积下降的"假瘦身"最常见——大文档拆小、条目翻倍。
6. **新立的常态动作没量体量就拿去跑**：本卡落地的同一天，给收工加的那条"顺手通读全量未结项"首次执行即卡住——账本 26 条 / 约 586 KB、单条千字，**收工内跑不动**。⇒ **规则也要先量成本**：常态动作入流程前先量对象体量；体量大时改「扫未结项标题 + 只销判据已满足的」，全量取证交专项。
