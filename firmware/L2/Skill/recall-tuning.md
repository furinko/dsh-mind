# recall-tuning — 召回调优（写得进却召不回）

> 心法一句话：**"召不回"先分三层，别一上来调参；验收判据是"排第几"，不是"命中没有"。**
> 来源：L3 结晶「蒸馏验收看召回不看体积」（私有区，不推送） ·
> L3 结晶「召回复刻真实上工路径」（私有区，不推送） ·
> L3 结晶「搜索面决定结论边界」（私有区，不推送） · `scripts/mind-search-lib.cjs` 注释里留下的**两次同形修复**
> （09-10 精度 · 09-17 量纲）+ Learn 里复发 ≥3 的召回落坑条目。

## 一、使用流程（Step 1→N）

1. **先复刻真实上工路径，再谈"召不回"**：查询必须带**真实调用方的口径**（本仓：`node scripts/mind-prime.mjs "<查询>" --cwd=<项目根>`）。
   项目 key 由 **cwd** 推出——**不带 cwd，项目区整块不参与候选**（只剩 `common`）⇒ 你测到的是**假阴性**。
2. **别手打"检测串"**：验证"某段文字在不在"只用**一个短且唯一的特征词**（或直接 `read` 源文件复制）。
   手打长串（引号 / 助词 / 反引号）差一个字符就判"召不回"——**判据比结论更不可靠**。
3. **三层定位（按顺序，别跳）**：
   - **① 词面**：查询用词与原文用词是否同一套？（中文按**单字**、英文按词切分；近重复是**词面 jaccard** 判据）——
     同义改写、漏字、中英混写 ⇒ 命中率为 0 是**设计**，不是 bug；要改的是**写卡时的用词**（把用户会说的词写进 `triggers`/标签/正文首句）。
   - **② 阈值 vs 真命中分布**：召回下限（`minScore`）的判据**不是"这个值高不高"，而是"它落在真命中分布的哪一段"**——
     先取一次真命中的 score 分布，再看阈值是否**切在分布中间**（本仓实测：0.03 恰好切在真命中分布中部 ⇒ 调到 0.02）。
   - **③ 切块**：整节算相似度会被**分母稀释**（长文里出现一个专有名词也拉不过阈值）⇒ 用**多粒度切块**（整节 + 节内各段 + 标题/tags + 文件名，取最高分块）。**切块只有一份实现**（共享函数），禁各自再写一处。
4. **核对排序量纲**：分数是"排序键"而不是"得分"——看**每一维的"一档"是否 ≥ 另一维的整条量程**（本仓实测：`scopeRank` 一档 100 恰好 = 相关度的整条量程 0~100 ⇒ **同等相关度时，通用结晶永远排在项目卡后面**，哪怕相关度高 2 倍）。
   调权重**要扫曲线**（本仓实测 10 / 100 / 1000 三档定拐点 ×100），不许凭手感改一个数。
5. **验收读"位次"，不读"有没有命中"**：目标是"**目标卡排进 top1/topN**"。只报"命中了"等于没验（命中第 8 位 = 用户看不到）。
6. **跑回归集**：改检索判据后必须重跑回归（本仓 `scripts/search-regression.mjs` + **出厂层**基线 `scripts/regression-baseline.factory.json`：基线记 `{语料数, 命中, top1}`；**分层跑法** —— `--layer=factory` 读出厂层、不带参数读本机私有层基线 ⇒ **别在文档里写死具体基线文件名**，否则分层一改文档立刻变死链）。
   分类拦截口径：**0 = 不劣/首次/语料增量放行 · 1 = 真退化 · 2 = 条数变/锚点丢失/语料减少**；门禁模式下**不许污染指标**（无副作用跑法）。
7. **回读口径**：回归集本身有**采样口径偏差**（本仓 20 条偏项目）⇒ 通用/跨项目结晶要**另做跨项目查询**再验收；所有读数**标注日期 + 口径**（阈值、语料数、查询集），下次复测以新读数为准。

## 二、核心规则（硬约束）

- **先复刻真实路径**：不带调用方口径（cwd / project / topic）测出来的"召不回"不成立。
- **判据自检**：拿"0 命中"当证据前，先用**已知存在的原文**做一次正对照，确认扫描面真的覆盖它。
- **阈值按分布定，不按手感定**：改 `minScore` 前先量真命中 score 分布。
- **切块解决"长文稀释"**：多粒度参评、取最高分块；**唯一实现**，不许第二份。
- **量纲不得互相压过**：任一维的"一档"**必须小于**另一维的整条量程（否则那一维形同虚设）。
- **验收 = 位次 + 回归集**，两项都要；单报"命中数"不算验过。
- **验收落在真消费者上**：候选面绿 / 库级排序绿 **≠ 上工真能取到**——取用端可能有配额或截断（本项目实测过一次「通用层被项目层饿死」：候选进了、`searchL3` 排 top1，但上工注入 0 条）⇒ 必须用**真上工路径**跑一次对照。
- **读数带时效与口径**：写明日期 / 语料数 / 阈值 / 查询集；别人在改的实现**不许拿旧读数当现状**。

## 三、行为准则（软技能）

- **"我测出来是空的"先怀疑测的方式**，再怀疑被测对象（同族：L3 结晶「工具局限不等于事实缺失」（私有区，不推送））。
- **一次只变一个变量**（阈值 / 切块 / 权重分开改，否则读数无法归因）；跨口径的数**不得相减**。
- **先捞免费数据**：已有台账 / 回归基线 / 命中打印往往已够出第一组数，别急着写新探针。
- **改检索实现前先问"这是契约还是参数"**：排序键公式、切块策略属**契约**（牵动全局位次）⇒ 改它要有回归集背书；阈值 / 权重属**可调参数**。
- 报结论时**把偏差摆出来**（"本回归集偏项目 ⇒ 通用结晶效果被低估"），别用一把有偏的尺子下通判。

## 四、踩坑记录（每条 ≤100 字）

- **手打检测串漏字 ⇒ 连判三次"召不回"**：漏中文引号 / 助词 / 反引号，每次都误报"新 Learn 没进召回"⇒ 只用短且唯一的特征词。
- **长文件只取尾部 ⇒ 写了等于没写**：上工只取 Learn **末尾 4 条**，149 条时**前 145 条召不回**——"只增不减"是病灶，验收要在**消费端**。
- **蒸馏只报体积不测召回**：125KB→23KB 很容易，难的是"压完还能被取到"；判据在消费端，验收必须"核心词检索排第一"。
- **阈值切在分布中间**：`minScore` 0.03 实测卡在真命中分布中部 ⇒ 一半真命中被切掉，改 0.02 后回归不退化。
- **排序量纲压过相关度**：`scopeRank` 一档 = 100 = 相关度整条量程 ⇒ 实测相关度**高 2 倍**的新结晶仍排第 2 ⇒ 压到 50 后位次才对。
- **验召回没带 cwd**：三条查询全"未命中"，差点把"卡没生效"写成结论；补 `--cwd` 后新卡以首位进 top5。
- **"命中"≠"可用"**：只报命中数会掩盖"排在第 8 位"；必须报**位次**（top1 / topN）。
- **候选进了 ≠ 取用得到（"饿死"，2026-09-18 实测）**：通用记忆在候选面 ✅、库级排序 ✅（score 23 top1），上工真路径却 **0 条**——取用端项目层用 `minScore: 0` **恒占满 limit** ⇒ `common` 恒零席位（实测项目知识 **32 条** vs limit 5）。修法＝给通用层**保底席位**（`mind-prime.mjs` 的 `GENERAL_MIN`，2 席），并留 ≥1 席给项目层；**验收必须跑真消费者**（同名卡：`verify-integrity`「harness 现加载 ≠ 运行进程」）。
