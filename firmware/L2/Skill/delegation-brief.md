# delegation-brief — 派活任务书（委派三件套）

> 版本：1.0.1 | 2026-09-28 | §四 踩坑记录补第 7 条（任务书的「约束」与「给料」不能自相矛盾）| 1.0.0 | 2026-09-27 | 新建——派活任务书（委派三件套）：入口选择（卡线优先）+ 派前查既有分析 + 任务书三件套（判据带反例面 / 闸门 / 不许自批）+ 落笔前回权威源量口径 + 看返回值与抽查验收；来源＝`mind-private/L1/Learn.md`「派成员 / 建卡整条链」同族 8 例 + 1 条正向实测；判据三条全过（跨项目可复用 / 有验证过的逻辑 / 以后还会遇到）。

> 心法一句话：**派活的成败在你落笔那一刻就定了——任务书里没写的判据，成员不会替你想到。**
> 来源：私有区 `mind-private/L1/Learn.md` 的「派成员 / 建卡整条链」同族 **8 例**（2026-09-24→09-27：
> 不查卡线 → 建卡参数错配 → 派错岗 → 派活前没读既有分析 → 任务书数字凭印象 → 成员自述不可采信）
> + 一条**正向实测**（独立成员第一次真跑就抓出真 bug）。口径真源＝`packages/dshome/lib/host/agent-roles.js`。

## 一、使用流程（Step 1→N）

1. **先定线（入口选择）**：派活前先 `role_list` 查有没有匹配的岗位卡——**有 ⇒ 走 `role_spawn`**（带卡的工具面 + 执行期闸 + 写范围）；**岗位对不上卡 ⇒ 才退到官方 `subagent`**（裸线**无工具面闸**，"只读 / 别写"全靠 prompt 撑着）。同 id 时项目卡覆盖私密卡，别凭印象猜卡里有什么。
2. **先查"这件事有没有既有的分析"**：grep `mind-private/L1/Dream.md`（灵感池）→ `mind-private/tasks/pending/` → 项目 `project.md` 的待办节 → L3 同主题知识。**既有分析不是参考读物，是规格的一部分**——漏了它，成员只能在文件内找同族（必然压不动），结论还会错记成"极限"。
3. **冻结规格 + 写任务书三件套**：① **判据**（含**能造坏的反例面**——写不出反例＝没验过）② **闸门**（**哪一步不过就停**）③ 明写"**不许自批 / 越界要标注**"。
4. **划工具面与写范围**：`write_scope` 给路径白名单（目录前缀或具体文件）；**不给 ⇒ `unbounded`**（只留痕、不拦）。⚠️ `pwsh` 不受路径闸约束 ⇒ 行为契约仍算数。
5. **起成员后看返回值**：`guardInstalled` 必须 true；`toolFace` 是 `restricted` 还是 `unrestricted`（`unrestricted` ＝该成员权限＝你的全部权限）；`ownScopeTools` 非空要说明（那是 `restrict` 裁不掉的自注册工具，仍在执行期闸枪口下）。⚠️ `role_send` **首次**唤醒返回的 `guardInstalled:false` 是延迟补装的**正常快照**，不是失败。
6. **验收只抽查关键证据**：读关键文件 / 复跑关键命令 / 独立复算——**不采信"已验证"自述**。
7. **收口**：成员完成后由 Lead 裁剪后呈现；改卡 / 建卡走正规通道（`role_card_write` / `role_card_rename` / `role_card_retire`），别用通用写工具直接改卡文件（无乐观锁、无原子写、无留痕）。

## 二、核心规则（硬约束）

- **任务书三件套缺一不可**：判据（带反例面）+ 闸门（不过就停）+ "不许自批 / 越界标注"。
- **凡要写进任务书的数量 / 分布 / 签名 / 引文，落笔前先回权威源核一次**：数量跑一条命令自己量、引文 grep 原句抓出来、签名读代码——**不转述**（"某人说 / 文档写 / 成员回执"都不算依据；口径类数字一律自己量）。
- **被管方不得自批**：成员在判据字面不满足时要**停下、标注越界、把判决权交回 Lead**。
- **主人用词可能与我的术语体系冲突**：先复述一遍再动手（"你说的 X 是指 A 还是 B？"）——同一个词在我的体系里有专有含义时，第一反应听到的那个意思往往正是最容易读反的地方。
- **成员工具面 = 卡声明 + 固定级联闸**：`subagent` / `subagent_fork` / `workflow` / `ralph` 一律在**调用期**被拒（但仍列在工具表里——**列着 ≠ 能用**）。
- **不给 `write_scope` ⇒ `unbounded`**：只留痕不拦，别把"没被拦"当成"没风险"。

## 三、行为准则（软技能）

- 成员名用**中文短名**（它进子代理列表的标题）；同一张卡起了多个成员时，"按卡 id 发消息"会因**不唯一**被拒 ⇒ 要用成员 name / childId 指明。
- 同时起多个成员时**别让它们写同一个文件**（尤其索引类文件）——交叉写会互相覆盖；"同一事实有多个落点"的索引类文件由 Lead 收口。
- 成员的中间态可能是"**假红**"（并发写者在同一工作区跑"注入→跑→还原"循环时的读数不算数）。
- 派活省下来的是**上下文**，不是时间；"怕共享工作区被乱写"不是取消分工的理由——该用 `write_scope` **闸**，不是取消分工。
- 成员回报里的话当线索、不当结论：它说"已验证"，我去读文件 / 复跑命令。

## 四、踩坑记录（每条 ≤100 字）

- **内联建卡的 `name` 会同时当卡 `id`（只允许 ASCII）**：中文名建卡 ⇒ `saved:true` 但 `role_list` 判「id 不合法」＝坏卡。
- **`role` 与 `persona` 同给 ⇒ `persona` 静默忽略**：信号＝`saved:false` + `cardPath:""` + label 前半是 `role` 卡名。
- **派活前没查既有分析**：`Dream.md` 里早写着的同一问题分析 + 两条前置路径没进任务书 ⇒ 任务书缺规格、结论错记成"极限"。
- **任务书里的数字凭印象**：51 个文件的分布写成"17/7"（实为 16/8）、引文把"立刻开跑"写成"立即开路"——两处都被成员用实测 / 快照当场纠正。
- **隔离 harness 漏传 `DSH_HOME`**：被隔离的模块在环境不满足时**静默回退真环境** ⇒ 假会话写进真台账（污染真数据）。
- **成员"已验证"自述不可采信**：12 张卡的交付回执写"入口配额 ✦3"，按表体数实为 **✦4**。
- **任务书的「约束」与「给料」不能打架**（09-27）：写「其余不动」却给整行替换文本 ⇒ 原文被替掉；写「放在 §四 之前」⇒ 顺序成 三→五→四。默认：**给整行文本就别写「其余不动」，给位置写「顺序必须一二三四五」**。
