# verify-integrity — 验证完整性

> "我记得它能跑"和"我证明过它能跑"之间，隔着一整套可以被反例推翻的动作。

## 一、四条规则

| # | 规则 | 判据 |
|---|------|------|
| 1 | **真加载** | 我跑的是真模块、真入口、真分支，还是只看了语法、只读了字符串、只 mock 了形状？ |
| 2 | **反例证伪** | 我能写出一个**让它报警的坏状态**吗？写不出，就等于没验过。 |
| 3 | **不污染被测对象** | 这次验证有没有顺手改变被测对象（真实数据、开关、状态文件）？ |
| 4 | **响亮失败** | 失败时它是**报错退出**，还是静默跳过并打印全绿？ |

四条缺任何一条，绿灯的信息量都归零。

## 二、为什么需要它

2026-09-11 的 P 阶段里，同一批改动共出现 **7 次"验证给了我错误结论"**，全部属于"验证过程改变了、或被改变了被测对象"：

| # | 现象 | 归类 |
|---|------|------|
| 1 | 脚本只 import 模块、不调入口函数，打印全绿 | 违反 1 真加载 |
| 2 | 用例内容里带敏感词，隐私门禁先把全部用例拦掉，被测门禁根本没被执行 | 违反 3 不污染 |
| 3 | 忘了高风险开关当时是开着的，自改类用例被短路放行，结论全反 | 违反 3 不污染 |
| 4 | 验证脚本自己往真实待裁决队列塞了几十条假记录 | 违反 3 不污染 |
| 5 | 用 shell 直接改放行真源来"造场景"（越权，且正好演示了 shell 绕过） | 违反 3 不污染 |
| 6 | 门禁判断用 `undefined` 开头（无输入）被当成"无风险"跳过 | 违反 4 响亮失败 |
| 7 | 删掉一个挂载行就能让守卫恒为 false，而旧脚本仍然打印全绿 | 违反 2 反例证伪 |

**最有效的一步不是加检查，而是加反例**：删挂载行、把守卫强制置 false，让新脚本报出"缺少核心心智插件""行为断言未通过"，而旧脚本对同样的坏状态打印 ✅。绿灯的信息量，取决于它**能不能变红**。

## 三、做法

1. **先写坏状态，再写结论**。任何"通过"之前，先构造一个必须失败的场景，确认脚本会失败。
2. **验证脚本自己必须是幂等的**：跑之前记录、跑之后还原被它碰过的真实文件；宁可只读，也不要"为了造场景"去改真源。
3. **隔离变量**：一次只让一个门禁被触发。多个门禁并联时，先用不触发其它门禁的中性内容确认目标门禁真的执行了。
4. **有开关先查开关**：任何"放行/拦截"结论，先确认当时的全局开关与身份，否则结论无效。
5. **无输入、空集合、缺文件一律按失败处理**，不允许"跳过即通过"。
6. **证明"线上跑的就是我改的代码"**（2026-09-11 补，判据配方）：挑一条**只有新版才有**的分支当判别器（旧版绝无此行为），配一组**正例 / 反例**——正例必须产生新痕迹、反例必须**完全不**产生（本次：`pwsh` 命令文本含「心智区路径+写入类动作」→ marker 追加一行；不含 → 行数不变）。配上"启动时写入的时间戳行"，三条齐了才叫"生效"。只看文件 mtime、或"我重启了应该生效了"，都不算。
7. **测门禁/守卫这类机制时，探针必须对被测资产零风险**（2026-09-11 补）：先 `snapshot` 兜底（万一是 fail-open、改动真落地也能一键还原），探针本身取**不可见且可逆**的最小改动；动手前先问自己"**如果它没拦住，我会损失什么**"。
8. **调参/改口径类改动，先离线扫参数矩阵，再动代码**（2026-09-11 补）：把候选变体 × 候选阈值列成矩阵，用现成回归集打分，**看数选**——本次靠它避免了两处误判：① 覆盖率口径也能满分但平均候选翻倍（4.1 vs 2.1），**能不动分母就不动**；② "把文件名并进元信息块"看着更全，实测 **9/10**（块变长→分母膨胀），而**单独成块** 10/10 且多救回一条查询。→ 结论：**"信息更多"不等于"召回更好"**；凡有回归集，就先扫矩阵；**并且要用反例否掉那个"看起来更全"的选项**，否则很容易凭直觉选错。
9. **对自身 / 自身系统评分（含对比评分）必须走「盲评 + 分档锚 + 证据指针」，且判据不许由被评方自选**（2026-09-11 补，**同型复发第 2 次**）：评分看着比"自评"客观（有维度、有分数、有证据），**但维度和判据若由被评方拟定，形式上的参照系就掩盖了实质上的主观**——警惕心反而比自评时更低。实证：给 DSHOME vs 外部项目打 8 维分，其中「工程健康度」**是我自己加的、也是我唯一大幅领先的一维**（+2.5）；而我打 **8.5** 的「门禁与验证」**当天就被自己的审计推翻**（判效回填 0 条 / 蒸馏从未触发 / 同类复发第 8 次，三件全落在这一维里）。⇒ 三件套：① **盲评**（独立子代理或他人，被评方不参与定表）；② **分档锚**（每档配可核对的实例，不给孤立数字）；③ **证据指针**（每条挂路径）。**另加硬约束：评分必须写「这个分数在哪个条件下不成立」**——实证显示那行限定才是后来审计的靶心，**分数只是它的包装**。

10. **判据也是「消费者」：改数据形状/行为必须同批改判据；判活复刻用户路径；诊断先打码**（2026-09-12 补，同日四处实证）：① **改形状前先 grep 谁在读它**——为让会话 `source` 合规把 `kind:'agent-instructions'` 换成 `plugin+form:'instructions'`，而 `verify-host-plugins` 的行为断言**正按旧 kind 找那条消息** ⇒ 断言恒红、**pre-commit 第③步卡死提交**（修好事故、却打红门禁，且报告自述"全部验证"里恰无此项）。② **别拿"会自动替你纠错的工具"当判据**——`GET /?token=…` 的真实响应是 **303 + Set-Cookie**（200 只在**带 cookie 跟跳之后**），而 curl/PowerShell **自动跟跳转** ⇒ 看它们的结果会把 303 误判成 200。判活要**复刻用户真实落地路径**（拿 cookie → 带 cookie 求 200 → 才认 200），并让**失败信息带实测 status**（这次正是 `status=303` 一眼指路）。③ **打印诊断先打码**——失败路径常整体打印 stdout 尾巴，而它含凭据（后端会把带 token 的 URL 打进日志）；`tail(out)` 一律先过 mask，否则 CI 日志留明文凭据（本站由独立复核员抓到并修，A/B：修前明文 ×1 / 修后 ×0）。④ **`--expect-fail` 不是判别力证据**——它对**任何**失败都判 PASS（端口占用、环境错、判据自己恒红都算"预期失败"）；判别力只能靠**正向跑 + 刻意构造的坏输入被判红**。

11. **每轮审查必问：这条门禁 / 判据的「盲区」是什么**（2026-09-12 补，收编自 CH4 v1.0.4 的 F2 修复轮——他们把「**校验盲区**」当**定期审查项**专门修一轮，同轮还修了判据 A2 / 快照对账 / 泛型归一）。
    **为什么它是固定一问而不是"想起来就问"**：盲区**不会自己报警**——门禁绿着，盲区就是绿的。2026-09-12 一天之内同一件事被撞出三个实例，全是"机制在、覆盖不全"：
    | 盲区 | 表现 |
    |---|---|
    | `verify-host-plugins` 按**文件路径** import | 绕过 `package.json` exports ⇒ 漏登记照样 11/11 绿，后端 boot 必死 |
    | marker「保护现场」的快照拍在**破坏之后** | 保护从未生效，每跑一次门禁伪造一条假 `mounted:` 行 |
    | 放行额度是**一次性消费** | 一次"未落盘的重试"就会烧掉额度（写成功才该消费） |
    **落地判据（现在有机器支撑）**：① 报"某门禁通过"之前，先说出**它真正覆盖的那条路径**；② 每条门禁写清"**它看不见什么**"（`scripts/gate-ledger.mjs --check` 已把"谁没有反证"做成台账 + 棘轮）；③ 自检要比**整轮起点基线 vs 终态**，不是局部前后（局部前后对"顺序错位"天然失明）。

12. **处置方式要分档：不可逆 / 危险动作 → 硬拒；判断类 / 可逆动作 → 放行**（2026-09-12 补，收编自 CH4 v1.0.4 语料层：写文件 / `Start-Process` / `ReadKey` 在**积木侧词法拦截**并返回 `ERR|`，**没有任何人工确认环节**）。
    **两者的分工不是风格问题**：危险动作走**放行面板**（人在环）看着更稳，但**混用会两头失效**——2026-09-12 实测：一次"未落盘的重试"把放行额度**烧掉**（正解应是"写成功才消费"），而当天真正不可逆的动作（改放行真源、批量覆盖目标目录、发布）其实更适合**硬拒**，不该提供一个会被点习惯的按钮。
    **判据**：① 先问"**这一步能不能撤销**"——不能撤销（删除 / 发布 / 覆盖目录 / 改放行真源）⇒ 机制层**直接拒绝**，不设"批一下就过"的通道；② 可撤销但需人判断（改规则 / 改口径 / 装插件）⇒ 走放行面板，且额度必须**一次性、写成功才消费**；③ 任何"放行"都不构成授权（`isApproved` 语义）——硬拒档如果留了后门，等于没拒。

13. **修复路径也是被测面：判据给出的「重建 / 修复」指令，必须自己真跑过一次**（2026-09-19 补，当日实测）：`pre-commit ⑬` 红了并印出指令「跑 `--update-baseline` 重建后提交」，**照做即崩**——`search-regression.mjs:165` 用了 `NO_SIDE_EFFECT`，而它 `:187` 才 `const` 声明（TDZ `ReferenceError`）。**为什么语法检查与真跑冒烟全绿**：不带该参数时 `updateBaseline && NO_SIDE_EFFECT` **短路求值**，那个标识符**永不求值** ⇒ 那行代码**从未执行过**，「修复路径」整条不在被测面内。同批还暴露该门禁的**基线从来没对过**（记 `items 20 / corpus 60`，实况 `31 / 15`）：它挂链（09-17）当日起就是红的，只因 `scripts/hooks/` 的源没装进 `.git/hooks/`（85 vs 125 行）而**无人看见**。
    **判据**：① 凡判据 / 脚本会**印出修复指令**的，那条指令必须**进过一次被测面**（真跑 + 断言退出码）——"我给你出路"与"出路能走"是两件事；② 查"机制在不在跑"要问**它挂在哪条链、那条链最后一次真跑是什么时候**（**有源 ≠ 已装**）；③ **基线 / 参考线类判据要自证"基线跟实况对得上吗"**，否则它可能**自诞生起就恒红**；④ 与配方 ⑩ 合看：**判据的盲区常常正好落在"它自己的修复路径"上**。

14. **判据要报出「它覆盖了哪几维」；校验面只含活文档面**（2026-09-19 补，同日三例实证）：
    ① **判据漏轴**——台账九行曾被追加到文件末尾的变更日志区，而每次提交前的行序校验都打 **PASS**（**序号 1..N 是对的、位置是错的**）：洞不在"没跑校验"，而在**判据只覆盖维度 A（序号），维度 B（位置）从没进过判据**。⇒ 报"通过"之前先**列出它检查了哪几维**，并**逐维配一条反例**（位置 / 序 / 计数 / 去重各一条）；同批写清「**它不检查什么**」——否则"全绿"会被读成"面面俱到"。
    ② **校验面 = 活文档面**——给 `related` 死链检查排除 `TRASH` 后，critical **反而 5→6**：我自己刚落的 5 份**改前快照**（源文件的字节副本）带着同样的死链进了扫描面。历史留痕面（TRASH / `snapshots` / archives）按定义是"当时的字节副本"、且**不许改**（改了即毁证据与回滚点）⇒ 产出**永远修不掉的 critical**。收窄时必须**显式上报跳过数**（本次 154 文件 / 19 带 related，不静默全绿），并配**双向反例**：活文档塞死链 → 照红；留痕面塞同样的死链 → 不报但跳过数 154→155。
    ③ **反例必须带"未改动基线必须 PASS"这一列**——反例脚本把用例名 `..._nostrict` 里的 `strict` 用 `-match 'strict'` 判成 `-Strict`（**`nostrict` 里也含 `strict`**）⇒ 正例被记成 FAIL，差点得出"门禁行为不对"。只有基线列能把「**门禁对**」与「**我的脚本错**」分开；**别用子串匹配判定枚举值**（同族：靠名字推语义）。

15. **变异反证前先读判据、先写定还原路径**（2026-09-24 实证，两处翻车）：
    ① **变色条件要先读出来**——给 `verify-l1-versions` 造「头版本 1.3 / 尾 1.4」的变异，门禁**没红**（它把"头≠尾"当**历史遗留、只提示**）；它真正的红条件是「**内容变但版本行没变**」。⇒ 设计变异前**先读判据代码/输出**，确认"什么条件下它会红"，否则"变异没变红"分不清是**门禁瞎**还是**变异没打中**（同族：配方 ⑭① 判据漏轴）。
    ② **还原路径必须写定、禁用 `git checkout --`**——这类门禁读的是**暂存面**（"本次提交无 L1 改动 → 跳过"），所以变异必须先 `git add`；一旦 add，**索引里就是变异版**，`git checkout -- <file>` 取回的就是**变异版**——"还原"变成还原成变异体（靠残留关键词扫描才抓到）。⇒ 还原只用**权威副本**（改前快照 / 原文重写），还原后**必扫残留**（关键词 + `git status`）+ **复跑门禁转绿**才算收（同族：配方 2「不污染被测对象」）。

16. **「没事发生」不等于「机制救了你」——给因果定锚，要找一条「只有机制介入才会踩的时相 / 计数 / 顺序」**（2026-09-24 实证，真机验收自治串行闸）：
    **病灶**：验收判据是「两条自治会话不重叠」，看着是绿灯——但它**同时兼容三种世界**：① 闸真拦了；② 第二条本来就晚触发；③ 两条根本没同批。**只断言「不重叠」＝只证明了「没观测到反例」**（测试侧同型口诀：**只断言「不并发」会假绿**）。
    **做法**：先找两条路径各自的**指纹**——原生到点恒**对齐调度边界**（整分），被闸放行恒**对齐前一个会话的结束**；再**故意拉长第一个会话**，把两种指纹拉开到远超噪声（本次 A 跑 100s ⇒ 两种指纹相距 40s），于是三种世界**三向可区分**：对齐整分＝没走闸 · 对齐会话结束＝闸放行 · 对齐下一个整分＝入了队但没被放行。
    **实测读数**（自治会话运行台账，`since = ts - durationMs` 反推触发时刻）：A2 起 16:32:00.151（整分 ✓）止 16:33:43.947；B2 起 16:33:44.105 ＝ **A 结束 + 158ms**，且比它自己下一次整分早 16s ⇒ B 只可能「入队 → 放闸补跑」。旁证：降级台账行 = 0（走的是正路，不是降级面）。
    **判据**：报「机制生效」之前先答一句——**「如果机制没生效，这次的观测会长成什么样？」** 答不出 ⇒ 这条绿灯只值「没出事」，不值「它在干活」。（同族：配方 ② 反例证伪——写不出坏状态＝没验过；⑭① 判据漏轴；⑪ 门禁盲区。）

17. **报「绿」之前，先指明绿的「是哪个面」——一条检查的结论只在它真正跑过的那个面上成立**（2026-09-26 收录，本仓库三条实录，可 `grep` 复核）：
    **病灶**：「**暂存区 / 工作区 / HEAD / 推送面**」是**四个不同的面**；门禁只跑了其中一个面，人却按另一个面读结论。⇒ 说「**全绿 / 已提交 / 已推送**」时，必须同时说清**是哪个面绿**——**面不匹配时，「绿」不是证据**。
    **三条实录**（都在本仓库发生过，不是虚构情节）：
    | # | 实录（判据代码/证据） | 面错位形态 |
    |---|---|---|
    | ① | `scripts/verify-scripts-run.mjs` **不带 `--all`** 时候选池 ＝ **已暂存（`git diff --cached`）的脚本**（`stagedScripts()` :120 → `pool = allMode ? [...SAFE] : staged` :168） | 新文件没 `git add` ⇒ **不进池** ⇒ 打印「无可跑候选」并 `exit 0`——**「跑了 0 个」被读成了「通过了」** |

18. **判据要能认出「上游收口了」；宣称写下的路径要用一次真动作走通**（2026-09-27 收录，两处实录）：
    **病灶**：判据只挡了「错」的那一半——**上游一旦把事情做对，判据不是放行，而是炸**。
    ① **「冲突已解」这条路没实现**：config 生成器对一处锚冲突只实现了「**报冲突**」（`status=CONFLICT-UNRESOLVED` ＋ 两条候选 ＋ `value=null`），**没有「设计侧已统一 ⇒ 落值」这条路径**。设计侧回填之后，生成器不是"自动填上"而是**响亮失败**（`could not read legacy anchor … matched 0 time(s)`，exit 1）——而 `接续须知` / 接口契约里写着「**裁完重跑生成器即自动填上**」：**那句宣称当时是空头**（文档宣称有 ≠ 机制在跑）。
    ② **零判据的宣称**：某 runtime 文件头反复宣称「三个未定字段的起测值在读数里看得见（`null_fields`）」，而 `grep null_fields tests/` = **零引用** ⇒ 忘了带 / 带错 / 恒为空，套件全绿；它恰是那份实现里**唯一**用来对冲"runtime 里编数"风险的机制。
    **判据**：① **判据/机制要认三态**——真冲突（报警）· **上游已收口（落值 / 前进）** · 真读不到（响亮失败）；把"上游收口"误当"读不到"，等于机制在上游一动作时从"该自动"变成"该炸"；② 写下「**只要 X 就会 Y**」的宣称时，**顺手 grep 那个 X 的判据**（`grep 零引用` 是最便宜的落地审计）；③ 给宣称补判据时**取值要避开默认值**（本次取 0.9 / 7 / 2.5 而非起测值 0.5 / 15 / 1.0——同值会让判据分不清"读了真源"还是"读了默认"），且**双向**断言（填上 ⇒ 用真源 ＋ 清单变空；抽掉 ⇒ 默认值回来 ＋ 清单复原）。
    （同族：配方 ⑭① 判据漏轴 · 配方 ⑰ 报绿的是哪个面 · 配方 ⑪ 门禁盲区 · `landing-audit` 三查「定义 / 接线 / 数据」。）

19. **判据工具不得污染被测对象；"真加载"要落在真模块作用域上，并断言"那件事真发生了"。**（2026-09-27 同一次交付里连撞两处）① **"抽函数 + 同形桩"绕过真作用域**：249 项判据全绿，却漏掉"通知插件每投递一次就把后端 `exit 1` 杀掉"——那些判据把被测函数从源码**抽出来**、配**自带 `settings` 形参**的桩，验的是"这段逻辑对不对"，不是"它在真模块里跑不跑得起来"；而且**没有一条判据真触发过投递路径**（只断言"没抛"）。修法＝补一节"**真 import 真模块 + 假宿主 `apply` + 真触发路径 + 真投递计数（没走到就硬失败）+ 变异必红**"。② **变异套件污染被测对象**：`--mutate` 用"原地注入→跑→还原"改**工作区源文件**，某次没还原回去，文件就此坏掉（插件 import 即抛），还被并发的打包同步吸进快照；而它自报 `restored=True` 是**自欺**（比的是"写回后内容 vs 写前文本"，还原语句没执行时这校验等于没校验）。⇒ 默认：变异**一律在副本上做**（相对导入要留同目录）；非要原地则必须"**结束前逐文件 sha 与开跑前比对，漂移即响亮失败 + 从备份自动恢复**"，且这条自证自身要有反例；**同步/打包前先 sha 对一遍源文件**。③ **改动面自证**：凡**动引用关系**的改动（改名 / 把变量从外作用域搬进内作用域 / 抽函数），改完必须自证**没有残留旧引用**——**改名后 `Select-String -Path <file> -Pattern <旧名>` 必须为 0**；**搬作用域前先 grep 该名在本文件的全部出现位置**（2026-09-11 实录：我漏了 20 行后的一处 ⇒ `node --check` 全绿、真跑 `ReferenceError`，见 `scripts/verify-scripts-run.mjs`）。（同族：配方 2 不污染被测对象 · ⑪ 门禁盲区 · ⑰ 报绿指明是哪个面。）

20. **判据的参照物必须是稳定的——环境一变假红、提交一次恒红，都是把判据建在流沙上**（2026-09-27 补，修「右侧栏掉缩略图 + 心智面板慢」时新写的门禁**连拆四处"判据自我失效"面**）：
    **病灶**：判据的逻辑没错、读数也都是真的——错的是它**拿什么当参照物**；参照物会随环境或提交而变，绿灯就随时变红，而且**红得毫无信息量**（不是"东西坏了"，是"参照物走了"）。四处自查表：

    | # | 自查表（本轮四处） | 失效形态 |
    |---|---|---|
    | ① | 三条拿**真实环境的数据量**当阈值：`TRASH 快照数 < 50 ⇒ FAIL` · `TRASH 层节点 ≤ 6` · `trashKept ≥ 1` | **环境一变就假红**——本仓**已有** `scripts/trash-sweep.mjs` / `scripts/snap-prune.mjs` 两个会清 TRASH 的机器件（cron 还会自己跑它们）⇒ 快照被清、读数归零，判据必 FAIL。实测：把快照数置 0 后旧口径直接 FAIL，而那**不是**代码坏了 |
    | ② | 一条拿 `git show HEAD:` 当"**改动前版本**"的对照臂（断言"HEAD 里必须还是旧写法"） | **提交一次即恒红**——改动一进 HEAD，前提就永久不成立；此后每次跑都红，且**永远修不好**（除非回滚这次修复） |
    | ③ | 顺带查出一条**从建立起就没红过的恒绿假绿**：`兜底后缀卡 ≤ 40`（真树实测 5；把规则模拟退化后也只到 28） | 上限 40 永远够 ⇒ **没有任何坏状态能让它变红** ≡ 违反配方 ②（写不出反例＝没验过）。它不是"覆盖了"，是"从没被用过" |

    **做法（三条一起改）**：
    - **判别力一律放夹具**：自造输入（临时目录 / 假树 / 假快照列表）、与环境无关——夹具里那条坏输入**必须红**、好输入**必须绿**；夹具里的坏状态就是这条判据的**存在证明**。
    - **真树 / 真实读数只作 `[info]`**：量真实环境的那几条（本轮：TRASH 快照 5 个 · 真树兜底卡 5 张）照常打印，但**不参与成败**（读数给人看，判据由夹具定）；上限类判据额外报**实测峰值**（"峰值 28 / 上限 40"），上限还合不合理才有人能复查。
    - **对照臂不许依赖 `git HEAD` 的相对位置**：要"改动前版本"就用**改前快照 / 权威副本**（`scripts/evolve-log.mjs snapshot` 的产物）；或者干脆换成**行为对照臂**——旧口径 vs 新口径各跑同一套夹具，比**输出**而不是比 git 里的字节。
    **判据**：写下任何一条阈值的**那一刻**问两句——① **这个数会自己变吗**（有没有别的机器件 / cron / 用户操作会动它）？② **它今天变红了，是"东西坏了"还是"参照物走了"**？答不出 ⇒ 这个量不配当参照物。
    （同族：配方 ② 反例证伪（③ 正是"写不出反例"的标本）· 配方 ⑪ 门禁盲区 · 配方 ⑬③ 基线要自证跟实况对得上 · 配方 ⑯ 因果定锚——**"红"也要能归因**。）

    **参照物稳定性的第三种形态（夹具的 `env` 作用域）**：夹具的 `env` 作用域要覆盖被测代码的**整个使用期**——被测模块在**调用期**读 `process.env`（如 `packages/dshome-mind/lib/index.cjs` 的 `repoRoot()`），而夹具只把 env 钉在**加载期**（`finally` 里还原）⇒ 被测代码拿到**真环境**的数据 ⇒ **假红甚至污染真数据**。实录（**修法前**）：`scripts/verify-mind-panel-labels.mjs` 报 **FAIL 8/17**（`DSH_HOME` 已设时 actual 列了 **9 张真卡名**），清空 `DSH_HOME` 则 **PASS 17/17**（＝**只改一个变量**的对照实验）；修法＝**env 作用域提到整个夹具块**（加载 + 断言都在这一段里）；落地后复测：**设 / 不设 `DSH_HOME` 各跑一次都 PASS 17/17** + `--self-test` **SELF-TEST PASS 20/20**（反证仍各自命中）。⇒ **定位环境敏感缺陷最便宜的手段 = 只改一个变量的对照实验**。

21. **改"被机制读取"的正文/数据前，先找到它的读者并量出口径——归档≠删，但读者必须零感知**（2026-09-27 收录，真实读数）：
    **实录**：`project.md` 整节指针化，**274,367 → 160,365 字节（−41%）**；而 `scripts/mind-prime.mjs` 的 R1 装配**正是从「进度状态」节取行** ⇒ 若直接整节指针化，**上工召回会被打空**。
    **成法四步**：① 归档前**先读消费者代码**、量出它到底取哪几行；② 用机器件搬（`node scripts/memory-archive.mjs --apply --file … --only …`；它把原文**逐字节**落 `L3/history/` 副本并给源文件留时间戳备份，但**脚本自己只写不校验** ⇒ **落刀前自己核一遍 history 副本 vs 原文逐字节一致**）；③ **补回活摘要**（把那几条复制回指针块下 + 一行注释写明口径）；④ **验收 ＝ 真跑消费者**（`node scripts/mind-prime.mjs "<任务>" --cwd <项目>` 看装配块）——**不是"validate 绿就算"**。
    （同族：配方 ⑩① 「改形状前先 grep 谁在读它」· `mind/L2/Skill/prompt-surface-audit.md` 的「机制承诺的引用真实性」。）

22. **判据的「匹配口径」本身就是覆盖面的一部分——同义形态没枚举完，判据就只覆盖了其中一支**（2026-09-28 收录，本机/本仓三处实录，跨 09-23 → 09-28 同型复发）：
    **病灶**：判据/闸/门禁写下的其实是**两件事**——「**判什么**」和「**按什么口径匹配**」。人读的时候只看见前者；后者落成代码里一个 `includes`、一个 basename、一次前缀比较，就**悄悄定死了覆盖面**——绿与"0 命中"都只是那**一支**的读数。
    **三条判据**：
    ① **匹配口径＝覆盖面的一部分**——写判据/闸/门禁时，必须把**同义形态**一起枚举：**大小写 · 前缀 · 全半角 · 戳落在哪一段（文件名 / 目录名 / 路径前缀）**…… 同一件事的不同形态没枚举完，判据就只覆盖了其中一支。
    ② **报「0 命中」时必须连匹配口径一起报**——只报"0 命中"不报口径，这个 0 **不可复算**、也**不构成证据**（同族口径：0 命中 ≠ 不存在——报 0 要带**搜索面 / 分母** + **正对照**）。
    ③ **独立臂先问「它和被测实现是否共用同一口径」**——共用了 ⇒ 它只能验**实现漂移**，验不了**定义错误**；定义面必须另配一条**结果导向**的判据（本例：**重名组 = 0** 才是那条抓得住定义错误的臂）。
    **三处实录**：

    | # | 实录 | 漏掉的那一支 |
    |---|---|---|
    | ① | **09-23**：一处**区分大小写**的 `includes`，让 3 处真私密名在 `origin/main` 上**假绿**数日；改成大小写不敏感后当场报出 5 处 | 大小写 |
    | ② | **09-24**：某角色卡的路径闸「绝对路径 + `..`」**真绕过**——绝对路径不进 `resolve`，而判定是**字符串前缀匹配** | 路径形态（绝对 / 相对） |
    | ③ | **09-28**：`TRASH` 归档过滤只认**文件 basename** 上的 `__` 戳，漏掉长在**目录名**上的同类戳 ⇒ 活图谱 14 个归档副本漏进图、4 组重名；而拿**同一条 basename 口径**做独立期望的 `scripts/verify-mind-graph-trash-snapshots.mjs` **13/13 全绿** ⇒ **不构成反证**（正是判据 ③ 的标本） | 戳落在哪一段（文件名 / 目录名）+ 独立臂共用口径 |

    （同族：配方 ② 反例证伪 · ⑪ 门禁盲区「它看不见什么」· ⑭① 判据漏轴 · ⑰ 报绿的是哪个面 · ⑳① 拿真实环境数据量当阈值——**五条问的是同一件事：这条绿到底覆盖了哪一支**。）

## 四、底线

- 绿灯只值它**被证伪过一次**之后的那部分。
- 别把"加检查"当成绩，先问**它能不能变红**。
- 别用"再想一遍"代替证伪；再想一遍得到的是同一个我。
- 给自己打分时，先问：**这张评分表的维度是谁选的？**（判据由被评方拟定＝替自己划考场）
