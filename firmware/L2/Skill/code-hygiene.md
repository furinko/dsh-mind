# code-hygiene — AI 代码卫生（生成时的四条铁律）

> 心法一句话：**AI 写代码的默认病不是"写错"，是"写多"**——多一套实现、多一个入口、多一层包装、多一段复述注释；本卡治的就是这个。
> 完整版（含违规/合规代码对照 + 检测器命令 + 项目级风格覆盖附录）在 `~/.agents/skills/code-hygiene/SKILL.md`；
> 本卡只写执行要点与判据，**不做第二份真相**。
> 来源：主人需求「生成的代码要干净 / 单源 / 相同功能不做多种方法 / 注释完整」（2026-10-04）。

## 一、使用流程（生成前动作序，不许跳步）

1. **先搜后写**：动笔前 grep 同功能实现——**同义命名一起搜**（例：`normalizeUrl` / `normalize_url` / `规范化URL`）。
2. **命中即改造**：改既有实现（加可选参数 / 改返回值），改完**一次性更新全部调用点**。
3. **未命中才新建**，且只建**一个**入口。
4. **写完过交付四问**（见 §二 末条）。
5. **能跑则跑兜底检测**：`tsc --noUnusedLocals --noUnusedParameters` / `knip`（未使用导出）/ `jscpd`（重复率）；跑不了就**说明未跑**，不得写"已验证"。

## 二、核心规则（硬约束）

- **单源**：一个功能全仓只有一处实现。发现第二处 ⇒ 立即合并，不留"暂时并存"。
- **入口唯一**：参数差异用可选参数 / options 吸收；**禁止** `xxxV2`、`xxxWithOptions`、`xxxAndYyy` 这类递进式包装。
- **不留残骸**：被替换的旧实现、注释掉的代码块、无引用的 `_legacy*`、"将来可能用"的预留实现——一律删。
  判据：**删掉它行为不变、且没有测试因此失效** ⇒ 它就该删。
- **注释只写为什么**：导出符号必须有 JSDoc（参数 / 返回值 / 抛出 / 副作用）；函数体内**禁止**复述型注释（`// 设置 name`），只允许写"为什么这么定 / 边界在哪"。
- **交付四问**：① 全仓只有这一处实现吗（贴 grep 证据）？② 我新增了第二个入口吗？③ 旧实现真删了吗（不是注释掉）？④ 导出符号都有 JSDoc 吗？有没有复述型注释？

## 三、行为准则（软技能）

- **宁可改造，不新增**：既有实现差一点就改它——多一个入口的长期代价远大于一次改动成本。
- **不设"兼容期"**：不保留新旧两套并跑；要替换就一次替换干净（这是 AI 最爱的"稳妥"姿势，也最毒）。
- **注释写决策不写动作**：值得写的是阈值为什么取这个数、为什么绕过某个机制。
- **风格类规则（大括号 / 语法糖 / try / 模块接口 / 命名）默认不启用**：它们是**项目私有决定**，由仓库根 `coding-style.md` 覆盖后才生效；本卡只保证卫生四项。
- **卡在"该不该删"时**：先看有没有测试引用它——有测试 = 删了会响亮失败（可安全删并同步删测试）；无测试且无引用 = 直接删。

## 四、踩坑记录（每条 ≤100 字）

- **"禁一切语法糖"会反噬**：边界无法收敛（可选链→解构→箭头→`async`），且手写判空链比 `?.` 更易漏层；正确做法是**可枚举黑名单**（嵌套可选链 >2 / 嵌套三元 / `!` 非空断言）并交给 linter 强制。
- **"注释完整"会养出注释垃圾**：强制"每处都写注释"⇒ AI 生产复述型注释，代码看着更脏；只强制"导出符号有 JSDoc"。
- **`try` 必须报错的正确形态**：内部一律 `throw` 不 `catch`，仅边界层统一兜；写成"每个 catch 都 log"等于换个姿势吞异常。
- **检测器是建议不是既成事实**：`knip` / `jscpd` 的具体读数须在目标项目实跑；未跑过不得写"已验证"（同 `verify-integrity`）。
