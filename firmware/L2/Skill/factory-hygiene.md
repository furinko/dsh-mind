# factory-hygiene — 出厂卫生自检（双区边界）

> 心法一句话：**按"这条会不会被推送出去"划区——出厂区（`mind/`、`scripts/`、`packages/`、`docs/`）
> 任何文件都可能被公开推送，一次都不许例外。**
> 权威定义**不在这张卡**：`mind/L0/AGENTS.md §五 边界（🔴）` 与 `mind/L1/Invariants.md #13 出厂卫生` 是真源
> ——本卡只写"**怎么自检**"，条文一律指过去（避免两份真相）。
> 来源：L3 结晶「双区卫生出厂区只放可公开内容」（私有区，不推送）·（E 族 10 条 ≥3 复发归并）。

## 一、使用流程（Step 1→N）

1. **先定位"要被推出去的面"**：以 **git 为准**——`git ls-files --cached --others --exclude-standard`
   （＝真会被提交/推送的文件）。**不是**"我改了哪些文件"，也不是"整个工作区"。
2. **跑门禁两条**：`node scripts/mind-validate.mjs --strict` ⇒ **必须 critical = 0**。判据不只是"绿"：
   ⑨（禁词表）与 ⑩（凭据形态）在**输入缺失 / 零有效词条 / 0 个文件被扫**时会**响亮报 critical**
   （补"删一个文件即整体解除"的洞）。**注意覆盖读数门禁在绿灯时不打印**（它只在出问题时说话）⇒
   **自己按第 1 步量一次**并写进汇报：推送面文件数（`git ls-files --cached --others --exclude-standard | wc -l`）
   + 禁词表有效词条数。**"我跑了门禁"与"门禁真量了对象"是两回事**。
3. **补门禁管不了的那一维：历史**。门禁只看**当前**工作区/索引 ⇒ 历史里的泄漏它永远看不见：
   `git grep -nI "<词>" HEAD` 与 `git log origin/main..HEAD --name-only`。**"工作区干净"≠"提交历史干净"**。
4. **清单复核**：拟推送清单里**不许**出现私有区与运行态文件——`mind-private/`（它在 `.gitignore`）、
   `settings.yaml`、`approvals.json`、`guard-decisions.jsonl`、`cron-runs.jsonl`、各类账本/快照。
5. **写之前先自问一句**：**这段能贴在公开 GitHub 上吗？** 答"不能"就换私有区；答"能"也再问一次
   （**注释里、版本说明里、举例里**同样算"出厂区的内容"）。
6. **补词即重跑**：给禁词表补一条词，当场重跑门禁——**补词是"把历史残留捞出来"的动作，不是"让门禁变绿"**；
   真被它抓到几处旧残留，才是它该有的样子。
7. **汇报要带读数**：扫了哪些面、**量了几个文件 / 几条词**、命中几处、历史扫的结论——让"我扫过了"变成可核对的数
   （门禁绿灯时**不打印**这些数，得自己量，见第 2 步）。

## 二、核心规则（硬约束）

- **唯一真源**：禁词表只有一份 `mind-private/tasks/private-denylist.txt`；**任何别的扫描面都引用它，禁止另编名单**（两处口径必然漂）。
- **禁词表与私有区同生共死**：它本身含私有名 ⇒ 永远不能进公开仓库；也正因此，"表缺失 / 零有效词条 / 一个文件都没扫到"一律当 **critical**。
- **两道扫描分工，两条都要绿**：⑨ **名单扫**（人维护，可增删）＋ ⑩ **形态扫**（凭据 / PII，机械可识别、**不依赖词表、删不掉**）。
- **以 git 为准**：扫的是 `--cached --others --exclude-standard` 这个推送面，不是整棵工作树。
- **豁免必须显式可审**：形态扫的豁免是在同一行写 `cred-ok`（可 grep、可审），**不是关掉门禁**；阈值刻意调松是为了不造恒亮灯，不是让人放宽心。
- **不许为绿灯放松门禁**：修复只有两条路——**改内容** 或 **显式从禁词表移除该词**；不许跳过、注释掉、临时绕过。
- **规则文本与门禁同口径**：若某处写着"机器校验"，那条校验必须真在跑（否则写成"靠纪律"）。

## 三、行为准则（软技能）

- 写注释 / 版本行 / 举例 / 索引时**与写正文同标准**（历史判例全部栽在这三处）。
- 蒸馏与整理时默认：**机制进出厂，实例进私有**；两区同名时**私有优先**（加载口径）。
- **别把"门禁变绿"当目的**：门禁的价值在"能红"；补词/补形态后当场变红是真的在工作。
- 汇报里**主动标注"哪些面没扫"**（历史、未跟踪文件、二进制、上游导入物）——把边界说清楚，比通判强。
- 一次只动一个面（先扫后改，改完复扫）——免得"改内容"把读数搅在一起。

## 四、踩坑记录（每条 ≤100 字）

- **私有项目名写进 `mind/L1/Tree.md` 随 push 上公开 GitHub**：公开历史永久留痕，**回滚 commit 也删不掉**（此后才立"出厂不登记运行时条目"）。
- **清理那处私有名时，反手把它写回 `AGENTS.md` 版本行**：同一个名字，前后两次都从"整理动作"里漏出去。
- **私有名第 N 次回归：写在 `scripts/mind-prime.mjs` 注释里**：注释 / 版本行 / 举例是三个高发出口。
- **门禁输入缺失时假装全绿**（审计原话「删一个文件即整体解除」）：现已改成无输入 / 零词条 **响亮报 critical**。
- **"跑了门禁"≠"门禁执行了"**：判据要看它**量了几个对象**；只报"通过"的自述不构成证据。
- **为让门禁变绿而放松门禁**：该改内容却去删词 / 加豁免，等于把唯一的守卫拆掉换一次绿灯。
