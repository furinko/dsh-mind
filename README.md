# dsh-mind · 心智

产品方向：由有长期人格与成长性的 Lead 理解需求、组织专业智能体协作，各专业分别积累知识与方法，让工作留下可验证、可复用、可纠错的成果。

mind 为 DSH 提供目标记录、任务与验收、按需协作、记忆与能力、权限与审计，以及工作台。普通问答和已授权的只读调查直接进行；需要正式交付或委派时，再使用任务、复核和采纳。岗位数量、审计条数和知识存量不等于工作效果。

上述定位于2026-10-22由用户确认，职责与实现顺序见[Lead与专业智能体](docs/design/Lead与专业智能体-2026-10-22.md)。专业岗位知识已有[默认自动召回](docs/design/专业默认召回与上下文-2026-10-22.md)：Lead取得本岗位最近有效知识，专业成员按当前绑定任务检索本岗知识，最多4条摘要。已声明的人格、用户偏好与教训也已有[持久装配与更正](docs/design/Lead连续性与更正-2026-10-22.md)；主动提炼、语义相关召回和成长效果仍需后续验证。

Lead还可保存[可修正的需求解释](docs/design/需求理解与工作上下文-2026-10-22.md)，自动接续未收尾目标和交付进展；专业成员只自动取得自己活动任务的必要简报。分工建议不代替真实任务或授权，模型理解与专业选择的质量仍待真实案例验证。

[协作反馈与后续案例](docs/design/协作反馈与后续案例-2026-10-22.md)可随教训记录原做法、用户反馈、调整做法与后续结果声明，并带入新会话。程序核对目标历史引用，保留改善、无改善、变差与未知；实际采用和成长效果仍需真实证据。

工作概览优先[本会话实际推进的目标](docs/design/Lead会话目标与相关教训-2026-10-22.md)。教训优先按[本轮已接纳的用户来源文本](docs/design/已接纳表达与教训选材-2026-10-22.md)词面检索，无可用表达时按会话目标，再退回近期浏览；词面零命中不夹带近期教训。首步新消息尚未接纳，仍按目标取材，尚不代表自动识别聊天意图。

开发主线同步到本机DSH的具体提交与回执按[当前状态](docs/STATUS.md)核对。源码同步、客户端重载与完整实机验收分别记录；能力范围和后续工作见[路线图](docs/ROADMAP.md)。

审批集中在心智「待你决定」，点击请求进入独立审阅页，聊天输入区没有审批卡。设置 → 心智分组管理运行与调度策略；介入度显示为0% / 50% / 100%，对应放权 / 预审 / 审批，原有行为保持一致。保存入口兼容UTF-8 BOM，最新修复仍需客户端完整重启后验收。

## 从工作开始

| 要做什么 | 如何使用 |
|---|---|
| 问答、澄清、只读调查 | 直接推进，遵守已有权限，不为对话额外建岗、起成员 |
| 调整运行与调度策略 | 设置 → 心智：失联保护、审批与复核共同保存，Lead 调度授权单独保存；刷新保留草稿，来源、路径与指纹按需展开 |
| 查看人设保护范围 | 工作台健康区或 `/mind status`：Linux要求完整隔离；Windows保留原生部分隔离供普通命令使用，文件工具仍禁止改写核心人设。Windows不保证任意命令都无法改卡 |
| 跨会话延续明确工作 | [项目工作摘要](docs/design/项目工作接续与自动提炼-2026-10-23.md)从轮缓冲异步提炼，新Lead按项目自动取得；`project_brief_query`可查来源，正式目标与限制仍用`goal_query`核对 |
| 记住称呼和相处习惯 | [协作偏好](docs/design/自然协作偏好与称呼记忆-2026-10-23.md)从明确用户原话自动整理进正式记忆，新会话自然沿用，支持后续更正及停用 |
| 完成一个正式交付 | 定验收判据，选择 Lead 本人或成员执行；提交产物，经复核后由 Lead 采纳 |
| 委派可拆分工作 | 使用 `member_spawn`，机制处理登记、钉版、绑定和任务书；文件范围须在部署上限内明确授予 |
| 获取独立意见 | 按需使用 `debate_*`；会审是咨询，不替代交付复核 |
| 查已有经验或知识 | `memory_query` 按需检索；区分相关召回、历史浏览和正文详情 |
| 中断或压缩后接续当前对话 | [轮级缓冲](docs/design/轮级缓冲与续聊恢复-2026-10-22.md)默认记录已接纳文本并有界回放；`turn_buffer_query`查本会话原文，人侧`/mind turn_buffer_forget`清空缓冲 |
| 了解工作为何受阻 | 看板“阻塞反馈”或 `monitor_query` 查看；`monitor_followup` 关联重试/放弃，`monitor_feedback` 提出原因；反馈不改变权限 |
| 查看目标的受管额度 | `budget_query id=<目标>` 查配置、累计与未决占用；人侧 `/mind budget_decide` 配置累计上限，换实例和后继不清零，正常执行无需逐次确认 |
| 查看模型已报告用量 | `usage_query` 查本项目观察，或 `id=<目标>` 查看开始时已归因的尝试；最新 usage 快照替换旧值，缺失与未归因另列，费用仍未知 |
| 中断后核对成员创建 | `operation_query` 按任务或操作id查创建意图、候选实例和阶段回执；已有意图不再签发创建，候选id不冒充已创建 |
| 复盘知识采用 | `task_submit` 可选附 `采用知识`；治理角色用 `knowledge_reuse_query` 核对声明、当前来源和历史采纳关联。缺失保持未知，不自动排行或判错 |
| 核对知识适用条件 | 写知识可选附 `知识说明`；明确的复验期限到点后退出默认建议，有权者可用 `含待复验=true` 查原文。到期不自动判错，旧知识不补造期限 |
| 核对负反馈后的处置 | 有权者在既有 `memory_lifecycle` 失效、降权或替代动作中可选附 `反馈引用={任务,提交序}`；治理查询显示明确关联的处置，未见关联不等于无人处理，已见不等于问题解决 |

治理知识查询只在单次调用内复用读取快照。读取期间来源变化会使整组来源与处置观察保持未知；任务真源或当前任务读权变化时重新查询，不拼接早晚批的声明与分母。该机制不创建后台刷新或缓存授权。

正式任务的判据派发后冻结，复核票只支持它实际核验过的内容。不能借另一个任务、同岗位身份、旧票或重试声明扩大权限或伪造完成。

## 安装形状

一个包、一张插件卡、三个组件，无需手写组件依赖：

| 组件 | 入口 | 职责 |
|---|---|---|
| 内核 | `dsh-mind/kernel` | `mind` 工具、`/mind` 命令、真实工具 guard、审计与上下文 |
| 安全类 | `dsh-mind/guard` | 四项安全探针、升级比较与回滚目标定位 |
| 看板 | 根包载体与 `dsh-mind/client` | 当前工作、待决定事项、审计与相关读面 |

组件共用同一个 `Org`。关闭内核会失去 Mind 的工具边界；安全类只定位回滚目标、记账并告警，不自动替用户改运行文件。看板从服务端投影读取事实，受控按钮调用正式命令入口。

在目标 profile 中按宿主支持的安装方式安装本地包或已发布包，例如：

```powershell
dsh plugin --profile <名> add <包或本地包路径>
node scripts/verify-profile-install.mjs <profile绝对路径>
```

安装后核对 profile 的依赖与 `dsh.profile.bundles`、三组件及各导出。安装自检检查包与 profile 形状；真实工具链是否生效仍须在目标宿主核验。旧安装故障与历史证据见[重整前 README](docs/归档/设计史/README-2026-10-20-重整前.md)。

## 部署者需要配置的边界

- `memberFileAccess` 给出成员可授文件域的上限，缺省为空。Lead 通过任务的 `工具文件范围` 授予其中子集；任务绑定本身不授予任意文件或 shell 权限。
- 新项目默认使用规范完整路径派生的键。旧 basename 项目需通过可信 `projectBindings` 明确认领；同名目录不自动共用账本。
- 复核免审为用户控制的全局设置，默认关闭；模型不能代开。审批、撤权和失联规则继续生效。
- 受控实验默认关闭，仅接受部署者审读并冻结的可信候选、封闭配方与单独许可；它的实际隔离能力不等于 OS 沙箱。

详见[成员工具边界](docs/design/成员通用文件工具边界-2026-10-20.md)、[项目身份](docs/design/任务账本与项目身份边界-2026-10-20.md)和[接口合同](INTERFACES.md)。

## 系统如何分工

LLM 理解意图、选择方案和判断内容；机器检查身份、授权、任务归属、版本和证据一致性。流程策略与界面选择可以按真实收益调整；反馈不能自行授予权限。

| 职责 | 实现位置 |
|---|---|
| 领域服务与事实 | `src/`：任务、身份、策略、产物、记忆、会审、审计 |
| 工具与命令适配 | `lib/`、`components/kernel/lib/` |
| 安全运维 | `components/guard/lib/` |
| 界面 | `components/board/lib/` |
| 出厂规则、岗位与能力 | `mind/`；用户叠加及运行事实保存在私有区 |

治理对象的标签授权与文件工具的真实路径边界共同生效。任务账本、身份和审计各有职责，工作台与指标从事实重建，不另建授权来源。完整职责、限制与真源见[当前架构](ARCHITECTURE.md)。
